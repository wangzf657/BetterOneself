## 1. 建模原则

1. **知识点是枢纽**:Task/Session/Quiz/Card/MasteryEvent 全部外键指向 knowledge_point,与总纲概念模型一致
2. **证据链内建**:掌握状态、薄弱点判定、重排记录都可回溯到具体证据(哪次测验/哪次复习),不留"状态凭空变更"
3. **从简**:无软删(删除用确认交互,需求已定义);时间存 UTC;JSON 字段用于低频读取的附属数据,高频过滤字段一律拆列

## 2. ER 概览

```
Study ──< StudySource >── Source ──< SourceChunk ──(vec_chunks 向量)
  │
  ├──< Plan ──< PlanEvent(重排/调整记录)
  │       └──< Task(锚定知识点)
  │
  ├──< KnowledgePoint(树:自引用 parent;依赖:kp_dependencies)
  │        │    ↑ ↑ ↑ ↑ —— Task / Session / Quiz / Card / MasteryEvent
  │        └──< KnowledgeRef >── SourceChunk(来源引用)
  │
  ├──< Session ──< Message(对话+引用)
  │       └──< Quiz
  ├──< Card ──< ReviewLog(FSRS 排程证据)
  └──< Summary(每日摘要/周复盘 + 指标快照)

全局:Settings(单行,BYO-Key 加密)/ UsageDays(成本统计)
```

## 3. 表结构

### 3.1 项目与资料(M1)

**studies** — 学习项目(M1-01)

| decompose_error | str | 拆解失败原因,前端展示并可重试 |
| created_at, updated_at | dt | |

**sources** — 知识库资料,独立于 Study(M1-02~05)
| 字段 | 类型 | 说明 |
|---|---|---|
| id / title | PK / str | |
| type | enum | pdf / md / url / github / text |
| origin | str | URL、repo 名或本地文件名 |

| parse_status | enum | pending / processing / ready / failed |
| parse_error | str | 失败原因,前端展示 |
| created_at | dt | |

**study_sources** — 多对多关联(总纲:一次导入多处复用):study_id + source_id 复合 PK

**source_chunks** — 切片,检索单元与引用目标(M2-01, M3-02)
| 字段 | 类型 | 说明 |
|---|---|---|
| id / source_id | PK / FK | |
| seq | int | 文档内顺序 |
| content | text | |

| 字段 | 类型 | 说明 |
|---|---|---|
| id / study_id / kp_id | PK / FK×2 | |
| front / back_md | text | 正面问题 / 背面答案+源引用 |

**review_logs** — 每次评分一条,指标与证据的数据源(M4-02, M6-01):id, card_id FK, rating(1 忘了/2 困难/3 良好/4 轻松), scheduled_days, elapsed_days, reviewed_at

### 3.6 档案与督促(M5, M6)

**mastery_events** — 掌握状态变更的证据链(M6-01"状态变更可追溯"):id, kp_id FK, from_status, to_status, evidence_type(quiz/review), evidence_id, created_at。当前状态在 knowledge_points.mastery_status 快照,历史在此。**薄弱点判定规则**(M4-05):同一 kp 连续 2 次 quiz/review 错误 → to_status=weak,并触发 review_weak 任务(M5-04)

**summaries** — 每日摘要与周复盘合一(M5-03/05):id, study_id FK, summary_type(daily/weekly), period_date, content_md, **metrics_json(指标快照,见第 4 节)**, created_at

### 3.7 全局(M7)

**settings**(单行):llm_base_url, llm_api_key_enc(Fernet 加密,密钥在本机文件;开发期亦可直接读根 .env), llm_model(默认 glm-5.3-flash), embed_base_url, embed_api_key_enc, embed_model(默认 BAAI/bge-m3), fsrs_params_json(默认参数,UI 可查看 M4-03), daily_review_limit(默认 20), inactivity_threshold_days(默认 5, M5-06), updated_at

**usage_days** — 成本按天×场景聚合(M7-04):date + scene(decompose/chat/quiz/embed)复合 PK, prompt_tokens, completion_tokens, requests, cost_est

## 4. 验证指标口径(V1.0 成功标准的数据支撑)

指标不建专表,全部由业务数据推导;每日摘要生成时把当日值快照进 summaries.metrics_json(防 due 等字段随后续复习漂移)。

| 指标(总纲第 12 节) | 数据源 | 口径 |
|---|---|---|
| 周留存 | sessions.started_at ∪ review_logs.reviewed_at ∪ tasks.completed_at 的 distinct 日期 | 每周行为日 ≥3 天视为"活跃周";周留存 = 活跃周人数/曾活跃人数 |
| 计划完成率 | tasks | 按日:done(scheduled_date=D) / 非 skipped(scheduled_date=D);取各日中位数 |
| 复习完成率 | summaries.metrics_json | 当日 due_count(生成摘要时点的到期数)vs 当日 review_logs 条数 |
| 掌握可信度 | quizzes × review_logs | quizzes.is_correct=true 的 kp,其后 7 天内该 kp 卡片出现 rating=1 的比例 |

## 5. 约定

- 迁移:SQLAlchemy + Alembic 建表起手;SQLite 迁移能力弱,改表走技术总纲 5.4 评审
- 全文检索补充:content_md/title 不建全文索引,V1.0 检索走向量 + 结构过滤,够用
- 阅读页定位:location 字段是 JSON(页码/行号),由各 ingest 适配器在解析时写入
