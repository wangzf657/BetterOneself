# V1.0 需求清单

> 版本：V1.0 草案 | 日期：2026-11-18
> 上游：[00-产品总纲](../00-产品总纲.md)（含产品逻辑，第 6-10 节）
> 范围决策：自用+小圈子、四环全做每环做薄、站内督促、首批服务程序员/技术学习者。

---

## 1. 版本目标

一句话：**让 1 个学习项目从"导入资料"到"连续 4 周被计划、被督促、被复习"完整跑通，且过程中产生的掌握状态被持续记录。**

验证目标见总纲第 7 节（周留存 / 任务完成率 / 复习完成率 / 档案可信度）。

## 2. 角色与场景

- **学习者**（唯一角色）：V1.0 无多用户权限体系，部署者即用户；小圈子共用一个部署时互不感知（不做隔离）
- 主场景：Web 桌面浏览器；碎片模式（3-10 分钟清卡片）与专注模式（30-60 分钟学习会话）并存

## 3. 需求清单

优先级定义：**P0** = 缺失则闭环断裂；**P1** = 闭环可用但体验残缺；**P2** = 本版加分项，砍掉不影响闭环。
验收标准用于开发自测与产品验收，均须可独立验证。

### M1 资料导入与知识库

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| M1-01 | 创建学习项目（Study）：输入名称与一句话目标 | P0 | 创建后进入项目页；项目可列表、可归档、可删除 |
| M1-02 | 导入本地文件：PDF、Markdown（支持一次多选批量） | P0 | 拖拽或选择上传；解析完成后可查看全文与目录结构；解析失败给明确错误提示 |
| M1-05 | 知识库管理：资料列表、重命名、删除、重新解析 | P1 | 删除资料后其派生内容（引用、知识点来源标注）有明确处理提示，不静默失效 |
| M1-06 | 导入进度与状态反馈（大文件解析可能较慢） | P1 | 显示解析进度或阶段状态；后台解析不阻塞页面其他操作 |
| M1-07 | 导入纯文本粘贴（临时笔记、邮件片段等） | P2 | 粘贴即建为资料，可参与后续拆解 |

### M2 知识点拆解与学习规划

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| M2-01 | 导入完成后自动拆解知识点：生成知识点树（含名称、简介、来源引用） | P0 | 每个知识点可点击跳转到源文位置；无来源支撑的知识点被标注"AI 推断" |
| M2-02 | 知识点依赖关系：标注前后依赖，以图或列表呈现 | P1 | 依赖关系可视化可读；计划生成时遵循依赖顺序（不出现"先学依赖方"） |
| M2-03 | 用户可编辑知识点树：删除、合并、改名、补充 | P0 | 编辑后计划与档案同步生效；删除已有关联卡片的知识点时给确认提示 |
| M2-04 | 目标访谈：规划前 Agent 问三件事——目标深度、完成期限、每日可用时长 | P0 | 三问以对话或表单完成；用户可跳过（用默认值并明示） |
| M2-05 | 生成学习计划：知识点×日期×预估时长的分日安排 | P0 | 计划遵循依赖顺序与每日时长上限；每天任务量超上限时有明确提示 |
| M2-06 | 计划确认与手动调整：用户可编辑后再生效 | P0 | 支持移动单日任务到其他日、增删知识点；调整后计划即时重算后续安排 |
| M2-07 | 已掌握跳过：规划时允许用户标记"我已掌握"的知识点 | P1 | 被标记知识点不进学习计划，但可选触发一次快速测验验证；测验不通过则回滚进计划 |

### M3 学习会话（讲解与测验）

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| M3-01 | 今日任务页：展示当日学习任务与到期复习入口 | P0 | 打开即见"今天该做什么"；任务可点击直接进入对应会话 |
| M3-02 | 知识点讲解会话：基于当日任务的对话式讲解，回答带源引用 | P0 | 每个回答附来源引用可点击回跳；讲解按小节分段（认知负荷控制） |
| M3-03 | 苏格拉底模式开关：默认引导式（先让用户作答、分层提示），可切直答模式 | P0 | 开关状态可见且可切换；引导式模式下用户直接要答案时，先给一层提示而非答案 |
| M3-04 | 内嵌测验：会话中按知识点出题（客观题+简答），即时反馈 | P0 | 答错给解释并回到对应源文；简答由 AI 评分并给评语 |
| M3-05 | 错题与卡壳点一键沉淀：测验错题自动、对话中用户标记的手动，生成复习卡片 | P0 | 自动生成的卡片可在队列中看到，正面为问题、背面含答案与源引用 |
| M3-06 | 自由提问：随时就当前资料提问（不限于当日知识点） | P1 | 回答带引用；不改变当日计划 |
| M3-07 | 费曼任务："你来讲，我来挑错"——用户用自己的话解释知识点，AI 追问与纠错 | P1 | 讲解被记录归档到该知识点证据；AI 至少提出 1 个追问或确认解释正确 |

### M4 复习系统

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| M4-01 | 复习队列：到期卡片出队，按到期紧迫排序 | P0 | 每日队列有数量上限（默认 20，可调）；无到期卡片时明示"今日无复习" |
| M4-02 | 四档评分：答完后用户自评（忘了/困难/良好/轻松），驱动下次到期时间 | P0 | 评分后卡片进入新排程；"忘了"的卡片当日队列内重现 |
| M4-03 | 间隔重复排程：采用成熟开源算法方案（业界首选 FSRS），不自研 | P0 | 相邻两次复习间隔随评分结果变化；排程参数可查看 |
| M4-04 | 卡片管理：查看全部卡片、手动新建、编辑、暂停、删除 | P1 | 卡片可按知识点/来源筛选；编辑不影响历史复习记录 |
| M4-05 | 错题薄弱点联动：连续答错的知识点标记为薄弱点 | P0 | 薄弱点在档案中标出，并触发 M5-04 的次日针对性任务 |
| M4-06 | 卡片导出 Anki 格式 | P2 | 导出文件可被 Anki 导入；导出不删本地卡片 |

### M5 督促与重排

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| M5-01 | 今日任务提醒：打开产品时首页即今日任务（站内，V1.0 无外部推送） | P0 | 首页信息层级第一；有逾期任务时显著提示 |
| M5-02 | 逾期自动重排：未完成任务按计划规则移入未来日程，不堆积 | P0 | 重排结果可见（"以下任务已重排"）；重排策略：优先保每日时长上限，必要时顺延完成日期并告知 |
| M5-03 | 每日摘要：当日学习/复习收束页（学了什么、复习多少、明日预告） | P1 | 有当日学习行为即可生成；可跳过 |
| M5-04 | 薄弱点针对性任务：次日任务自动插入薄弱知识点的复习/变式练习 | P0 | 插入的任务带"针对薄弱点"标识，点击可见薄弱证据（哪次答错） |
| M5-05 | 周复盘：每周一次完成率、掌握进展、遗忘预警与计划调整建议 | P1 | 建议需用户确认才调整计划；数据空缺时如实说"本周无数据" |
| M5-06 | 长期中断回炉：检测连续 N 天（默认 5）未使用，回归时触发回炉流程 | P2 | 回归时询问是否重排剩余计划，并优先安排高风险遗忘卡片 |

### M6 掌握档案与学习报告

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| M6-01 | 知识点掌握状态：未学/学习中/已通过/薄弱，状态由测验与复习证据驱动 | P0 | 状态变更可追溯到证据（某次测验/复习记录）；"已通过"须有至少一次测验通过证据 |
| M6-02 | 掌握档案视图：知识点树+状态的整全视图 | P1 | 可视化呈现学习项目的整体掌握情况；支持按状态筛选 |
| M6-03 | 自评与评估分离：用户自评"已掌握"单独记录，不改变系统评估状态 | P1 | 界面明确区分"自评"与"测验通过"两个维度（借鉴 DeepTutor 诚实设计） |
| M6-04 | 学习总结导出：项目结项时输出学习报告（Markdown） | P2 | 报告含知识点清单、掌握状态、学习时长、卡片留存情况 |

### M7 基础与设置

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| M7-01 | 模型配置：自带 API Key（BYO-Key），可配置对话/解析所用模型 | P0 | Key 加密存储本地，不出现在任何日志与 AI 请求内容中 |
| M7-02 | 单部署单用户模式：无注册登录，数据存本地 | P0 | 重启后数据完整；提供数据备份导出入口 |
| M7-03 | 全量数据导出：资料、计划、任务、卡片、档案可导出为开放格式 | P1 | 导出内容可再导入或被第三方工具读取（MD/JSON） |
| M7-04 | 使用成本可见：展示当前周期的模型调用量/预估费用 | P2 | 数字与实际账单量级一致；不追求精确到分 |

## 5. V1.0 明确不做（Out of Scope）

| 不做 | 理由 | 归属 |
|---|---|---|
| 账号体系 / 多用户隔离 | 自用+小圈子定位（总纲决策 #1） | V2.0 |
| IM 推送（企微/飞书/Telegram bot） | 先验证"推什么"再解决"推到哪"（决策 #3） | V1.1 |
| 邮件推送 | 打开率低，IM 优先 | V1.1 评估 |
| 零资料冷启动（输入主题自动找资料） | V1.0 聚焦"已有资料"主流程 | V1.1 |
| **导入网页（URL 抓取）/ GitHub 仓库导入** | 发起人 2026-11-20 决定移出本期：先只支持离线批量导入，联网抓取（含防爬噪声处理与 repo 文件树交互）成本另评估 | V1.1 |
| EPUB / 音视频转写导入 | 格式扩展 | V1.2 |
| 错题回灌讲解闭环的完整自动化 | V1.0 先做"薄弱点→次日任务"半自动 | V1.2 |
| 垂类学习路径 / 路径市场 | 依赖掌握档案数据积累 | V2.0 |
| 移动原生 App | Web 优先；碎片场景由复习队列轻量承担 | 长期 |
| 音频播客 / 视频 / 游戏化 | 转换器军备竞赛，非主线〔调研〕 | 不做 |
| AI 同学 / 多人课堂 | 实时性成本高〔调研：OpenMAIC 教训〕 | 长期评估 |
| K-12 / 家长监护 | 合规复杂度 | 长期 |
| 插件/技能市场、开放 API | 生态期再谈 | V2.0+ |

## 6. 验收路线（开发顺序建议）

按"闭环最早可跑通"排序，每个里程碑都是可用的最小产品：

1. **能学**：M1-01/02 + M2-01 + M3-01/02/03 —— 导入 PDF → 拆解 → 讲解对话（断链点：无计划无复习）
2. **能考**：M3-04/05 + M4-01/02/03 + M6-01 —— 测验 + 卡片沉淀 + 复习队列（闭环的引擎上线）
3. **能规划**：M2-02/03/04/05/06 + M5-01/02 —— 依赖推断与知识点编辑（计划遵循依赖顺序、编辑后计划/档案同步生效，均须计划存在才可验收）+ 计划生成/确认 + 今日任务 + 逾期重排（伴学主形态成型）
4. **能督促**：M5-04 + M4-05 —— 薄弱点联动次日任务（差异化闭环合拢）
5. **补全**：M1-05/07（知识库管理、文本粘贴）+ 其余 P1/P2 按需 —— 网页/GitHub 导入经发起人确认移出本期（见 Out of Scope）

> 技术选型、架构与实现方案不在本文档范围，待产品方案评审通过后另行立项。
