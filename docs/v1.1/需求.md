# V1.1 需求清单（草案，待评审）

> 版本：V1.1 草案 | 日期：2026-11-19
> 上游：[00-产品总纲](../00-产品总纲.md) v0.2（方向修订：学透一本书，ADR #9）
> 前提：V1.0 已交付（40 条，闭环资产全保留）；本版是**聚焦与降本**，不是推翻。

---

## 1. 版本目标

一句话：**把"导入一本书 → 全书学透 100%"做通：导入分钟级、知识树即时可见、LLM 成本随学习量而非藏书量，全书学透百分比成为产品门面。**

背景：V1.0 真机验证暴露大文档拆解成本失控（855 切片 ≈ 70 万 token / 2 小时，线性于文档大小）。根因是"LLM 全量拆解"把质量增强当成了入场券；而书自带目录结构与章节顺序，骨架本可免费获得。

## 2. 角色与场景

- 学习者（唯一角色）：以**一本书**为教材的人——技术书、教材、备考书；一次主学一本，多本并行=多项目
- 主场景不变：Web 桌面；碎片模式（清卡片）+ 专注模式（学一章的一节）

## 3. 需求清单

优先级定义同 V1.0：P0 缺失则方向不成立；P1 体验残缺；P2 加分项。

### B1 一项目一本书（聚焦）

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| B1-01 | 创建项目即绑定一本书：建项目流程合并"上传主资料"一步 | P0 | 新建项目必须有一本主资料才能进入学习流程；项目页以书为单位展示 |
| B1-02 | 旧数据处置：V1.0 已有多来源项目不破坏、可继续学习，不做迁移工具、不额外兼容 | P0 | 旧项目全功能可用；不做专项适配 |
| B1-03 | 补充资料下限支持：粘贴文本/MD 仍可作为"书的补充片段"挂到项目（不独立成树） | P2 | 补充片段可被检索引用，不产生独立知识点树 |
| B1-04 | 电子书格式扩展：epub、txt 与 pdf/md 同级支持（发起人 2026-11-19 决定,原定 V1.3 提前） | P1 | epub 按章节结构出目录树；txt 按标题行/分段出树；解析失败给明确错误 |

### B2 结构优先拆解（降本核心）

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| B2-01 | 导入即出知识树：按书标题结构（heading 层级）即时建树，零 LLM、秒级完成 | P0 | 上传完成即见全书树；每节点带来源引用可跳转；无标题结构的文档降级为"批次拆解"并明示 |
| B2-02 | 章级 LLM 增强：对选中章节做粒度合并、逐点摘要、依赖推断；**一律手动触发**（"增强此章"按钮,发起人 2026-11-19 拍板） | P0 | 用户点按钮才开始增强；增强前后树可见差异；失败可重试且原因可见；不点不花任何 LLM token |
| B2-03 | 按章分批：增强的批次单位是章（章内再切片），批大小提升 | P1 | 同章内容不跨批断裂；批次进度可见（沿用 V1.0 进度条） |
| B2-04 | 依赖降级：章节顺序为默认学习顺序，LLM 依赖推断仅作为增强项输出 | P2 | 未增强的章按目录顺序排计划，不阻塞计划生成 |

### B3 章级学习强度

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| B3-01 | 章级强度三档：略读（只读不出题）/ 读透（章末费曼复述,**AI 判定过关**）/ 学透（知识点测验通过+复习留存） | P0 | 强度在知识树/目录上可见可改；强度决定该章的任务形态与"完成"判定 |
| B3-02 | 访谈按目标深度批量设强度：目标访谈新增"哪些章略读/哪些学透"（可全默认学透） | P1 | 访谈产出章级强度表，确认计划前可逐章调整 |
| B3-03 | 略读/读透章不计入学透百分比，但计入阅读进度 | P1 | 全书进度区分"读过"与"学透"两个口径，口径定义在界面明示 |

### B4 全书进度（产品门面）

| ID | 需求 | 验收标准 | 优先级 |
|---|---|---|---|
| B4-01 | 全书学透视图：章→知识点两级进度条，首页即见"本书学透 N%" | 按章聚合掌握档案；未增强章节按目录+测验证据同样可追踪 | P0 |
| B4-02 | 章完成判定：学透章=该章知识点全部通过且无高风险卡；读透章=费曼过关 | 判定口径在界面上可追溯（点开见证据链，复用 V1.0 档案） | P0 |
| B4-03 | 结业报告：全书学透 100% 时生成"这本书你学到了什么"（复用 V1.0 报告导出） | 报告含各章掌握轨迹与薄弱点清零记录 | P2 |

### B7 学习开场（V1.0 真机反馈：会话页只有空对话框,用户无从下手）

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| B7-01 | 会话开场即讲解：进入讲解会话,AI 先开口——基于知识点原文自动输出第一段分段讲解（带引用）,用户接着问;不再空对话框 | P0 | 首条 assistant 消息由系统生成（不伪造用户消息）;讲解遵循"单次聚焦一小节"原则 |
| B7-02 | 知识点原文面板：会话页展示该知识点的摘要与原文切片;**简易版已先行实现**（纯前端,重用源文接口,V1.0 分支）,本版补轻量内容端点替代整包拉取 | P0 | 打开会话即见原文与摘要,可折叠;大资料不再整包拉取切片 |

### B8 学习方法前台化（V1.0 反馈:"苏格拉底引导"是术语,用户看不懂）

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| B8-01 | 方法说明页:六种学习方法的大白话解释+科学依据(内容底稿见页面清单 §2.1),问号入口全站可达 | P1 | 无术语裸奔;每个方法对应到产品里的具体形态 |

## 5. 里程碑（建议）

1. **M-B1 结构优先**：B2-01/02/03 + B1-01/02 + B1-04（epub/txt）→ 导入秒级出树、增强手动可控
2. **M-B2 门面**：B9-01/02/03（学习首页+书页+独立入口）+ B4-01/02 + B7-01 + B8-02（方案选择器）→ "学透一本书"的产品形态成立
3. **M-B3 收尾**：B3-02 + B1-03 + B4-03 + B5-01 + B2-04 + B7-02 收尾/B7-03 + B8-01/03 + B6-01/02/03（书包分享）

每个里程碑以全量测试绿 + 一条 E2E 收口（沿用 V1.0 门禁标准）。

## 6. 评审决议（2026-11-19 发起人拍板,需求据此定稿）

1. **旧项目兼容**：不做迁移工具、不额外费心兼容——旧项目能打开能学即可（B1-02 据此简化）
2. **增强触发**：**一律手动**——只有用户点"增强此章"才跑 LLM；目标访谈只设各章强度，不自动触发增强（B2-02 据此修订）
3. **读透判定**：AI 判费曼过关（复用 V1.0 费曼机制,至少一追问,AI 判定是否讲清）（B3-01 据此确认）
4. **电子书格式**：epub/pdf/txt 等常见格式**本版即支持**（原定 V1.3 的格式扩展提前,新增 B1-04）
