# V0.2 原型设计

> 日期：2026-11-20｜形式：桌面 Web 高保真文字线框与交互脚本
> 配套：[页面清单](页面清单.md)；页面与状态定义以页面清单为准，本文负责把关键屏“画出来”。
> 样例书名为真实测试样书，仅用于说明信息密度，不代表目录规划结果已验证。

## 1. 视觉方向

### 1.1 设计关键词

**书桌感、清楚、克制、证据可见。**

- 页面像一张有组织的学习桌，而不是 AI 聊天工具或数据大屏；
- 每屏只有一个视觉主动作；
- 进度数字重要，但来源和下一步同等重要；
- AI 的存在通过“正在整理、为什么这样调整、依据在哪里”体现，而不是到处放发光图标；
- 红色只用于薄弱与破坏性操作，不用于普通逾期数量。

### 1.2 桌面基准

- 设计基准：1440 × 900；最小桌面宽度 1024；
- 顶栏高 56，页面左右留白 32；
- 普通页面内容最大宽度 1080；目录和会话工作区最大宽度 1440；
- 卡片圆角 10，边框 1；页面间距以 8 为基数；
- 正文 14/22，页面标题 24/32，大进度数字 40/48；
- 树节点行高 36，任务行高 56，按钮标准高 36；
- 弹窗宽度：普通表单 520，合并 / 拆分 720，调整记录抽屉 480。

### 1.3 状态色

| 状态 | 颜色倾向 | 使用方式 |
|---|---|---|
| 未学 | 中性灰 | 文字与小圆点，不整块铺灰 |
| 学习中 | 蓝 | 进度条与小徽标 |
| 已通过 | 绿 | 勾与小面积文字 |
| 薄弱 / 高风险 | 红橙 | 标签与证据入口 |
| 待确认 | 琥珀 | 节点左侧小点与说明 |
| AI 调整 | 紫 | 仅用于调整标记与记录，不用于主按钮 |
| 已排除 | 灰 + 删除线 | 保留在树中，可恢复 |

颜色必须配合文字或图标，不能只靠颜色传达掌握状态。

### 首页交互脚本

1. 点“继续学习”→ 进入 4.2 会话，并恢复上次消息与原文位置；
2. 点“开始复习”→ 复习页当前书队列，评完返回时首页到期数同步减少；
3. 点“为什么推荐”→ 行内展开两条答错证据，不跳走；
4. 点“口径与变化”→ 右侧抽屉显示当前统计范围与最近分母变化；
5. 点“查看变更”→ 展开真实知识点名和日期，不出现内部 ID。

## 9. 核心点击流

### 9.1 首次闭环

```text
我的书
  → 添加一本书
  → 导入并查看目录
  → 检查低置信节点 / AI 调整
  → 设置章强度
  → 生成学习计划
  → 确认草案
  → 自动回到学习首页
  → 开始第一条任务
  → 阅读第一段讲解
  → 考我一组
  → 答错一题
  → 看到“已形成复习卡”
  → 完成今日学习
```

### 9.2 次日复习闭环

```text
学习首页
  → 今日复习
  → 显示答案
  → 选择“忘了”
  → 当天稍后再次出现
  → 选择“良好”
  → 返回首页
  → 到期数减少
  → 档案时间线新增复习证据
```

### 9.3 AI 失败降级

```text
添加一本书
  → 基础目录已显示
  → AI 规划失败提示
  → 原目录不消失
  → 用户手动排除“本章小结”
  → 设置强度并排计划
  → 稍后重试规划
  → 新结果与手动编辑冲突时保留用户最后操作
```

## 10. 响应式与可访问性

- 1024 以下目录改为 38% / 62%，隐藏非关键学习数据；
- 768 以下顶部导航折叠为菜单，书页双栏改为页签，主操作固定在底部安全区；
- 所有树节点、任务行、评分按钮支持键盘焦点；
- 四档评分快捷键为 1–4，显示答案为空格，输入框聚焦时不劫持字母与数字输入；
- 弹窗打开后焦点进入标题后的第一个输入项，关闭后回到触发按钮；
- 长书名、长知识点名最多两行，完整名称可通过悬停或聚焦查看；
- 加载、失败、空态和禁用都不仅靠颜色区分。

## 11. 原型评审重点

实现前只需围绕以下问题逐屏打磨，不再把技术方案混入产品评审：

1. 首页是否始终只有一个最显然的下一步？
2. 目录页是否能同时看清“原书结构、AI 改过什么、我能怎么改”？
3. 用户是否能区分任务完成、知识点通过和章学透？
4. 学透数字变化时，是否一眼知道是证据变化还是统计范围变化？
5. 答错到成卡、次日复习、证据回流的每一步是否都能被看见？
6. AI 不可用时，是否仍有一条完整、诚实的基础路径？
