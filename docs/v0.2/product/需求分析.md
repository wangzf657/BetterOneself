# V0.2 产品需求分析

> 日期：2026-11-20｜状态：现行产品事实源，待逐节打磨
> 配套：[需求列表](需求列表.md)｜[页面清单](页面清单.md)｜[原型设计](原型设计.md)
> 边界：本文只讨论用户、问题、学习逻辑与产品取舍，不规定表、字段、接口或解析库。

## 1. 一句话定位

**一个陪你学透一本书的 Agent：导入一本书后，先看到可信、可修改的知识骨架，再按目标排计划；每天陪你学、考你练、盯住薄弱点和复习，直到掌握证据支持“学会”，而不是只显示“读过”。**

V0.2 仍是单机、单用户、自导入的验证版本。它要证明的不是“AI 能生成多少内容”，而是“一个自学者能否更持续、更可信地学完一本书”。

## 2. 为什么重做

V0.1 的功能链路曾经全绿，但真实学习暴露两个根本问题：

1. **入口不成立**：全书 LLM 拆解慢且贵，知识点数量随切片膨胀；用户还没开始学习，就先付出大量时间和调用成本。
2. **结果不可信、界面不顺畅**：学习进度与真实掌握之间不够清楚，导出、筛选、回跳等基础操作存在测试未发现的断点。

因此 V0.2 不是在旧清单上继续加功能，而是重新回答三个产品问题：

- **先学什么**：导入后，用户能否迅速看到一张可信的全书地图？
- **现在做什么**：每天打开产品，是否只有一个清楚的下一步，而不是一排功能入口？
- **凭什么说学会**：每个进度是否都能回到测验、复述或复习证据？

失败证据与保留经验见 [V0.1 失败经验](../../v0.1/失败经验.md)。

## 3. 目标用户与场景

### 3.1 目标用户

有明确教材、有学习目标，但缺少过程管理的成人自学者。首批仍以技术学习者为主，因为技术书通常目录清楚、概念与操作并重，便于验证“讲解—考练—复习”的闭环。

典型状态：

- 书已经下载，却停留在“读过前几章”；
- 看讲解时觉得懂，合上书无法复述或应用；
- 不知道每天该学多少，中断后面对堆积任务容易放弃；
- 笔记和卡片很多，但不知道哪些内容仍然薄弱。

### 3.2 两类日常使用

| 场景 | 用户可用时间 | 产品应提供的主路径 |
|---|---:|---|
| 专注学习 | 20–60 分钟 | 继续今日知识点 → 看讲解与原文 → 提问 → 测验或复述 → 留下下一步 |
| 碎片复习 | 3–10 分钟 | 打开首页 → 清到期卡片 → 看到薄弱点变化 → 可立即结束 |

### 3.3 不服务的情况

- 没有教材、只想随意聊天的人；
- 只需要标注和阅读进度、不需要考练与复习的人；
- 需要班级、多人协作、账号体系或社区运营的人；
- 希望导入整个收藏夹、让 AI 一次性处理所有资料的人。

## 4. 核心问题与产品回答

| 用户问题 | V0.2 的回答 | 明确不采用 |
|---|---|---|
| 导入后“然后呢” | 第一屏先给全书目录与知识骨架，再给明确的整理、设强度、排计划动作 | 导入后只出现空聊天框 |
| 目录识别不完全可靠 | 显示识别依据与置信度，允许改名、拆分、合并、排除和移动 | 把机器结果包装成绝对正确 |
| AI 什么时候整理目录 | 导入后自动做一次目录规划；未配置或失败则跳过，保留原结构 | 为等 AI 而阻塞导入；从全文重新生成目录 |
| 知识点应该多细 | 以“一次能学完、能出题、能追踪掌握”为准，目录只是候选骨架 | 越细越好，或机械地一章一个点 |
| 学完为什么要复习 | 错题和卡壳形成卡片，在将忘时重现；连续错误变成薄弱点并影响后续任务 | 学完自动生成一大批没有学习缺口的卡片 |
| 今天该做什么 | 首页直接给今日任务、到期复习和继续上次 | 只有统计图表，没有下一步 |
| 中断后怎么办 | 逾期任务重排而不是堆积，长期中断提供回炉 | 用逾期数量惩罚用户 |
| 什么叫学透 | 知识点通过测验，相关记忆没有明显高风险；证据可查看，进度可回退 | 阅读时长、滚动位置或任务勾选等于掌握 |

## 5. 产品范围

### 5.1 本版必须做通

1. 一个学习项目只绑定一本书、一个主文件；
2. 支持 EPUB、TXT、PDF、Markdown；
3. 导入后形成可编辑、可溯源的目录与知识骨架；
4. 章级学习强度、目标访谈、计划确认与调整；
5. 带原文与引用的学习会话、内嵌测验、费曼复述；
6. 错题与卡壳成卡、间隔复习、薄弱点回流；
7. 今日任务、逾期重排、每日摘要、周复盘和长期中断回炉；
8. 全书学透进度、章级进度、掌握档案与学习报告；
9. 密钥安全、数据导出、用量可见，以及 V0.1 已知界面断点修复。

### 5.2 本版明确不做

- 补充资料、多文件混装、粘贴文本导入；
- 网页、GitHub、音视频导入；
- 书籍分享、导入他人分享、社区、账号与多人协作；
- 跨书统一掌握档案；多本书只提供清楚的书筛选，不混算掌握度；
- 自动批量制卡、自动生成播客或视频等生成物；
- 让 AI 未经确认直接改计划、删除学习记录或篡改掌握证据；
- 为“以后可能有用”设计插件市场、技能编排平台或可视化工作流。

分享只保留为 [后续候选](../后续候选/书籍分享.md)，不得影响本版闭环。

## 6. 产品概念

| 概念 | 产品含义 | 关键约束 |
|---|---|---|
| 书 / 学习项目 | 一次“学透这本书”的完整容器 | 一本书对应一套目录、计划、会话、卡片和档案 |
| 目录节点 | 从原书结构识别出的层级，反映书长什么样 | 必须展示识别可信度，允许用户修正 |
| 知识点 | 一次学习、测验和掌握评估的基本单位 | 不等于正文切片；须有来源，非学习内容可排除 |
| 章 | 设置学习强度、查看局部进度的目录层级 | 产品在目录中明确标出哪些节点按章管理 |
| 学习强度 | 用户希望把这章学到什么程度 | 略读、读透、学透；是任务与完成判定的硬约束 |
| 学习方案 | 用户希望 AI 怎么陪学 | 带我学、讲给我听、帮我过关；不能越过学习强度 |
| 计划 / 任务 | 把目标落到具体日期和学习动作 | 用户确认后生效；可增删、改期；逾期重排 |
| 学习会话 | 围绕一个知识点的讲解、提问、测验或复述 | 对话必须带当前学习上下文与来源 |
| 卡片 | 针对一个真实记忆缺口的复习单元 | 来自答错、卡壳标记或手建，可回源文 |
| 掌握档案 | 每个知识点的系统评估、自评和证据历史 | 系统评估与自评分开；进度唯一依据是证据 |
| 督促 | 让计划持续可执行的提醒与重排 | 不堆积、不羞辱、不用虚假进度鼓励 |

**知识点是产品枢纽**：计划排它，会话讲它，测验考它，卡片记它，档案证明它。任何新功能若绕过知识点另建一套进度，都会重新制造 V0.1 的割裂。

## 7. 核心闭环

```text
导入一本书
  → 识别目录、显示依据与置信度
  → 自动进行目录规划（失败则保留原结构）
  → 用户确认或修改知识骨架、设置各章强度
  → 目标访谈、确认计划
  → 今日任务进入学习会话
  → 原文 + 讲解 + 提问 + 测验 / 复述
  → 答错或卡壳形成卡片，掌握证据更新
  → 到期复习，连续错误形成薄弱点
  → 薄弱点影响后续任务，逾期与中断触发重排
  → 章级与全书进度随证据更新，必要时回退
```

闭环里有两个重要方向：

- **向前**：书结构决定学习顺序与计划，计划驱动学习行为；
- **向后**：测验和复习结果改变档案、薄弱点与后续计划，而不是学习会话结束后数据就停止流动。

## 8. 关键产品逻辑

### 8.1 知识骨架：先可信，再聪明

目录构建分两层，但用户看到的是同一棵可编辑树：

1. **原书结构**：优先保留书已有的目录、标题与顺序。没有 AI 也应能看到这一层。
2. **目录规划**：AI 只根据目录标题、层级和篇幅做语义修正，例如排除前言、致谢、纯习题答案，拆分过粗区域，合并过碎节点，把章内内容组织成适合学习的区域。

AI 的价值是**修正目录的学习语义**，不是从正文重新发明一本书。原目录会先开放查看，AI 调整则等原文引用就绪后再应用，确保拆分、合并后的学习单元仍能回到原书。规划结果必须可识别、可修改；失败不能清空原目录，也不能让导入一直等待。

### 8.2 知识点粒度：学习单位，不是检索单位

合适的知识点通常能用一次 20–45 分钟的专注学习完成，并足以支持一组有上下文的测验。1–4 页只是常见参考，不是机械切分规则。

判断一个节点是否合适，问四件事：

- 能否用一句清楚的话说明“学完它会做什么或理解什么”？
- 能否围绕它讲出一段完整语义，而不是半页残片？
- 能否出几道有区分度的题，而不是只考一句定义？
- 答错后能否明确定位一个可补救的缺口？

如果答案多数是否定，说明节点可能过碎、过粗或根本不是学习单元。

### 8.3 强度是硬约束，方案是软偏好

| 强度 | 用户意图 | 完成方式 | 不发生什么 |
|---|---|---|---|
| 略读 | 知道这章讲什么即可 | 用户显式标记读完 | 不安排知识点测验，不进入学透分母 |
| 读透 | 能用自己的话讲清这章 | 章末费曼复述通过 | 不要求每个知识点分别测验，不进入学透分母 |
| 学透 | 知识点学会且之后仍记得 | 知识点通过考练，相关卡片无高风险 | 不能靠任务完成或自评直接标记学透 |

学习方案只调整讲解风格和考练密度。“帮我过关”也不能把略读章变成学透章；改强度不会追溯改写历史证据。

“我已掌握”只是用户的自评，不等于系统通过。只有学透章内有原文的知识点可以用一道快速题验证自评；通过后才记录自评，未通过、出题失败或中途退出都不跳过任务，未通过时回到计划。略读章看显式读完，读透章看费曼复述，不能借自评绕过各自的完成方式。

### 8.4 卡片只在学习缺口出现时创建

三种入口足够：

1. **答错自动成卡**：错题已有明确问题、答案和来源，系统直接沉淀；
2. **对话中手动标记**：用户觉得某段解释或自己的卡壳值得记，主动保存；
3. **手建卡片**：用户自己写正反面并关联知识点。

不做“学完本节后，AI 建议生成 12 张卡”。没有真实缺口的批量卡片只会制造复习债务。

### 8.5 学透进度必须诚实且可回退

- 只统计用户设为“学透”的章内有效知识点；
- 被排除的非学习单元、没有来源的节点不进入分母；
- “有效通过”表示知识点已有通过证据，且直接关联的复习卡没有高风险；全书分子与学透章完成使用同一口径；
- 没有可统计对象时显示“—”，不是 0%；
- 通过测验后，若后续复习显示记忆仍不牢，该知识点退出有效通过，章完成状态和全书百分比同步下降，历史通过证据仍保留；
- 改强度、合并或排除节点造成分母变化时，界面必须说明变化，不能只展示一个变大的数字；
- 每个百分比都能下钻到章、知识点和具体证据。

## 9. 用户旅程

### 9.1 第一次使用

1. 点击“添加一本书”，输入学习目标并选择一个文件；
2. 在导入页看到解析、目录识别、目录规划等状态，不需要理解内部技术；
3. 打开目录，看到识别依据、置信度和 AI 调整痕迹；
4. 排除不需要学习的部分，必要时拆分、合并或改名；
5. 给各章设置略读、读透或学透；
6. 回答目标、期限和每日时间，预览计划并确认；
7. 回到首页，从第一条今日任务开始学习；
8. 第一次答错后即看到“已形成复习卡”，理解学习闭环不是未来功能。

### 9.2 日常学习

- 首页先处理到期复习，或直接进入继续上次；
- 会话左侧能看原文，右侧能看讲解和提问；
- 学完立即考一组，错题回原文并自动成卡；
- 离开时知道明天会学什么，不需要自己整理状态。

### 9.3 中断与恢复

- 普通逾期：首页说明哪些任务已搬到未来，不累积出无法完成的今天；
- 长期中断：用户确认后重排剩余计划，并优先处理高风险记忆；
- 恢复后不展示“你已经失败”，只展示一个可完成的下一步。

## 10. 产品原则

按优先级排序，冲突时上位优先：

1. **闭环大于单点**：宁可每环简单，也不能导入、学习、复习彼此断开。
2. **先结构，后智能**：没有 AI 也能看见已识别的书结构；AI 用于改善而不是阻塞。
3. **掌握证据大于阅读行为**：读过、看过、勾选过都不等于学会。
4. **用户确认大于 Agent 自作主张**：目录、计划、删除与重排都要可见、可控。
5. **信任锚定原书**：讲解、题目、卡片与档案都能回到来源。
6. **保护长期动机**：任务可完成，逾期可重排，进度变化如实解释。
7. **成本随学习量，不随藏书量**：浏览和目录整理应轻量，AI 用在真正需要语义判断的地方。
8. **开放而非锁定**：学习数据、卡片和报告可以导出。

## 11. 验证标准与止损线

### 11.1 本版成功证据

| 要验证的问题 | 证据 |
|---|---|
| 导入入口是否成立 | 一本真实 300 页左右的书能快速看到结构树；结构识别本身不消耗 LLM；AI 失败时仍可编辑原结构 |
| 粒度是否改善 | 同一本样书不再产生上千个半页知识点；计划任务时长、讲解上下文与题目质量可人工接受 |
| 用户是否知道下一步 | 首次导入与每日打开都无需询问“我该点哪里”，主路径可独立完成 |
| 卡片是否负担可控 | 新卡都能追溯到答错、手动标记或手建，不出现无学习事件的批量卡片 |
| 学透是否可信 | 抽查已通过知识点均可回证据；制造高风险卡后章状态与全书进度能回退 |
| 闭环是否能持续 | 自己完整学透至少一章，并在随后复习中验证，而非只完成一次演示 |

### 11.2 止损线

出现以下任一情况，停止扩展功能：

- 必须等待全文 LLM 拆解才能看到目录；
- AI 目录规划失败后原目录消失或无法继续；
- 学透百分比无法解释，或可通过改强度静默美化；
- 首页只有统计而没有明确学习动作；
- 自动化测试通过，但真实导出、筛选、回跳、编辑仍失败。
