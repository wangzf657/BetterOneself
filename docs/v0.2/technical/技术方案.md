> 产品依据：[需求分析](../product/需求分析.md)、[需求列表](../product/需求列表.md)
> 配套：[数据模型](数据模型.md)、[流程图](流程图.md)、[接口设计](接口设计.md)

## 1. 技术目标与约束

1. 原书结构识别与 AI 目录规划解耦：前者零 LLM，后者失败可跳过。
2. 复用 V0.1 的计划、会话、测验、卡片、FSRS、档案与督促资产，不重写闭环。
3. 只用当前技术栈与已有依赖完成本版；先验证再承诺格式稳定性。
4. 核心 AI 能力拆成三个可独立测试的小 skill，不建设通用编排平台。
5. 所有 LLM 自动化测试 mock；真实样书只用于人工冒烟与质量评审。

## 2. 技术栈

| 层 | 沿用选型 | 本版使用方式 |
|---|---|---|
| 后端 | Python 3.12、FastAPI、SQLAlchemy 2、SQLite | 单机单用户，Alembic 迁移 |
| 向量 | sqlite-vec、硅基流动 BAAI/bge-m3 | 1024 维 float32；与正文解析异步 |
| PDF | Docling；PDF 书签读取 | 书签优先，正文按页定位；完整链路待 spike |
| EPUB | 标准库 `zipfile` + 已有 BeautifulSoup/lxml | 读 OPF、nav/NCX 与正文，不新增 ebooklib |
| AI | OpenAI 兼容 SDK | 目录规划、讲解、费曼、出题与判分 |
| 编排 | LangGraph 仅保留在有状态学习会话 | 单次目录规划不强行上图 |
| 复习 | py-fsrs | 不自研排程 |
| 前端 | React 19、Vite、TS strict、TanStack Query、shadcn/ui、Tailwind 4 | 类型由 OpenAPI 生成 |
| 测试 | pytest、Playwright、ruff、mypy、tsc、ESLint | 核心逻辑单测 + 主链路真实结果 E2E |

GLM Coding Plan 沿用既有实测约束：不含 embedding；embedding 独立走硅基流动；高负载可能排队；思考型模型需给 reasoning tokens 留空间。以上属于服务约束，不进入产品文案。

## 3. 模块边界

```text
frontend/src/features/
  today / studies / outline / plan / learn / review / cards / mastery / settings

backend/app/
  api/          参数校验与响应，不写业务
  services/     studies / sources / knowledge / planning / learning / quiz /
                review / mastery / nudges
  ingest/       格式识别、目录提取、正文解析、切片、定位
  skills/       outline_planner / tutor / quiz
  agents/       仅保留需要 LangGraph 状态机的学习会话
  models/       按数据模型迁移
```

目录提取是确定性 ingest 能力，不是 LLM skill。卡片创建主要是 service：答错自动、手动标记、手建都不需要额外 LLM，因此不制造“卡片生成 skill”。

## 4. 导入与目录识别

### 4.1 三类产物与先后顺序

**阶段 A：结构草稿**

- 读取目录、标题与顺序；
- 生成初始知识树；
- 标记识别依据与置信度；
- 不调用 LLM，不等待正文或 embedding，结构树立即可浏览。

**阶段 B：正文与引用**

- 解析正文、规范化、切片；
- 将切片关联到目录节点，计算跨格式通用篇幅；
- 提交 `knowledge_refs` 后自动触发一次 AI 目录规划；
- 后台并行生成向量；来源未就绪的节点明确显示“原文准备中”。

**阶段 C：AI 规划应用**

- 只输入标题、层级和篇幅，不输入正文；
- 必须在引用挂载完成后才能应用拆分、合并与组织操作，避免把引用尚未生成的节点改成无来源学习单元；
- 不等待 embedding；向量先完成或规划先完成都不改变目录结果。

### 4.2 格式策略

| 格式 | 结构信号优先级 | 正文与定位 | 置信度处理 |
|---|---|---|---|
| PDF | 书签 → 编号标题 → 字号/字重 | Docling 正文；优先按书签页码区间挂切片 | 书签高；编号中；样式低 |
| EPUB | nav → NCX → 正文标题 | OPF spine 顺序读取 XHTML，保留 `href + 锚点` | nav/NCX 高；正文标题中 |
| Markdown | `#`–`######` 标题 | 按完整标题路径切分，记录行号 | 明确标题高；跳级需提示 |
| TXT | Markdown 式标题 → `第 N 章` / 数字编号 → 无结构 | 按识别标题切分并记录行号 | 编号中；无结构不假装有目录 |

无结构 TXT 或其他识别失败文档：保留正文、显示无目录空态，允许手动新增学习单元；**不自动全文 LLM 拆解**。

### 4.3 PDF 现状与待验证

【现状】

- `ingest/parsers.py` 当前只实现 Markdown 与 PDF；PDF 直接整本 `convert()` 后导出 Markdown。
- 当前没有利用 PDF 书签建立知识树，也没有按页导出。
- 当前切片器只把 `level <= 2` 的标题写入层级路径，h3–h6 会丢失结构意义。
- 真实样书通过书签读取到 293 个节点、12 个顶层节点，说明书签是有价值的主信号。

【目标】

1. 先读书签与页码，形成结构草稿；
2. Docling 按页导出正文，利用书签页码区间确定目录叶子；
3. 页内再按标题与段落切片，并保留完整层级；
4. 书签与正文无法对齐的区间标低置信度，不模糊匹配后假装成功。

【已确认的库能力】

- Docling 导出接口存在 `page_no` 与 `page_break_placeholder` 参数；
- 文档项 provenance 有页码信息；
- 标题层级推断配置存在，但默认不启用，且中文“第 N 章”不能承诺被英文编号规则识别。

【待验证，不得提前写成已完成】

- 313 页样书从书签 → 按页导出 → 页码区间挂引用的完整链路；
- 第一章 p15–38 的引用覆盖率、错挂率与耗时；
- 无书签 PDF、扫描 PDF、中文编号 PDF 的降级表现；
- EPUB nav/NCX 与 TXT 编码、标题规则的真实样本覆盖。

### 4.4 切片调整

- 保留 h1–h6 全部标题路径；
- 继续以标题和段落做机械切片，切片是检索单位，不直接创建知识点；
- `MAX_CHARS` 初始沿用现有值，只有真实检索抽评证明不足时才调；
- `location` 保存页码或行号区间，引用回跳不依赖标题模糊搜索。

## 5. AI 目录规划

### 5.1 输入与输出

输入仅包括：

```json
{
  "book_title": "……",
  "nodes": [
    {"id": "n1", "parent_id": null, "title": "……", "depth": 1, "char_count": 14620, "page_span": 24}
  ]
}
```

- `char_count` 为必填的跨格式篇幅指标：节点自身及后代的规范化纯文本去除空白后的字符数，同一切片只计一次；
- `page_span` 仅 PDF 有可靠页码时填写，其他格式为 `null`，不得伪造页数；
- 不输入正文，不让模型重新生成整棵树。输出限定四类操作：

1. `exclude`：排除非学习单元并给理由；
2. `split`：把篇幅过大或语义过多的节点拆成 2–5 个学习区域；
3. `merge`：合并在语义与篇幅上都过碎的相邻节点；
4. `organize`：在章内建立学习区域父节点，但不改变章锚点，产物 `origin='ai_organize'`。

每条操作建议必须引用输入节点 ID，并带一句理由。结构化输出校验失败即本次规划失败，保留原树。

### 5.2 自动触发与降级

- 初始结构树提交后先解析正文并挂载引用；引用事务提交后自动排一次规划；
- 同一结构版本只自动跑一次，页面浏览、访谈和计划生成不重复触发；
- 正文未就绪时不调用规划，`outline_status='structure_ready'` 与正文解析错误分别展示；
- 未配置 LLM：在引用就绪后直接标记 `skipped`；
- 超时、限流、校验失败：标记 `failed/skipped`，原树保留；
- 用户可在引用就绪后手动重试；
- 运行期间用户已修改的节点，在应用结果时按 `updated_at` 检查并跳过冲突，保留用户最后操作。

### 5.3 粒度约束

规划 prompt 只给软约束，不制造机械规则：

- 常见学习目标为 20–45 分钟；PDF 可辅以约 1–4 页参考，其他格式使用 `char_count` 与同书节点篇幅分布；
- 过粗或过细必须结合标题语义判断；
- 小结、思考题是否排除取决于内容角色，不能只用关键词正则；
- 章节点不得删除，不跨章合并；
- 不生成 LLM 依赖边，默认学习顺序仍是目录顺序。

真实样书旧库 1132 个知识点、946 个仅一条引用，是“过碎”的反例；新版目标约 180 个只是样书评审参照，不是全产品定额。

## 6. 三个核心 skills

目录：

```text
backend/app/skills/
  outline_planner/
    skill.py
    prompt.md
    test_skill.py
    golden/
  tutor/
    skill.py
    prompt.md
    test_skill.py
    golden/
  quiz/
    skill.py
    prompt.md
    test_skill.py
    golden/
```

每个 skill 只有：

- 一个输入/输出 Pydantic 契约；
- 一个主提示词文件；
- 一组 golden cases；
- 对统一 `llm()` 薄函数的调用。

| Skill | 职责 | 不做什么 |
|---|---|---|
| `outline_planner` | 目录排除、拆分、合并、章内学习区域 | 不读正文、不建依赖图 |
| `tutor` | 引导/直答讲解、费曼追问与评价 | 不改计划、不直接改掌握状态 |
| `quiz` | 出题、客观题契约、简答评分 | 不自行决定卡片与复习排程 |

service 负责权限、数据、事务和副作用；skill 只做 AI 输入输出。golden case 用于 prompt 迭代，测试全部 stub，不花真实 token。

不引入注册表、热加载、YAML DSL、插件包、可视化编排或动态工具市场。

## 7. 学习、检索与证据

### 7.1 会话

- 保留现有 LangGraph 学习会话状态机与 SQLite checkpoint；
- 新建 `session_type='lecture'` 的讲解型会话后，前端自动调用开场端点，首条 assistant 消息带引用；这里的 `lecture` 是会话类型，不是学习方案，`guided / lecture / drill` 三种方案都自动生成开场；free 会话不调用；
- 创建会话时保存三值 `scheme`，取章覆盖或项目方案；由它派生 `socratic_mode` 与考练密度，不能再把三种方案压成一个布尔值；
- 会话内切换三值方案只影响当前会话后续消息与测验，不改书/章默认；
- 略读不开放知识点测验，读透只开放章末费曼，service 层硬校验。

### 7.2 检索

【现状】当前 `_retrieve` 先取知识点静态引用，不足 `_TOP_K=6` 时用项目内向量补足。

【目标】保留“静态引用保底 + 向量补足”，并补两类测试：

- 知识点引用少于 2 条：是否能补足完整上下文；
- 知识点引用超过 6 条：选择是否按当前问题相关，而不是固定截掉后半章。

在真实抽评前不新增复杂重排器。若现有截断确实影响质量，先在知识点引用池内做向量排序，仍保持 `_TOP_K=6`。

### 7.3 测验、卡片与掌握

- 答错由 `quiz` service 同事务创建 `origin='auto_quiz'` 卡片并记录掌握事件；
- 对话标记与手建复用现有 `manual_mark / manual_new`；
- 不做批量卡片生成器；
- 连续错误、薄弱点任务、FSRS 评分与复习日志沿用现有 service；
- 自评快速验证复用现有 `self-report / quick-quiz` 路径，但 service 增加“仅学透章有效叶子”校验；出题前不写自评，通过后才标记 `mastered`，未通过或中途退出均不跳过任务，未通过时补回计划；
- 费曼通过增加 `feynman` 证据，不用 `quiz ? 测验 : 复习` 的二分前端显示。

## 8. 异步、事务与恢复

- 沿用 FastAPI BackgroundTasks，不引入 Celery 或消息队列；
- 文件保存、项目创建、主资料绑定在一个事务；正文解析、向量与目录规划在提交后运行；
- 结构建树、引用挂载、规划应用、拆分合并各自独立事务；引用挂载提交是规划触发与应用的前置条件，embedding 不是；
- 重新识别只用于尚无自动结构的资料：重跑确定性结构识别与正文解析，保留手动节点和现有学习数据，不触发全文 LLM 拆解；已有自动结构时返回冲突，不用重解析覆盖用户目录；
- 重启后未完成的内存任务以数据库状态识别：正文可重试解析，目录规划可重试，原树不清空；
- 每日摘要、周复盘、逾期重排继续惰性触发；V0.2 不引入常驻调度。

## 9. 前端实现约定

- 服务端状态全部 TanStack Query，路由与书选择器保持一致；
- OpenAPI 生成类型，禁止手抄响应模型；
- 树编辑统一走 knowledge mutation，成功后失效目录、计划、档案与首页进度查询；
- 原文深链使用真实 `studyId` 与 chunk 定位，不允许 `/studies/0/`；
- 下载用浏览器真实响应并验证 `download` 事件，不拦截后假成功；
- 组件只实现页面清单需要的状态，不提前做拖拽布局、虚拟化或跨书档案。

## 10. 安全与数据边界

- LLM 与 embedding key 继续 Fernet 加密落库，密钥文件本机保存；
- 日志、异常、outline 事件、导出和 LLM 请求上下文均不包含明文 key；
- 单部署单用户，无账号；默认仅本机/内网；
- 全量导出排除密钥明文；
- 上传只接受四种扩展名并限制大小，文件名只作为显示文本，存储路径由服务端生成；
- EPUB 作为 zip 读取时防路径穿越，不将包内路径直接写盘。

## 11. 测试与验证

### 11.1 自动化

| 层 | 必测 |
|---|---|
| ingest 单测 | 四种格式、标题跳级、无目录、编码、页码/行号定位、完整 h1–h6 |
| 目录 service | 零 LLM 建树、引用提交前不规划、章层稳定、排除与恢复、冲突跳过、规划失败保树 |
| 目录 skill 契约 | 四种格式 `char_count`、PDF 可选页跨度、四类操作、非法节点 ID、跨章合并、结构化输出失败 |
| 数据一致性 | 拆分合并不减卡片/测验/证据，掌握取较弱状态；embedding 先完成或后完成均不影响目录 |
| 进度算法 | 分母为 0、旧项目、排除、无引用、高风险同时降低分子与章状态、暂停卡、可回退 |
| 学习契约 | 三种方案及会话内切换、强度硬约束、自评快速验证、开场、引用、答错成卡、费曼证据 |
| E2E | 导入到复习主链路 + 真实下载 + 筛选 + 正确回跳 + AI 失败降级 + 高风险后百分比与章同步回退 |

### 11.2 真实样书 spike 顺序

1. **PDF 第一章**：验证书签页码区间、切片归属和引用回跳；
2. **全书结构**：验证 293 个目录节点的结构草稿耗时与 AI 规划输入大小；
3. **EPUB/TXT 小样本**：只验证主路径与无目录降级，不追求格式全覆盖；
4. **人工学习抽评**：抽查讲解、题目、卡片与 20–45 分钟任务粒度。

任一样书未达到“结构可信、引用可回跳”，先修 ingest，不继续扩张 AI 能力。
