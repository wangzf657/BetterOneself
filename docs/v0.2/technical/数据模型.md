# V0.2 技术数据模型

> 日期：2026-11-20｜状态：目标设计，尚未实施
> 产品依据：[需求列表](../product/需求列表.md)｜实现边界：[技术方案](技术方案.md)
> 本文是目标字段与统计口径的技术事实源。现有代码以 `backend/app/models/` 为准，不能把本文当作已经完成的迁移。

## 1. 建模原则

1. 保留 V0.1 已有学习闭环表，不为“新书方案”重建一套平行数据体系。
2. 知识点仍是唯一学习枢纽；不新增 `chapters` 表。章是带稳定标记的知识树节点。
3. 目录原文、AI 规划与用户修改必须能区分；结构变化留事件，掌握证据不被重建清空。
4. 学透进度实时计算，不落百分比快照；只有结业报告保存当时快照。
5. 主资料是单文件，但暂不删除旧多资料关联表，避免破坏旧项目。
6. 无来源、被排除的节点不进入学透分母；自评永远不等于系统证据。

## 3. 字段增量

### 3.1 `studies`

| 字段 | 类型 | 目标语义 |
|---|---|---|
| `primary_source_id` | `int FK sources.id ON DELETE SET NULL`，可空 | 新项目的唯一主文件；旧项目为 `NULL` |
| `scheme` | `varchar(16) NOT NULL DEFAULT 'guided'` | `guided / lecture / drill` |
| `outline_status` | `varchar(24) NOT NULL DEFAULT 'idle'` | `idle / structure_ready / planning / ready / skipped / failed` |
| `outline_error` | `varchar(500)`，可空 | 最近一次目录规划的可读失败原因 |

迁移时将既有 `decompose_status / decompose_error` 重命名为 `outline_status / outline_error`，同步更新全部调用点，不保留双写字段。旧的“全文拆解运行中”状态不再进入新导入路径。

约束：

- 新项目创建提交前必须同时存在主资料与 `study_sources` 关联；
- 主资料必须属于当前项目；
- 不提供换绑主文件接口，换书即新建项目；
- `primary_source_id IS NULL` 表示旧项目，API 的学透聚合返回 `null` 与原因，不返回 0。

### 3.2 `sources`

`type` 的新项目取值为 `pdf / md / txt / epub`。旧值 `url / github / text` 仅为历史兼容，不开放新入口。

解析产物继续使用：

- `content_md`：规范化正文；
- `raw_path`：原文件；
- `parse_status / parse_error`：正文解析状态；
- `source_chunks.heading_path`：完整标题路径；
- `source_chunks.location`：JSON，按格式保存 `page_start/page_end`、`chapter_href` 或行号，不新增一批格式专用列。

### 3.3 `knowledge_points`

| 字段 | 类型 | 目标语义 |
|---|---|---|
| `is_chapter` | `bool NOT NULL DEFAULT 0` | 稳定章锚点；结构识别后确定，普通拆分合并不改变 |
| `intensity` | `varchar(8)`，可空 | 仅章：`skim / read / master`；新建章默认 `master` |
| `scheme_override` | `varchar(16)`，可空 | 仅章；`NULL` 跟随项目方案 |
| `read_marked` | `bool NOT NULL DEFAULT 0` | 仅章；用户显式标记读完 |
| `feynman_passed` | `bool NOT NULL DEFAULT 0` | 仅章；读透完成证据快照，原始证据仍存会话与事件 |
| `excluded` | `bool NOT NULL DEFAULT 0` | 排除出学习、计划与学透统计；节点保留可恢复 |
| `exclusion_reason` | `varchar(500)`，可空 | AI 或用户排除理由 |
| `origin` | `varchar(24) NOT NULL DEFAULT 'legacy'` | `toc / heading / manual / ai_split / ai_merge / ai_organize / legacy` |
| `source_name` | `varchar(300)`，可空 | 原目录标题，AI 或用户改名后仍可对照 |
| `confidence` | `float`，可空 | 0–1；人工创建或确认后可为 1 |
| `confidence_basis` | `varchar(32)`，可空 | `pdf_bookmarks / epub_nav / md_headings / numbering / style / manual` |
| `planning_note` | `text`，可空 | 最近一次 AI 规划的拆分、合并或组织理由 |

写入规则：

- `intensity / scheme_override / read_marked / feynman_passed` 只允许 `is_chapter=1`；
- 排除章表示整棵子树在统计与计划中有效排除，但数据不删除；
- 合并与拆分不得跨章移动学习证据；整章可调整顺序；
- `origin / source_name / confidence_basis` 用于展示依据，不参与掌握状态计算；
- 每次用户手动修改都要更新 `updated_at`，供后台规划应用结果时检测冲突。

### 3.4 `sessions`

| 字段 | 类型 | 目标语义 |
|---|---|---|
| `scheme` | `varchar(16) NOT NULL DEFAULT 'guided'` | 当前会话的 `guided / lecture / drill`，创建时取章覆盖或项目方案 |

- `guided`：引导讲解、标准考练密度；`lecture`：直接讲解、较低考练密度；`drill`：短讲解、较高考练密度。
- `socratic_mode` 保留给现有会话图使用，由 `scheme` 推导：`lecture=false`，其余为 `true`；它不是第三份方案事实源。
- 会话内修改方案只更新当前会话的 `scheme` 与派生开关，影响后续讲解和考练，不回写书/章默认，也不改写历史消息。
- 迁移旧会话时按原 `socratic_mode` 回填为 `guided / lecture`；旧数据没有 `drill` 语义，不凭空推断。

### 3.5 `mastery_events` 与 `summaries`

- `mastery_events.evidence_type` 扩展为 `quiz / review / feynman`；费曼的 `evidence_id` 指向会话。
- `summaries.summary_type` 扩展为 `daily / weekly / graduation`。
- 结业报告以 `study_id + summary_type='graduation'` 查重；`metrics_json` 保存当时的分子、分母与各章判定，之后进度回退不重写历史报告。

### 3.6 `outline_events`（新表）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | PK | |
| `study_id` | FK `studies.id ON DELETE CASCADE`，索引 | |
| `kp_id` | FK `knowledge_points.id ON DELETE SET NULL`，可空 | 节点删除后事件仍保留 |
| `event_type` | `varchar(32)` | 见下表 |
| `actor` | `varchar(16)` | `structure / ai / user / system` |
| `detail_json` | `text NOT NULL DEFAULT '{}'` | 调整理由与前后快照 |
| `created_at` | `datetime` | |

事件类型：

```text
structure_built / planning_started / planning_finished /
planning_skipped / planning_failed /
kp_created / kp_renamed / kp_split / kp_merged / kp_moved /
kp_excluded / kp_restored / kp_deleted / intensity_changed
```

所有会影响有效叶子或学透章范围的事件，`detail_json` 统一带：

```json
{
  "leaves_before": 186,
  "leaves_after": 178,
  "master_leaves_before": 152,
  "master_leaves_after": 144,
  "percent_before": 31.6,
  "percent_after": 32.6,
  "reason": "排除本章小结与纯习题答案"
}
```

规划运行事件另带输入节点数、排除/拆分/合并计数、跳过冲突节点数与用量；不存正文和密钥。

## 4. 章、叶子与有效范围

### 4.1 初始章层

结构树首次生成时：

1. 从根向下找第一个“同一层节点数 ≥ 2”的层级；
2. 若整棵树每层都只有一个节点，取最深层；
3. 该层节点设置 `is_chapter=1`；
4. 后续拆分、合并与改名不重新计算章层，避免进度锚点漂移。

### 4.2 有效叶子

```text
叶子 = 没有未排除子节点的学习单元
有效叶子 = 叶子
           且自身及祖先均 excluded = 0
           且 knowledge_refs 至少一条
```

- 已排除父节点的后代不进入计划与统计；
- 无引用节点可以展示和编辑，但不进入学透分母；
- 章自身没有子节点时，可作为一个叶子，前提是有引用；
- 章引言引用挂在有子节点的章自身时，只用于阅读，不单独制造一个统计叶子。

## 5. 进度与风险口径

### 5.1 全书学透百分比

```text
D = 所有 intensity='master' 且未排除章的有效叶子并集
有效通过叶子 = mastery_status='passed' 且该叶子没有高风险卡
N = D 中有效通过叶子数
percent = D > 0 ? round(100 * N / D, 1) : null
```

高风险只在实时统计中阻断“有效通过”，不把历史 `mastery_status` 或测验证据篡改成失败。界面应区分“测验已通过”和“记忆仍待巩固”。

同时返回：

- `master_done / master_total`：学透完成章数 / 未排除学透章数；
- `read_done / chapter_total`：显式读完章数 / 未排除总章数；
- 每章 `leaf_passed` 表示有效通过数，`risk_blocked_leaves` 表示仅因高风险而未计入分子的叶子数；
- `percent=null` 时前端显示 `—`；
- 旧项目全部返回 `null`，附 `reason='legacy_project'`。

### 5.2 章完成

| 强度 | 完成判定 |
|---|---|
| `skim` | `read_marked=1` |
| `read` | `feynman_passed=1`，且能定位至少一条费曼证据 |
| `master` | 章内有效叶子非空，且全部为有效通过叶子 |

任务勾选、自评、会话时长均不参与完成判定。全书分子与学透章完成共用“有效通过”定义，因此不得出现某学透章仅因高风险未完成、全书却仍显示 100% 的情况。

### 5.3 高风险卡

```sql
status = 'active'
AND stability IS NOT NULL
AND stability < 3.0
```

- `stability` 单位为天；3.0 是 V0.2 固定阈值，代码留 `shortcut:` 注释，出现真实调参需求再进设置；
- py-fsrs v6 没有 `New` 状态，新卡为 `Learning + stability=NULL`，不能用 `state != 'New'`；
- Python 比较前必须先排除 `None`；
- 学透判定只统计 `cards.kp_id` 直接指向章内有效叶子的卡片；中间节点、已排除节点的卡片仍在卡片页可见，但不阻断本书学透统计；
- 高风险卡使其直接关联的有效叶子退出 `N`，并使所属学透章未完成；暂停卡不阻断，章聚合返回 `suspended_cards` 并明示数量。

### 5.4 可回退

以下变化允许百分比或章状态下降：

- `passed → weak / learning`；
- 新卡或既有卡变为高风险，使关联叶子不再有效通过；
- 合并后目标节点按较弱掌握状态记；
- 新增有效叶子使分母增大。

改强度或排除导致分母缩小时，不是“新增掌握证据”，必须写 `outline_events` 并返回前后值。

## 6. 合并与拆分的数据不变量

### 合并

`knowledge.merge_kps` 现有迁移思路可复用，但必须验证完整覆盖：

- `knowledge_refs` 去重迁移；
- 子节点、`cards`、`quizzes`、`tasks`、`mastery_events`、`sessions` 与旧依赖边保留；
- 目标节点掌握状态取两者较弱者：`weak < new < learning < passed`；
- 同事务写 `kp_merged` 事件与关联迁移计数；
- 禁止调用“删除整树再建”的路径。

### 拆分

- 原节点的引用按用户或 AI 指定范围分配到新节点；
- 历史证据不伪造到新节点：保留在原节点的历史事件中，原节点可保留为父节点；
- 新学习单元默认 `new`，除非有可明确对应的既有证据；
- 卡片若无法明确归属，保留在原父节点并在界面说明，不随机复制；
- 同事务写 `kp_split` 事件。

## 7. 迁移策略

当前代码通过 Alembic 启动迁移，V0.2 新增一个显式 revision：

1. 重命名两个目录状态列；
2. 为 `studies`、`knowledge_points` 与 `sessions` 添加 nullable 或带默认值列，并按旧 `socratic_mode` 回填会话方案；
3. 创建 `outline_events` 与索引；
4. 不回填旧项目主资料，不批量重建旧知识树；
5. 迁移前后分别测试：空库、V0.1 样例库、含卡片与证据的旧项目。

SQLite 加列与重命名采用 Alembic batch 模式；禁止启动时临时拼一串无版本 `ALTER TABLE`。

## 8. 明确不新增

- `chapters`、`book_packs`、`shares`、用户与社区表；
- 目录规划注册表、技能实例表、可视化编排表；
- 学透百分比缓存列；
- 独立的考练密度字段，密度由会话 `scheme` 决定；
- 高风险阈值设置列；
- 跨书统一档案表；
- 为分享预先设计的“以后会用”字段。
