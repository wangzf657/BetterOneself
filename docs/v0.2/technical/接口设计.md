# V0.2 接口设计

> 日期：2026-11-20｜状态：目标 API 契约，未实施
> 产品行为以 [需求列表](../product/需求列表.md) 为准；字段与统计口径见 [数据模型](数据模型.md)。
> 原则：路由薄、Pydantic 契约明确、前端类型从 OpenAPI 生成。本文不表示端点已经存在。

## 1. 通用约定

- 前缀 `/api`，JSON 使用 UTF-8；文件创建使用 `multipart/form-data`；对话继续使用 SSE。
- 路径中的资源必须属于同一 `study`，否则 404 或 422，禁止跨书挂接。
- 写操作由 service 开事务；路由不直接拼 SQL。
- 400 为格式错误，404 为资源不存在，409 为状态冲突，415 为文件类型不支持，422 为领域约束不满足。
- 错误响应保留可读 `detail`；内部异常不泄露密钥、文件绝对路径或模型请求头。
- 列表空结果返回 `[]`；学透不可用时返回 `null + reason`，不使用 0 冒充。

## 2. 项目与导入

### `POST /api/studies`【修改现有】

`multipart/form-data`：

| 字段 | 类型 | 必填 |
|---|---|---|
| `name` | string 1–200 | 是 |
| `goal` | string 1–1000 | 是 |
| `file` | `.pdf/.md/.markdown/.txt/.epub` 单文件 | 是 |

201 响应：

```json
{
  "id": 12,
  "name": "AI Agents in Depth",
  "goal": "……",
  "status": "active",
  "primary_source_id": 31,
  "book_title": "AI-Agents-in-Depth-zh-CN",
  "scheme": "guided",
  "outline_status": "idle",
  "outline_error": null
}
```

实现要求：项目、来源、关联与主资料绑定一个事务；提交后再排解析。旧 JSON 创建调用点与测试同步修改，不保留“无文件兼容分支”。

### 保留项目接口

- `GET /api/studies?include_archived=false`
- `GET /api/studies/{study_id}`
- `PATCH /api/studies/{study_id}`：只允许名称、目标、状态、方案；不允许换主文件
- `DELETE /api/studies/{study_id}`
- `GET /api/studies/{study_id}/progress`

进度响应改为按阶段返回：

```json
{
  "items": [
    {"key": "parse:31", "stage": "parse", "status": "running", "done": 8, "total": 24},
    {"key": "outline:12", "stage": "outline", "status": "pending", "done": 0, "total": 1},
    {"key": "embed:31", "stage": "embed", "status": "pending", "done": 0, "total": 36}
  ]
}
```

### 主资料

- `GET /api/studies/{study_id}/sources`【保留】用于旧项目与主资料信息；新 UI 不展示“添加资料”。
- `GET /api/sources/{source_id}`【保留】资料元数据与正文按需获取。
- `POST /api/sources/{source_id}/reparse`【扩展】默认只重试正文解析，不清空可用目录；空目录页的“重新识别”传 `{"mode":"structure"}`，重跑确定性结构识别与正文解析，202 返回处理状态。
  - `mode='structure'` 不调用 LLM，只用于尚无自动结构的资料；已有自动结构返回 409，不能借重解析覆盖用户目录。
  - 保留手动节点、卡片、测验、证据与用户设置，只新增本次识别出的结构及引用；仍未识别到时保留空目录与可读原因。
- `POST /api/studies/{study_id}/sources` 与 `/sources/text`【新入口停用】旧数据读取不受影响；是否从路由删除在实现时一次完成，不留隐藏的新上传能力。

## 3. 目录与知识点

### `GET /api/studies/{study_id}/knowledge`【扩展响应】

返回嵌套树，每个节点：

```json
{
  "id": 101,
  "parent_id": 20,
  "name": "4.2 上下文工程",
  "source_name": "4.2 上下文工程",
  "summary": "……",
  "is_chapter": false,
  "intensity": null,
  "scheme_override": null,
  "read_marked": false,
  "feynman_passed": false,
  "excluded": false,
  "exclusion_reason": null,
  "origin": "ai_merge",
  "confidence": 0.98,
  "confidence_basis": "pdf_bookmarks",
  "planning_note": "合并两个过碎的小节",
  "mastery_status": "learning",
  "self_reported": "unknown",
  "ref_count": 7,
  "sort_order": 2,
  "children": []
}
```

### `POST /api/studies/{study_id}/outline/replan`【新增】

- 202：`{"status":"planning"}`；
- 结构不存在返回 422；已有运行返回 409；
- 未配置 LLM 返回 422 并说明配置位置，不改变原树；
- 自动首次规划由导入 service 调用同一内部函数，不通过 HTTP 自调用。

### `GET /api/studies/{study_id}/outline/events`【新增】

按时间倒序返回 `outline_events`，保留 `detail_json` 中的前后统计与理由。支持 `limit`，默认 50，不做复杂筛选。

### `GET /api/studies/{study_id}/outline-status`【新增，替换 decompose-status】

```json
{
  "status": "ready",
  "error": null,
  "can_replan": true,
  "has_structure": true
}
```

旧 `POST /decompose` 不再进入新流程；全文拆解不是目录失败的重试方式。

### `POST /api/studies/{study_id}/kps`【扩展】

```json
{
  "name": "自定义学习区域",
  "summary": "……",
  "parent_id": 20,
  "chunk_ids": [501, 502]
}
```

手动节点 `origin='manual'`、`confidence=1`；无 `chunk_ids` 可创建，但 `ref_count=0` 时不进学透统计。

### `PATCH /api/kps/{kp_id}`【扩展】

可写字段：

```json
{
  "name": "……",
  "summary": "……",
  "parent_id": 20,
  "sort_order": 3,
  "intensity": "master",
  "scheme_override": null,
  "read_marked": true,
  "excluded": false,
  "exclusion_reason": null
}
```

- 章字段写非章返回 422；
- 移动与同章约束由 service 校验；
- 排除、恢复、移动与强度变化写事件；
- `feynman_passed` 不接受用户直接写入。

### `POST /api/kps/{kp_id}/split`【新增】

```json
{
  "units": [
    {"name": "信息筛选", "chunk_ids": [501, 502]},
    {"name": "信息压缩", "chunk_ids": [503, 504]}
  ]
}
```

2–5 个单元；引用必须来自原节点。响应返回新子树与事件。原子失败则不产生半组节点。

### `POST /api/kps/{kp_id}/merge`【保留路径，修改语义】

请求 `{"target_id": 102}`。service 必须迁移所有关联、目标掌握取较弱者并写事件；响应增加：

```json
{"id": 102, "moved": {"cards": 2, "quizzes": 3, "tasks": 1, "events": 5, "sessions": 2}}
```

### `GET /api/kps/{kp_id}/impact`【新增】

删除弹窗打开时调用，统计当前节点及全部后代的真实关联：

```json
{
  "descendants": 3,
  "tasks": 2,
  "cards": 5,
  "quizzes": 4,
  "mastery_events": 8,
  "sessions": 2
}
```

计数口径必须与后续删除事务一致；查询本身不改数据。

### `DELETE /api/kps/{kp_id}`【保留】

前端必须先展示 impact；service 返回冲突或执行删除，不能伪装成“排除”。成功返回 204，排除优先走 PATCH。

### `GET /api/kps/{kp_id}/content`【新增】

```json
{
  "kp": {"id": 101, "name": "……", "summary": "……", "mastery_status": "learning"},
  "refs": [
    {"chunk_id": 501, "source_id": 31, "heading_path": "……", "location": {"page_start": 114, "page_end": 114}, "content": "……"}
  ]
}
```

只返回当前节点引用，不拉整本书。

### `GET /api/chunks/{chunk_id}`【新增】

供全局引用回跳，返回切片、所属 `study_id/source_id`、标题路径和定位。跨书深链由服务端给真实上下文，前端不猜项目 ID。

## 4. 计划与任务


- `GET /api/studies/{study_id}/summaries`【保留】。
- `GET /api/studies/{study_id}/inactivity`【保留】。
- `POST /api/studies/{study_id}/return-from-break`【保留】。

## 5. 学习会话与测验

### `POST /api/studies/{study_id}/sessions`【修改并校验强度】

请求字段为 `kp_id/task_id/session_type/scheme`；`scheme` 可空，未传时取章覆盖或项目方案。响应包含实际生效的 `scheme`，不再暴露独立的 `socratic` 入参。略读知识点请求 quiz 类型或读透章请求逐点测验返回 422。

### `PATCH /api/sessions/{session_id}/scheme`【替换 socratic 开关】

请求 `{"scheme":"drill"}`，只允许 `guided / lecture / drill`。service 同步更新会话方案与派生的 `socratic_mode`，返回 `SessionOut`；只影响当前会话后续讲解和考练密度，不改书/章默认与历史消息。旧 `/socratic` 调用点同步迁移，不保留双入口。

### `POST /api/sessions/{session_id}/opening`【新增】

- 仅 `session_type='lecture' + kp_id` 可用；这里指讲解型会话，与方案字段无关，`guided / lecture / drill` 三种方案均可用；
- 前端进入会话且没有 assistant 开场时自动调用；
- 同步生成并保存首条 assistant 消息，200 返回 `MessageOut`；
- 已有开场则幂等返回原消息；
- 失败不创建伪造 user 消息，会话与原文仍可打开，前端可重试；
- `free` 返回 422。

其余保留：

- `GET /api/sessions/{session_id}`：响应含会话 `scheme`；
- `POST /api/sessions/{session_id}/chat`（SSE）
- `POST /api/sessions/{session_id}/quizzes`
- `GET /api/sessions/{session_id}/quizzes`
- `POST /api/quizzes/{quiz_id}/answer`

答错响应除测验结果外增加 `created_card_id`，便于前端显示真实成卡入口：

```json
{"id": 88, "is_correct": false, "ai_feedback": "……", "created_card_id": 44}
```

### 自评与快速验证【扩展现有端点】

仅学透章内的有效叶子开放“我已掌握”；略读、读透、无引用或中间节点调用快速验证返回 422，不能绕过章强度。

1. `POST /api/kps/{kp_id}/quick-quiz`：仅 `self_reported!='mastered'` 时可发起，已有自评时返回 409；201 返回 `{"quiz_id":88,"question":"……","options":["……"]}` 与来源，不泄露答案。创建题目时不写 `self_reported`，也不移除任务。
2. `POST /api/kps/{kp_id}/quick-quiz/{quiz_id}/answer`：请求 `{"answer":"……"}`，重复作答返回 409；通过时才在同一事务写入 `self_reported='mastered'`，未通过不修改自评并补回计划。
3. `POST /api/kps/{kp_id}/self-report`：只接受 `{"mastered":false}` 取消既有自评；直接传 `true` 返回 422 并提示必须完成快速验证。

出题失败、作答未通过、取消或未作答退出都不修改既有自评；除未通过按规则补回计划外，其余情况也不改计划，因此不存在“未验证已跳过”或误清除已有自评的状态。

响应：

```json
{
  "is_correct": false,
  "correct_answer": "……",
  "ai_feedback": "……",
  "chunk_ids": [501],
  "self_reported": "unknown",
  "reinstated_task_id": 71
}
```

未通过时保持原自评并补回当前生效计划，返回新任务 ID；没有生效计划时 `reinstated_task_id=null` 并提示下次生成计划会纳入。通过时写入 `mastered`，仅影响后续计划筛选。验证题目与结果按普通测验留证据，自评动作本身不是通过证据。

## 6. 卡片、复习与档案

### 卡片

- `GET /api/studies/{study_id}/cards`【扩展筛选】：增加 `kp_id/status/origin/query`；`kp_id` 包含后代。
- `POST /api/studies/{study_id}/cards`【保留】。
- `PATCH /api/cards/{card_id}`【保留】：编辑不重置 FSRS 与历史。
- `DELETE /api/cards/{card_id}`【保留】。
- `GET /api/studies/{study_id}/cards/export.tsv`【保留】，响应必须为真实附件。

### 复习

- `GET /api/review/queue?study_id=`【保留】。
- `POST /api/cards/{card_id}/rate`【保留】。
- `GET /api/review/params`【保留】：前端必须读取实际参数，不只看 settings 中的 `null`。

### 掌握与进度

`GET /api/studies/{study_id}/mastery`【扩展】：

```json
{
  "percent": 32.0,
  "progress_reason": null,
  "master_done": 3,
  "master_total": 9,
  "read_done": 7,
  "chapter_total": 12,
  "kps": [],
  "chapters": [
    {
      "kp_id": 20,
      "name": "第 4 章 上下文与记忆",
      "intensity": "master",
      "leaf_total": 24,
      "leaf_passed": 18,
      "risk_blocked_leaves": 2,
      "high_risk_cards": 2,
      "suspended_cards": 1,
      "done": false
    }
  ],
  "outline_events": []
}
```

`chapters[].leaf_passed` 与全书分子都使用“有效通过”口径：系统状态为 `passed` 且该叶子无高风险卡。`risk_blocked_leaves` 用于解释仅因风险造成的回退。

旧项目：`percent/master_done/master_total/read_done/chapter_total=null`、`progress_reason='legacy_project'`，`kps` 仍返回，保证旧档案可用。

保留：

- `GET /api/studies/{study_id}/report.md`
- `GET /api/export`

## 7. 设置与用量

- `GET /api/settings`、`PUT /api/settings`【保留】；
- `GET /api/usage?from=&to=`【保留并按场景扩展 `outline`】；
- 响应密钥字段永远只返回掩码或是否已配置，不返回明文；
- 全量导出、错误日志与目录事件均不得包含密钥。
