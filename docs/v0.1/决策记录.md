# V0.1 决策记录

> 日期：2026-11-20｜本文只记录产品边界与关键取舍；实现细节分别归 product/ 与 technical/。

| # | 决策 | 结论 | 原因与影响 |
|---|---|---|---|
| 1 | 版本计数 | 当前版本为 **V0.1**，从头计数 | 前身实验已按 #24 清零，不再占用版本号；其失败教训浓缩于[注意事项](注意事项.md)，完整证据仅存 git 历史。 |
| 2 | 当前版本 | V0.1 为单机自用验证版 | 仍处产品验证期，不用“已交付版本”掩盖方向与真实使用问题。 |
| 3 | 文档边界 | V0.1 分为 `product/` 与 `technical/` | 产品讨论用户、逻辑、页面与验收；技术讨论模型、流程、接口和验证。两侧仅用需求 ID 对齐，避免相互替代。 |
| 4 | 外层总纲 | 删除产品总纲与技术总纲 | 产品尚未成型，过早维护两层总纲造成同步与冲突；有价值内容先归 V0.1，成型后再提炼。 |
| 5 | 产品主线 | **学透一本书** | 书自带结构与顺序，掌握结果可量化；差异化是完整学习闭环，不是阅读器或聊天机器人。 |
| 6 | 项目与资料 | 一个项目一本书、一个主文件，格式为 EPUB/TXT/PDF/MD | 降低导入与理解成本；本版不做补充资料、粘贴文本、网页或 GitHub 导入。 |
| 7 | 结构来源 | 原书目录与标题优先，结构识别零 LLM | 避免把 AI 生成当作学习入口；未配置 AI 也能看到已识别结构。 |
| 8 | AI 目录规划 | 导入后自动运行一次，只看标题、层级与篇幅（2026-11-20 由 #25 修订升级） | AI 用于排除、拆分、合并和组织学习区域，不自动推断依赖；摘要不可用时仍以此为准。 |
| 9 | 规划失败 | 未配置、失败或超时均跳过并保留原树 | 目录可编辑与置信度明示是信任基础；AI 不能成为阻塞点。 |
| 10 | 知识点粒度 | 知识点是学习、计划、考练和证据单位，不是检索切片 | 反对“越细越好”；以可完成、可讲解、可出题和可追踪为准。 |
| 11 | 卡片创建 | 答错自动、对话卡壳手动标记、手建 | 卡片必须对应真实学习缺口；不做学完自动批量制卡。 |
| 12 | 强度与方案 | 章级略读/读透/学透是硬约束；学习方案是软偏好 | 强度决定是否考练与完成判定，方案只调整讲解和考练密度。 |
| 13 | 学透口径 | 证据驱动、分母透明、可回退 | 不用阅读时长或自评冒充掌握；高风险与统计范围变化必须可见。 |
| 14 | 核心 AI 组织 | 拆 `outline_planner / tutor / quiz` 三个 skill | 各自拥有输入输出契约、prompt 与 golden cases，可独立迭代；不做通用技能平台。 |
| 15 | 分享与社区 | 全部延后 | 当前先证明自导入闭环；只保存简单书包格式候选，不引入账号、社区或版本合并。 |
| 16 | 技术验证口径 | 明确区分【现状】【目标】【待验证】 | PDF 页码对齐、EPUB 与 TXT 稳定性未经完整样书验证，不能写成已解决。 |
| 17 | 工程质量 | 验收同时包含正向结果与反例 | 导出必须真下载、筛选必须真有效、编辑不得丢证据；mock 测试不代替真实界面走查。 |
| 18 | 范围收缩 | 只做最薄闭环：导入 → 骨架 → 学 → 测 → 点亮 | 前身实验教训是一次铺开 40 条把"功能存在"当"闭环成立"；计划、复习、卡片、档案、督促、导出等移入 `后续候选/`，原 B3～B8、B10 大部不再约束本版。 |
| 19 | 点亮语义 | 一次通过即点亮，永久保留 | 点亮 = 当前通过证据，不承诺长期记忆；复习体系接入后再升级口径；全站必须可见此说明。 |
| 20 | 解锁规则 | 全部学习单元开放，无解锁门槛（2026-11-20 由 #27 修订措辞：开放对象是学习单元，不含容器节点） | 尊重自学者跳读自由；树是状态图不是关卡；门槛类玩法后续评估，不进本版。 |
| 21 | AI 目录规划 | 保留导入后自动一次 | 只动结构（排除 / 拆分 / 合并），失败保留原树；拆分合并移入后续候选（此句仅指**用户手动**拆分合并）。现行用户手动编辑完整清单见数据模型 §6：重命名、排除/恢复、解散部分分组、恢复原目录（2026-11-20 修订）。 |
| 22 | 技术文档 | 标记待修订，随实现更新 | 产品先行收缩，避免产品技术双重返工；见 technical/ 各文档头部标记。 |
| 23 | 技能树形态 | 章节星盘 + 章内路径为默认视图；工作树承担搜索 / 排除 / 重命名等操作；点亮全套仪式 | 游戏感只服务进度仪式与导航，操作职责不向游戏感妥协；动效一次性（粒子 → 流光 → 金实心，章满戴冠），音效默认关；见 原型设计 §4。 |
| 24 | 旧实现处置 | **清零重写**：删除 backend / frontend 与部署脚本；放弃旧项目数据兼容（B1-04 移除） | 用户决策：思路归一的优先级高于重建成本；旧代码与旧数据仅存 git 历史。重写时必须重新防范真机踩过的坑：变量遮蔽、用量静默失败、vec 脏稳态（见 [注意事项](注意事项.md)）；真机冒烟仍是必须一关。 |
| 25 | 拟大纲与四问法 | AI 目录规划升级为**拟大纲**：输入加章节内容摘要，产出全书总述 + 跨章部分层 + 排除/拆分/合并；四问（整体/细节/辨析/应用）沉入讲解与测验 prompt，不新增 UI | 依据《如何阅读一本书》分析阅读：骨架按书的逻辑组织而非机械照抄章节；章锚点保留、章顺序不变，引用与证据不漂移；目录已贴合书逻辑时微调或不调，兼顾技术书与论说书；摘要不可用退回 #8 原行为，全书正文逐字不进单次上下文。 |
| 26 | 会话三框与节点笔记 | 学习会话 = 左原文 / 中陪学 / 右笔记：两侧定宽可折叠、陪学常驻不可折叠，折叠按书记忆；新增节点级单篇 Markdown 笔记（B3-05，P1） | 做笔记是主动阅读核心动作（艾德勒结构/概念笔记 + 生成效应），笔记栏与拟大纲呼应：位置骨架自动、内容手写；引用点击自动展开原文框，折叠不破坏回跳；最薄护栏：不做划线、多条、富文本、搜索与导出，笔记不参与点亮口径。 |
| 27 | 学习单位口径 | **仅有效学习单元可学习、测验、点亮**：无子节点（结构叶，与子节点是否被排除无关）∧ 自身及祖先未排除 ∧ refs≥1；父节点、部分层与有子节点的章是容器，只显示聚合进度，不进分母、无学习中态、无学习入口；无子节点的章自身是学习单元 | 关闭整体评审 P0-01：此前"任意节点可学习"、分母只统计叶子、原型给父节点显示学习中三者矛盾；结构叶口径与既有分母公式最接近，排除全部子节点不会让父节点意外进入分母；全站（树、会话、书架、星盘、API）使用同一分母。 |
| 28 | 测验计分与通过线 | 正式测验 = 3–5 道**客观计分题**（单选/判断，二元等权）+ 至多 1 道**不计分简答练习题**；通过线为 service 固定映射 {3题:对2, 4题:对3, 5题:对4}，生成时落库、判分只比对；简答练习提交后给评语但不进成绩；三种学习方法与历次测验通过线一致 | 关闭 P0-04：简答题无判分规则会使点亮可信度依赖 LLM 判分；客观题二元等权 + 固定映射最易复验；保留简答练习维持"先答再看"的生成效应价值，但绝不参与点亮。 |
| 29 | 学习证据保护窄规则 | **学习证据** = 节点子树存在任一：session / message / quiz / note / lighted_at（不能只看消息数）；拟大纲应用（自动或手动 replan）逐条在写事务内复查，split/merge 绝不作用于有证据子树，其余操作遇证据或 updated_at 冲突跳过并记 planning_conflict_skipped 事件；恢复原目录有任何证据 422、规划运行中 409；重解析仅限失败重试（暂存数据 + 完整成功后原子替换），有证据的重解析 409；structure_built 快照保存稳定节点 ID、层级、章锚点与 refs 映射 | 关闭 P0-03：V0.1 不做学习数据通用迁移，用"禁止破坏性操作"替代复杂的拆分继承与结构版本系统；对评审建议的一处偏离：手动 replan 不采用"有证据一律 409"，而是复用自动规划的逐条复查机制，保护等价且不损失 exclude/group/organize 的后续改进能力。 |
| 30 | 测验作答与判分持久化 | 不新增表：`quizzes` 增加 `submitted_answers_json`（用户作答）与 `grading_results_json`（逐题正误、评语、返回用 refs）；`knowledge_points.lighted_by_quiz_id` 显式记录首次点亮证据，与"最近一次测验"分开 | 关闭 P0-05：此前作答与逐题判分无落库位置，刷新即丢，B4-04 回看与 B5-01 下钻无法实现；标准答案仍只存服务端，未提交测验任何响应不含答案面。 |
| 31 | 删除无验收价值交互 | 从 V0.1 删除：书架"归档/恢复"、错题"再问一个变式"、设置页全局"删除数据"（保留清除配置与删除单本书） | 关闭 P2-03：三者均无 22 条需求背书、无 API 契约（tutor skill 还明确"不出题"）；砍掉比补契约更符合范围克制，需要时随后续版本补需求再实现。 |
| 32 | PDF 解析选型 | V0.1 落地用 **pypdf**（书签 + 按页正文），Docling 降为升级候选（2026-11-21 重建时决定） | pypdf 零模型依赖、离线可测、确定性，满足阶段 A/B 对"结构识别零 LLM、测试不下载模型"的纪律；Docling 首次运行需下载布局模型且依赖体积大，与自动化测试不触网的要求冲突。§4.3 spike 若证明 pypdf 对真实样书（扫描件、复杂版式）提取质量不足，再引入 Docling 并更新 §4.2。 |
| 33 | 打包分发 | V0.1 增加 Windows **免安装文件夹**打包：PyInstaller onedir，双击 exe 即用，控制台窗口可见，数据存 exe 旁 `data/`（便携，删文件夹=卸载）（2026-11-22 决定） | 依赖已极轻（#32 pypdf、无 ML 模型）使打包可行，用户机零依赖；单文件 exe 否决：每次启动解包慢且杀软误报高；保留控制台是刻意的——日志可见、关窗即退出是 V0.1 唯一停止手段，不做托盘。见技术方案 §14。 |
