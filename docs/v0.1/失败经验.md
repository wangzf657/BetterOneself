# V0.1 失败经验

> 归档日期：2026-11-20。本文记录失败证据和可复用经验，不承担现行需求或技术规范。

## 1. 结论：功能全绿，不等于产品成立

当时验收记录显示：本期 40 条需求全部标记完成，后端 62 个测试和 6 条 E2E 通过。但真实使用同时暴露两类根本问题：

1. **学习入口的成本与质量失控**：全书交给 LLM 拆解，一本 313 页的书产生 855 个切片，全文拆解约 70 万 token、约 2 小时；最终得到 1132 个知识点，其中 946 个只有一条来源引用。入口慢、贵，而且知识点过碎。
2. **界面可用性没有被验收覆盖**：导出按钮被前端阻止默认行为，部分引用跳到写死的 `/studies/0/`，卡片筛选只列顶层节点且参数不受后端支持，计划只能改期不能增删，掌握档案把树渲染成平表。

所以失败不是“功能不够多”，而是**把功能存在误当成学习闭环成立**。

## 2. 产品侧根因

### 2.1 先列功能，后想学习过程

需求覆盖导入、拆解、计划、会话、复习、督促和档案，却没有先把几个关键问题讲透：

- 一个知识点为什么存在，它和检索切片有什么区别？
- 用户导入后第一屏应该看到什么，下一步为什么显而易见？
- 学到什么程度才算“学会”，进度是否可以回退？
- 卡片应在什么学习缺口出现时创建？

结果是每个模块都有页面，模块之间却缺乏一致的产品语义。

### 2.2 把“拆解得更细”误当成“更适合学习”

知识点是学习、计划、测验、卡片和掌握证据的调度单位，不是全文索引的另一种叫法。过碎会造成：

- 计划里出现大量几分钟的小任务；
- 每个点只有一次很窄的上下文，讲解和出题反而缺少完整语义；
- 测验和复习数量膨胀，用户被考练淹没；
- 全书掌握百分比看起来精细，实际不可信。

V0.2 必须同时反对两种极端：按章粗切导致上下文过大，按切片细拆导致学习单位失去意义。

### 2.3 让 AI 生成成为导入的入场券

书通常自带目录和章节顺序，但 V0.1 没有优先利用这些结构，而是让 LLM 从全文重新发现结构。由此把“内容理解增强”错误地放在“用户能否开始学习”的关键路径上。

**教训：先给用户可信、可编辑的结构，再让 AI 改善结构；AI 不可用时，基础学习链路仍应存在。**

### 2.4 只写正向验收，没有写反例

“可见、可点击、有提示”不能证明交互正确。V0.1 的导出和筛选缺陷说明，验收必须检查真实结果和禁止行为，例如：

- 点击导出后浏览器确实下载文件，而不只是出现提示；
- 来源回跳确实保留当前书，而不是只验证路由存在；
- 目录规划失败时保留结构树，而不是留下空白或持续转圈；
- 改学习强度不得伪造掌握证据，也不得静默抬高学透百分比。

### 2.5 产品文档被实现细节主导

旧需求里混入字段、端点、库配置和算法阈值，产品决策与技术方案互相替代：改界面像是改 API，讨论学习逻辑又很快变成讨论表结构。最终两边都难以独立评审。

**教训：产品文档回答“为谁、解决什么、如何操作、怎样算完成”；技术文档回答“用什么结构、流程和接口实现”。两侧只用需求 ID 对齐。**

## 3. 技术侧根因

### 3.1 切片层级丢失，结构信号被浪费

旧切片器只把较浅标题写入层级路径，更深标题留在正文里；PDF 解析也没有优先利用书签页码。后续只能依赖标题模糊匹配或全文 LLM 拆解，既不稳定又昂贵。

### 3.2 检索与知识点粒度互相拖累

旧讲解检索先取知识点静态引用，不足 6 条再用向量补足。知识点太碎时，静态引用只有一条；太粗时，引用超过上限，后续正文又进不了上下文。说明知识点粒度不是展示偏好，而会直接影响讲解和测验质量。

### 3.3 E2E 验证了路径，没有验证用户结果

旧 E2E 能证明主链路没有断，却没有覆盖真实下载、筛选结果、正确项目上下文等关键结果。测试分层本身没有错，错在把“主链路绿”扩张成“所有页面都可用”。

### 3.4 未验证的技术推断被写成定稿

PDF 书签与正文页码对齐、EPUB 目录解析、不同中文标题规则等，在真实样书验证前不能承诺“稳定支持”。技术文档必须区分【现状】【目标】【待验证】，不能用配置项存在代替链路验证。

## 4. 仍然成立、可带入 V0.2 的经验

以下是本次失败中保留下来的资产，不代表旧实现无需修改：

1. **闭环方向仍值得验证**：导入、计划、学习、考练、复习和督促缺一不可。
2. **结构化学习流优先**：对话应附着在任务、知识点和卡片上，不做无上下文聊天机器人。
3. **掌握证据优先**：测验与复习证据决定掌握状态；阅读时长、任务勾选和自评不能冒充学会。
4. **来源引用是信任基础**：讲解、题目、错题和卡片都应能回到原书位置。
5. **复习复用成熟算法**：继续使用 py-fsrs，不自研间隔重复算法。
6. **卡片来自真实学习缺口**：答错自动成卡、对话卡壳手动标记、用户手建；不在学完时批量制造卡片。
7. **计划须经确认且可调整**：逾期重排而非无限堆积，所有调整可见。
8. **单机自用与数据开放**：无账号体系，密钥加密落库，数据可导出。
9. **工程纪律保留**：核心算法单测、LLM 测试全部 mock、E2E 验证真实闭环、最小改动、文档先于代码。

## 5. 不再继承的内容

- 旧 40 条需求及 M 系列 ID，不作为 V0.2 的完成定义；
- “40 条全部完成”的验收结论，不作为产品质量证明；
- 多资料项目、网页/GitHub/粘贴文本导入，不恢复为当前范围；
- 全文 LLM 拆解、LLM 依赖推断和手动章级全文增强；
- 旧版本路线图、页面层级、接口和字段，未经 V0.2 重新评审不得直接照搬；
- 任何“某格式一定能稳定出树”的未验证承诺。

## 6. V0.2 的止损线

出现以下任一情况，停止加功能，先回到产品逻辑或关键验证：

1. 没有 LLM 就无法看到任何已识别出的目录结构；
2. 知识点数量继续随切片数线性膨胀，而不是形成可学习的单元；
3. 用户无法从首页明确知道“现在该做什么、为什么做、做完证明什么”；
4. 学透百分比上升但无法追溯到证据，或通过缩小范围被静默美化；
5. 测试通过但关键界面仍不能完成真实导出、筛选、编辑和回跳。
