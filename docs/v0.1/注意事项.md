# 注意事项——前身实验的教训

> 前身实验（40 条需求，实现已按[决策记录](决策记录.md) #24 清零，仅存 git 历史）曾功能全绿、测试全过，真实使用却不可用。本页是其失败教训的浓缩，重建时逐条对照；它是提醒清单，不是现行需求。

## 产品纪律

1. **功能存在 ≠ 闭环成立**：前身 40 条需求全部标记完成、后端 62 测试与 6 条 E2E 通过，仍不构成"学完一本书"的产品成立。完成定义 = 验收逐条通过 + 测试绿 + 真实界面走查。
2. **先结构，后智能**：书自带目录与章节顺序，结构识别零 LLM；AI（拟大纲）失败或未配置时，基础学习链路必须完整。前身把全文 LLM 拆解做成了学习入场券：313 页 → 855 切片、约 70 万 token、约 2 小时、1132 个知识点（946 个仅一条引用）——入口慢、贵、碎。
3. **验收必须含反例**："可见、可点击、有提示"证明不了交互正确。前身实际断点：导出被前端拦截默认行为、引用跳到写死的 `/studies/0/`、卡片筛选参数后端不支持、掌握档案把树渲染成平表。导出要真下载、回跳要落在当前书、规划失败要保树。
4. **产品与技术文档分离**：产品文档被字段、端点、库配置主导时，两边都无法独立评审。产品回答"为谁、解决什么、怎样算完成"，技术回答"用什么结构实现"，两侧只用需求 ID 对齐。

## 粒度与检索

5. **知识点是学习单位，不是检索切片**：同时反对两个极端——按章粗切导致上下文过大，按片细拆导致学习单位失去意义（计划充满几分钟小任务、讲解缺完整语义、考练淹没用户、百分比看似精细实则不可信）。
6. **切片保留完整标题层级**（h1–h6 全部写入路径），PDF 优先利用书签页码；否则只能靠标题模糊匹配或全文 LLM 拆解，既不稳定又昂贵。

## 工程纪律

7. **【现状】【目标】【待验证】不得混写**：PDF 书签与页码对齐、EPUB 目录解析、中文标题规则等，未经真实样书验证不得写成"稳定支持"；不能用配置项存在代替链路验证。
8. **E2E 验证用户结果，不是路径**：主链路绿 ≠ 所有页面可用；E2E 必须覆盖真实下载、筛选结果、正确的项目上下文。
9. **真机冒烟是必须一关**：LLM 测试全部 mock，stub 全绿不代表真实链路通。真机踩过的坑：局部变量遮蔽断掉链路、用量失败被静默吞掉、向量库进入脏稳态。每轮重建收尾必须接真实 key 冒烟主链路。

## 仍然成立的方向

闭环本身值得验证；结构化学习流优先（对话附着在节点上，不做无上下文聊天）；掌握只认测验与复习证据；来源引用是信任基础；FSRS 不自研；卡片来自真实学习缺口；单机自用、密钥加密落库。
