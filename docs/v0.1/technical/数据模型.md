## 1. 建库策略

- 空库起步，Alembic 单个 init revision 建全部表与 sqlite-vec 虚表；
- 单机自用：schema 演进允许破坏性重建 + 手动重导入，不写增量兼容迁移；
- 知识点是数据枢纽：会话、测验、笔记、点亮全部通过 `kp_id` 关联，检索切片（chunk）不是学习单位。

| planning_note | TEXT NULL | AI 调整理由 |

| lighted_at | TIMESTAMP NULL | **点亮时间：非空即已点亮；一次写入永久保留**（B4-03） |
| lighted_by_quiz_id | FK→quizzes NULL | 首次通过证据：与 lighted_at 同事务写入，仅首次；下钻与 B4-04 回看用，与"最近一次测验"分开（决策 #30） |
| created_at / updated_at | TIMESTAMP | updated_at 仅用户编辑触发（AI 写 chapter_summary / planning_note 不触发），是规划冲突比对依据 |

**学习单元 / 容器（决策 #27）**：无子节点的节点（结构叶，与子节点是否被排除无关）是学习单元候选；父节点、部分层与有子节点的章是容器，不可学习、测验与点亮，只显示聚合进度。无子节点的章自身是学习单元。

节点三态（B2-06）全部派生，不落字段，**仅学习单元有三态**：

- **已点亮**：`lighted_at IS NOT NULL`；
- **学习中**：未点亮 ∧ 该节点存在任一 message 或 quiz 记录（quiz 也是学习活动，不能只看会话存在）；
- **未学**：其余。全部学习单元开放，无解锁门槛（决策 #20、#27）。

### 3.6 knowledge_refs

`id` PK、`kp_id` FK CASCADE、`chunk_id` FK→source_chunks RESTRICT、`sort_order`，**UNIQUE(kp_id, chunk_id)**（同一节点对同一切片不重复挂载，P1-07）。引用挂载提交是拟大纲应用的前置条件；**有效学习单元（结构叶 ∧ 未排除 ∧ refs≥1）才能开始学习与测验**（决策 #27）。

### 3.8 sessions

`id` PK、`study_id` FK CASCADE、`kp_id` FK CASCADE **UNIQUE**（节点 1:1 持久会话，取或建幂等）、`scheme`（会话内可切换，只影响本会话）、`created_at / updated_at`。

### 3.9 messages

| 列 | 类型 | 说明 |
|---|---|---|
| id | PK | |
| session_id | FK CASCADE | |
| role | TEXT NOT NULL | user / assistant |
| content | TEXT NOT NULL | Markdown |
| refs_json | TEXT NULL | 引用列表：chunk_id + 定位 + 被引文本（角标点击回跳） |
| stopped | BOOLEAN NOT NULL DEFAULT 0 | 生成中断标记：用户停止或断连时保存已生成部分并置真（技术方案 §7.2 持久化语义；仅 assistant 消息有意义） |
| created_at | TIMESTAMP | |

测验卡不是消息：`quizzes` 挂 `session_id`，会话详情把 messages 与 quizzes 按 `created_at` 合并渲染对话流，避免双写。开场讲解是首条 assistant 消息。

### 3.10 quizzes

| 列 | 类型 | 说明 |
|---|---|---|
| id | PK | |
| study_id / kp_id / session_id | FK CASCADE | 证据链：点亮下钻到首次通过 quiz（B5-01）；service 校验三者同属一个 study（P1-07） |
| questions_json | TEXT NOT NULL | 下发面：题型（choice 单选 / judge 判断 / short 简答练习）、计分/练习标记、题干、选项；**不含答案**（B4-01） |
| answers_json | TEXT NOT NULL | 服务端持有：答案、解析、来源 refs；**answered_at 为空的测验任何响应不包含**（未提交测验公开面） |
| pass_line | INTEGER NOT NULL | 通过线 = service 固定映射 {3题:2, 4题:3, 5题:4} 按计分题数落库，不得中途变（B4-02、决策 #28） |
| submitted_answers_json | TEXT NULL | 用户实际作答，提交时一次写入（决策 #30） |
| grading_results_json | TEXT NULL | 逐题判分：正误、正确答案、解析、简答评语、返回用 refs（决策 #30） |
| correct_count | INTEGER NULL | 判分后写：**仅计客观计分题**，简答练习不计 |
| passed | BOOLEAN NULL | 判分后写：correct_count ≥ pass_line 的代码判定 |
| created_at / answered_at | TIMESTAMP | answered_at NULL 即未提交 |

**进行中唯一**：`UNIQUE INDEX ON quizzes(kp_id) WHERE answered_at IS NULL`（partial index）——同一节点同时最多一组进行中测验；生成接口幂等返回进行中的测验，提交以条件更新 `WHERE answered_at IS NULL` 原子认领，首个请求判分，重复提交幂等读回已判分结果（P1-03）。

去重（B4-02 反例）：生成时查询该 kp 全部历史 `questions_json` 的题干列表传入 quiz skill 排除；生成后做题干完全重复检查，重复则重试一次；**第二次仍完全重复则本次生成明确失败**（状态与原因可读、可重试），不下发旧题。

### 3.11 notes

`id` PK、`study_id` FK CASCADE、`kp_id` FK CASCADE **UNIQUE**、`content_md` TEXT（64KB 上限）、`created_at / updated_at`。upsert 幂等；不参与点亮与任何统计（决策 #26）；节点顶部位置行由前端从树数据渲染，不存正文。

### 3.12 settings

`key` TEXT PK、`value` TEXT、`updated_at`。键：`llm.base_url / llm.model / llm.api_key`（Fernet 加密）、`embed.base_url / embed.model / embed.api_key`（加密）。点亮反馈偏好（音效/动效开关）是前端偏好，localStorage，不落库。

### 3.13 usage_days

`id` PK、`date`（YYYY-MM-DD）、`scene`（outline / tutor / quiz / embed）、`requests / prompt_tokens / completion_tokens`，UNIQUE(date, scene)。写入失败不得静默吞掉（注意事项 #9）。

## 4. 点亮进度口径（B5-01）

```
有效学习单元（分母） = 结构叶（无子节点，与子节点是否被排除无关；决策 #27）
                    ∧ 自身及全部祖先未排除
                    ∧ knowledge_refs ≥ 1      # 无引用节点无法学习与测验，不进分母
progress = count(lighted_at IS NOT NULL ∧ 有效学习单元) / count(有效学习单元)
分母 = 0 → progress = null（前端显示「—（无有效学习单元）」，不显示 0%）
```

- 容器节点（父节点、部分层、有子节点的章）永不进分母——部分层 `origin='ai_group'` 必有子节点，结构叶条件已天然排除，不再单列；
- 排除全部子节点**不会**让父节点变成结构叶、不会进入分母；无子节点的章是学习单元，进入分母；
- 无引用节点待拟大纲拆分挂引用后自然进入分母，不需要人工干预；
- 每个进度数字可下钻：已点亮学习单元 → `lighted_by_quiz_id` 指向的首次通过 quiz（题面、本人作答、逐题判分、得分、通过线、时间）；
- **分母变化必须透明**：排除、恢复、解散分组、恢复原目录、split/merge 应用写 `outline_events`，detail_json 带 leaves / lighted / percent 前后值（B5-01 反例：不得静默美化）；重命名不改变分母、不写分母事件；
- 进度实时计算，不落缓存列。

## 5. 点亮语义（B4-03，决策 #19/28/30）

- quiz 判分 `passed=true` 且节点未点亮 → 同事务写 `kp.lighted_at` 与 `lighted_by_quiz_id`（首次通过证据；已点亮不重复写、不刷新时间与证据）；
- 已点亮后重考：本次 quiz 结果照常落库，`lighted_at` / `lighted_by_quiz_id` 不受影响，反馈显示"原有点亮保留"；
- 计分口径：`correct_count` 只统计客观计分题（二元等权），简答练习只给评语不计分；`passed` 是 `correct_count ≥ pass_line` 的代码判定，通过线为固定映射（§3.10），判分只比对不重算；
- 永久保留：任何流程不得清空 `lighted_at`；唯一级联清除是删除整本书；
- 重命名不改点亮；排除已点亮节点：证据原样保留、只出分母，恢复后回分母；
- 打开会话、阅读、自由提问、未通过测验都不写 `lighted_at`——点亮只有测验通过一条路径；
- 全站口径文案统一：「点亮 = 节点测验当前通过，不含长期记忆验证」。

## 6. 结构编辑不变量（B2-05，决策 #6/21/27/29）

**学习证据 = 节点子树存在任一：session / message / quiz / note / `lighted_at`**（不能只看消息数——用户可不生成讲解直接测验或写笔记）。

用户手动编辑仅四种，其余结构操作是 AI 拟大纲产物（决策 #21，现行清单取代决策 #21 旧句）：

1. **重命名**：只改 name，写 kp_renamed 事件；原名保留在事件 detail_json；点亮、会话与分母不受影响；
2. **排除/恢复**：只改 `excluded / exclusion_reason` + 写事件（带分母前后值）；不动 sessions / messages / quizzes / notes / lighted_at；已排除节点禁止新会话、讲解与正式测验（422），既有数据只读可回看；恢复不产生新证据；
3. **解散部分分组**：删 group 节点，子章 parent_id 上移一级；学习数据零变动；
4. **恢复原目录**：以 `structure_built` 快照重建（快照含稳定节点 ID、层级、章锚点与 refs 映射）。前置条件：全书**无任何学习证据**且 `outline_status ≠ planning`（planning 中拒绝，防 stale 写入）；不满足则 422 列出证据所在节点，提示改用逐个排除。快照无法可靠保留的手动编辑（重命名、排除）在恢复时一并撤销，响应与弹窗明示撤销清单，不静默覆盖。`shortcut: 学习中途需要精细回滚时升级为按调整逆放, 出现真实回滚需求再做`；
5. AI 规划应用（自动或手动 replan，决策 #29）：逐条在写事务内复查——目标或后代有学习证据时 split / merge 跳过（破坏性），exclude / organize / group 不删除节点身份、不因证据跳过；`updated_at` 用户编辑冲突时全部操作跳过；被跳过的写 `planning_conflict_skipped` 事件。

## 7. 删除与级联

- 删除整本书：CASCADE 清除全部关联（前端先弹影响清单：会话数、测验数、点亮数）；stored_path 文件随库删除一并清理，删除失败不静默；
- 删除单节点：不提供——排除取代删除，保证证据可恢复（B2-05 反例）；
- 重解析（决策 #29）：仅失败重试与无目录重识别两个入口；新结果先写暂存数据，**完整成功后一个事务原子替换**旧 chunks / vec_chunks / refs，失败旧数据原样保留；全书存在任何学习证据时 409 拒绝（历史消息、测验、笔记持有的 chunk 引用不得被删除，本版不做 chunk 版本化）；
- 归档：V0.1 不提供（决策 #31）。

## 8. 外键与约束行为（P1-07，可执行级别）

- **每连接启用 `PRAGMA foreign_keys=ON`**（SQLAlchemy `connect` 事件钩子），以真实 SQLite 集成测试验证，不依赖模型声明；
- 删除行为全表明确：业务主链 `study → source/chunks/kp/session/quiz/note` 全 CASCADE（删书即全删）；`knowledge_refs.chunk_id` 与 `lighted_by_quiz_id` 用 RESTRICT——引用与证据不得悬空；`outline_events.kp_id` 用 SET NULL 并在 detail_json 保存名称快照（节点被 merge 删除后事件仍可读）；
- 约束：`knowledge_refs UNIQUE(kp_id, chunk_id)`；`sessions UNIQUE(kp_id)`；`notes UNIQUE(kp_id)`；`quizzes partial UNIQUE(kp_id) WHERE answered_at IS NULL`；`usage_days UNIQUE(date, scene)`；
- 跨表归属由 service 校验：session / quiz / note / ref 操作前断言同属一个 study，防止跨书挂接（B3-02 反例）。
