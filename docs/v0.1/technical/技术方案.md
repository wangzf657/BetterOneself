## 1. 技术目标与约束

1. 只做最薄闭环「导入 → 骨架 → 学 → 测 → 点亮」；计划、复习、卡片、掌握档案、督促、导出在 [后续候选](../后续候选/)，不在本文。
2. 原书结构识别与 AI 拟大纲解耦：前者零 LLM，后者失败可跳过、原树保留（B2-01、B2-03、B5-03）。
3. 骨架只有结构信息，讲解与测验进入学习时按节点生成，导入阶段不预生成任何学习内容（B2-04）。
4. 点亮只认测验通过证据：一次通过即点亮、永久保留；阅读、提问、打开会话不产生点亮（B4-03）。
5. 入口必须快：吸取前身「全文 LLM 拆解做学习入场券」的教训（[注意事项](../注意事项.md) #2），有可靠目录的书导入即可看树。
6. 核心 AI 能力拆成三个可独立测试的小 skill，不建设通用编排平台（决策 #14）。
7. 所有 LLM 自动化测试 mock；真实样书只用于人工冒烟与质量评审；真机冒烟是发版前必过的一关（注意事项 #9）。

## 2. 技术栈

| 层 | 选型 | 本版使用方式 |
|---|---|---|

| EPUB | 标准库 `zipfile` + BeautifulSoup/lxml | 读 OPF、nav/NCX 与正文，不新增 ebooklib |
| AI | OpenAI 兼容 SDK | 拟大纲（含章节摘要）、讲解、出题与判分；无 LangGraph——V0.1 会话是无分支顺序流，SDK 直调即可 |

## 4. 导入与目录识别

### 4.1 三阶段解耦（B1-01～03、B2-01～04）

**阶段 A：结构草稿**

- 读取目录、标题与顺序，生成初始知识树，标记识别依据与置信度；
- 不调用 LLM，不等待正文或 embedding，结构树立即可浏览。

**阶段 B：正文与引用**

- 解析正文、规范化、切片（切片是检索单位，不直接创建知识点）；
- 将切片挂到目录节点（`knowledge_refs`），计算跨格式通用篇幅 `char_count`；
- 引用挂载事务提交后自动触发一次 AI 拟大纲（阶段 C 的前置条件）；
- embedding 后台并行，不阻塞任何阶段。

**阶段 C：拟大纲应用**

- 见 §5；必须等引用挂载完成后才应用结构调整，避免把引用尚未生成的节点改成无来源学习单元。

### 4.2 格式策略

| 格式 | 结构信号优先级 | 正文与定位 | 置信度处理 |
|---|---|---|---|
| PDF | 书签 → 编号标题 → 字号/字重 | pypdf 按页提取正文；优先按书签页码区间挂切片 | 书签高；编号中；样式低 |
| EPUB | nav → NCX → 正文标题 | OPF spine 顺序读取 XHTML，保留 `href + 锚点` | nav/NCX 高；正文标题中 |
| Markdown | `#`–`######` 标题 | 按完整标题路径切分，记录行号 | 明确标题高；跳级需提示 |
| TXT | Markdown 式标题 → `第 N 章` / 数字编号 → 无结构 | 按识别标题切分并记录行号 | 编号中；无结构不假装有目录 |

无结构 TXT 或识别失败文档：保留正文、显示无目录空态（P03-F），本期不支持学习；**不自动全文 LLM 拆解**。

### 4.3 PDF 待验证

【目标】先读书签与页码形成结构草稿；Docling 按页导出正文，书签页码区间确定目录叶子；页内按标题与段落切片并保留完整层级；书签与正文无法对齐的区间标低置信度，不模糊匹配后假装成功。

【待验证，不得提前写成已完成】

- 313 页样书从书签 → 按页导出 → 页码区间挂引用的完整链路；
- 第一章 p15–38 的引用覆盖率、错挂率与耗时；
- 无书签 PDF、扫描 PDF、中文编号 PDF 的降级表现；
- EPUB nav/NCX 与 TXT 编码、标题规则的真实样本覆盖。

### 4.4 切片规则

- 切片按标题层级组织（h1–h6 完整路径，前身切片器丢 h3–h6 是已确认的反例），**不按整章切**：整章切片语义混杂会稀释向量检索精度，引用回跳也只能定位到章、不满足「定位到对应位置并高亮」；「章-节」是学习单元（知识点）的粒度，不是切片粒度；
- `MAX_CHARS` 沿用前身实测值，只有真实检索抽评证明不足才调；
- `location` 保存**按格式区分的 JSON 联合类型**，引用回跳不依赖标题模糊搜索：PDF `{type:'pdf', page_start, page_end}`；TXT / Markdown `{type:'lines', line_start, line_end}`；EPUB `{type:'epub', href, anchor?}`；无可用定位时 `{type:'none', chapter_hint}`，回跳降级为显示所在章与来源文本（P03 1.4），不伪造定位。

## 5. AI 拟大纲（B2-03，决策 #25）

### 5.1 输入与输出

输入：`book_title`、`nodes`（含 `char_count` 必填——节点自身 refs 字符数；`subtree_char_count` 子树 refs 去重字符数；`page_span` 仅 PDF 可靠页码时填，其他格式 `null` 不伪造）、`chapter_summaries`（可选）、`ref_manifest`（全书 refs 的有序元数据清单：chunk_id、所属节点、书内顺序、标题路径、location、char_count；**不含正文**，供 split 划定边界）。正文逐字内容不进入输入。

输出限定五类结构操作 + 全书总述：

1. `exclude`：排除非学习单元并给理由；
2. `split`：把篇幅过大或语义过多的**结构叶**（无子节点）拆成 2–5 个学习区域，输出 `{node_id, parts: [{title, start_chunk_id, end_chunk_id}]}`，用边界 chunk ID 表示区间；
3. `merge`：合并同章、同父、相邻且均无子节点的过碎节点，输出 `{node_ids: [A, B], new_title}`；
4. `organize`：章内建立学习区域父节点，不改章锚点，产物 `origin='ai_organize'`；
5. `group`：章层之上建部分节点，仅覆盖**连续章节区间**，产物 `origin='ai_group'`；不吞并章、不改章顺序；原目录贴合书逻辑时可不出。

**split / merge 数据契约（可执行、可重放）**：

- `split` 校验：parts 2–5 段、按书内顺序排列；各段 `[start_chunk_id, end_chunk_id]` 首尾相接，**完整覆盖该节点全部 refs 且互不重叠**；区间不得跨到其他节点的 refs。任一不满足 → 该次规划整体失败保树；
- `split` 应用：同一事务内——原节点**转为容器**（保留 id 与章锚点属性，origin 不变），新建子节点 `origin='ai_split'`，refs 按区间整体迁移给子节点，原节点不再持有 refs；
- `merge` 校验：A、B 同章、同父、sort_order 相邻、均为无子节点；应用：同一事务内新建节点 `origin='ai_merge'`，refs = A、B 的 refs 按书内顺序**去重并集**，A、B 删除（仅当二者均无学习证据，证据复查见 §5.4）；
- 旧节点处置规则固定：split 保留为容器、merge 删除无证据旧节点；操作与 refs 迁移在同一事务完成，无法分配或校验失败则整项回滚保树，不留半次结果。

另附 `thesis`（一句话总述：这本书整体讲什么 + 各部分如何推进），存 `studies.outline_thesis`，不产生节点。每条操作必须引用输入节点 ID 并带一句理由。结构化输出校验失败即本次规划失败，保留原树。

### 5.2 触发与降级

- 引用挂载事务提交后自动排一次，两步执行：先逐章压缩内容摘要（每章独立一次轻调用、可并行，输入该章 refs 全文，固定四问模板：这章解决什么问题 / 核心论点 / 与前后章的关系 / 内容性质〔理论·案例·小结·附录〕），再拟大纲；摘要写入 `kp.chapter_summary`（§8 chat 复用），失败退回仅结构信息输入（决策 #8 原行为），不重试循环、不阻塞；
- 同一结构版本只自动跑一次，浏览与学习不重复触发；
- 未配置 LLM：引用就绪后直接标 `skipped`；超时、限流、校验失败标 `failed`；两者原树均保留（B5-03）；
- 用户可手动重试（`POST /outline/replan`），与自动规划走同一条生成与应用链路（含 §5.4 的逐条复查）；
- 应用结果时逐条复查（§5.4）：用户已编辑（`updated_at` 比对）或目标子树有学习证据的破坏性操作跳过，保留用户最后操作与学习数据。

### 5.3 粒度约束

prompt 只给软约束：常见学习目标 20–45 分钟；过粗过细结合标题语义判断；小结/思考题是否排除取决于内容角色，不只靠关键词正则；章不可删、不跨章合并；部分层按书的逻辑划，不设统一格数；不生成依赖边，默认学习顺序仍是目录顺序。

### 5.4 准确性保障（「准确」= 不破坏、有据、克制、可回滚）

LLM 只提结构操作建议，不生成树——准确性的地基是硬约束兜住结构、把 LLM 的自由度限制在五类操作内：

**生成**：thesis 与全部操作**单次全局调用**产出（部分分组必须看到全书，逐章调用无全局视野）；prompt 按分析阅读顺序分步——①通读标题树与摘要写 thesis → ②划部分（仅连续区间，已贴合则不分组）→ ③逐部分查章（非学习单元 → exclude，必须给理由）→ ④逐章查粒度（char_count 偏离同书分布 → split/merge）→ ⑤输出操作列表（每条带 node_id 与理由，不确定的不动）。低温度（0–0.3）；思考型模型换准确率（导入是后台任务，慢可接受）——【待验证】与标准模型的真实样书对比。

**校验（代码层，不靠 LLM 自觉；任一失败 → 整体失败保树，宁缺毋滥）**：

- 操作引用的 node_id 必须存在于输入；
- exclude 不得作用于 `is_chapter=true`；
- merge 双方相邻、同章、同父且均无子节点；split 仅章内、目标为无子节点的结构叶、产物 2–5 个且区间构成完整有序互不重叠分区（§5.1）；
- group 为连续章节区间，不吞并章、不改顺序；
- 同一节点不得出现在冲突操作中（先 exclude 又 split）；
- thesis 非空、长度合理。

**应用（逐条在写事务内复查，任一冲突只跳过该条、不失败整次）**：

1. `updated_at` 比对：用户已编辑的节点跳过该条操作（用户优先）；
2. **学习证据复查（决策 #29）**：**学习证据** = 目标节点或其后代存在任一 session / message / quiz / note / `lighted_at`；split / merge 属破坏性操作（删除或替换节点身份），命中证据即跳过；exclude / organize / group 不删除节点身份（证据按 kp_id 稳定挂靠），不因证据跳过；
3. 被跳过的操作写 `planning_conflict_skipped` 事件（原因：用户编辑 / 学习证据）；应用的每条操作落 `outline_events`（理由即 planning_note，B2-03「调整结果可辨认」）；`adjust_summary` 分别记录**实际应用数与跳过数**，不混淆计划数与应用数；
4. 恢复原目录整机回滚（前置条件见数据模型 §6）；引用就绪前不应用。

`planning` 进行期间树可编辑、refs 就绪的学习单元可正常学习——应用的写事务复查保证"规划期间产生的编辑与学习证据"不会被覆盖。

**评测**：golden 小书（结构松散的已知答案样例）做 skill 契约回归；真实样书人工抽评是发版验收（需求列表既定规则）。

### 5.5 状态机与页面状态条映射

`studies.outline_status`：`idle → structure_ready → planning → ready | skipped | failed`。

| P03 状态条 | 判定 |
|---|---|
| 结构识别中 | `parse_status ∈ {pending, parsing}` 且 `outline_status=idle` |
| 原文与引用准备中 | `outline_status=structure_ready` 且正文解析未完成；结构可编辑，不能开学习 |
| AI 规划中 | `outline_status=planning`（原目录仍可编辑） |
| 未配置 AI | `outline_status=skipped` 且原因为未配置 |
| 规划失败 | `outline_status=failed`（附原因与重试） |
| 规划完成 | `outline_status=ready`（附调整摘要：N 个部分、排除/拆分/合并计数） |
| 低置信度 | 树上存在 `confidence` 低于阈值的结构（派生展示，请用户检查标记节点） |

## 6. 三个核心 skills

```text
backend/app/skills/
  outline_planner/   skill.py + prompt.md + test_skill.py + golden/
  tutor/             同上
  quiz/              同上
```

每个 skill 只有：一个输入/输出 Pydantic 契约、一个主提示词、一组 golden cases、对统一 `llm()` 薄函数的调用。不引入注册表、热加载、YAML DSL、插件包或可视化编排。

| Skill | 职责 | 不做什么 |
|---|---|---|
| `outline_planner` | 章节摘要消费、全书总述、部分分组、排除、拆分（边界 chunk ID）、合并、章内组织 | 不输入正文逐字内容（ref manifest 仅元数据）、不建依赖图 |
| `tutor` | 开场讲解（定位 + 首段 + 理解问题）、自由问答、按学习方法调整风格 | 不改节点状态、不出题（含"变式追问"，已随 P2-03 移除） |
| `quiz` | 按节点出题（3–5 道客观计分题 + 至多 1 道简答练习）、简答练习评语 | 不判正误、不决定点亮与通过线（service 比对与判定）、不做卡片 |

**四问法沉入 prompt（决策 #25）**：tutor 开场先答「本细节在整体中的位置」；quiz 题型覆盖「细节理解与辨析」（作者论断是否成立、论据是否支持）和「应用」（给定情境怎么用）。不新增 UI。

**学习方法（B3-03）**：`scheme` 三值 `guided（带我学）/ lecture（讲给我听）/ drill（帮我过关）`，只改变 tutor 的讲解风格与 quiz 的考练密度，**不降低也不抬高通过线**。书级默认存 `studies.scheme`，会话内切换只影响当前会话。

## 7. 学习会话与测验点亮（B3、B4）

### 7.1 会话模型：学习单元 1:1 持久会话

- 会话与测验入口仅对**有效学习单元**开放（决策 #27：无子节点 ∧ 自身及祖先未排除 ∧ refs≥1）；容器节点与已排除节点创建会话 / 生成测验返回 422；已排除节点既有的会话、测验、笔记**只读可回看**，恢复后可继续，不产生新证据（B2-05）；
- 一个学习单元至多一条会话：进入学习时「取或建」（`POST /sessions {kp_id}` 幂等），消息持续追加；「继续学习」回到上次节点即回到同一条会话；
- 节点状态「学习中」为派生态：未点亮 ∧ 该节点存在任一 message 或 quiz 记录（不能只看会话存在或消息——quiz 也是学习活动）；容器节点无三态，只显示聚合进度；不落字段；
- `last_kp_id` / `last_learned_at` 由最近的 message 写入或 quiz 提交更新，与「继续学习」口径一致；
- 自由提问、阅读、离开都不改节点状态（B3-04）。

### 7.2 开场与对话（B3-01、B3-02）

- 进会话若无 assistant 消息，前端自动调 `POST /sessions/{id}/opening`：tutor 生成首条消息——① 一句话定位（本节点属于哪部分、推进全书什么、要解决什么；大纲不可用时只说后者）② 首段讲解带 `[1][2]` 引用 ③ 一个简短理解问题；失败不伪造用户消息，保留原文与重试按钮；
- **生成持久化语义（P1-04）**：同一会话串行生成（进程内每会话一把锁，双击排队不并发）；opening 原子认领——已有 assistant 消息或开场生成进行中时返回 409 / 既有结果，不产生第二条开场；`chat` 的用户消息在调用 LLM **之前**提交入库；assistant 消息在生成完成或用户停止时保存（停止保存已生成部分并标记 stopped）；客户端断连等同停止；LLM 失败不保存 assistant 消息，用户消息保留、可重试；
- **错误分界**：SSE 流建立前失败返回 HTTP 503 JSON（带 `retryable`）；流建立后失败发 SSE `error` 事件（同样带原因与可重试）；流式契约不变：`delta` / `done` / `error`；
- 每条 assistant 消息带 `chunk` 引用列表；前端点击角标 → `GET /chunks/{id}` → 原文框（收起则自动展开）滚动定位高亮。

### 7.3 测验与点亮（B4-01～04）

- `POST /sessions/{id}/quizzes` 生成一组：**3–5 道客观计分题（单选 / 判断）+ 至多 1 道简答练习题**；题干、选项、解析必须锚定本节点 refs；`coverage` 返回实际覆盖列表（各题的题型与四问维度），不是单值；
- **固定通过线（决策 #28）**：`pass_line` 由 quiz service 按计分题数查固定映射 **{3题: 对2, 4题: 对3, 5题: 对4}** 写入 quizzes，生成说明明示（如「4 道计分题，对 3 题点亮；另附 1 道练习不计分」）；LLM 输出与前端均不参与通过线判定；三种学习方法、同节点历次测验使用同一映射；
- **未提交测验公开面**：answered_at 为空的测验，任何响应只含题目面（题号、题型、计分/练习标记、题干、选项）；答案与解析（answers_json）只存服务端，提交判分后才返回（序列化面分 `QuizPublic` / `QuizAnswered`）；
- **生命周期与幂等（P1-03）**：同一节点同时最多一组进行中测验（条件唯一约束）；生成接口幂等——已有进行中的测验直接返回它，双击与断连重试不产生重复；提交原子认领（条件更新 `WHERE answered_at IS NULL`，首个请求判分）；已提交再提交幂等读回已判分结果，不重复判分；
- **判分与持久化（决策 #30）**：`POST /quizzes/{id}/answer` 整组提交后由代码立即判定——计分题二元等权（单选比对选项、判断比对布尔），**简答练习由 quiz skill 给具体评语但不计分、不影响 passed**；作答（`submitted_answers_json`）与逐题判分（`grading_results_json`：正误、正确答案、解析、评语、返回用 refs）在判分事务内一次写入 quizzes，刷新后逐题内容、作答与评语完全一致；
- **达线即点亮**：判分事务内若节点未点亮则写 `knowledge_points.lighted_at` 与 `lighted_by_quiz_id`（首次通过证据，与"最近一次测验"分开）；已点亮后重考只写本次 quiz 结果，不触碰 lighted_at，反馈显示"原有点亮保留"（B4-03）；点亮只认测验证据，永久保留；
- **未通过**：不点亮、不锁任何功能；「再考一组」须先提交或作废进行中的测验；生成新题时将该节点全部历史题干传入 quiz skill 排除，生成后做题干完全重复检查，重复则重试一次；**第二次仍完全重复则本次生成明确失败**（可读原因 + 可重试），不下发旧题、不扩大考点（B4-02 反例）；
- 历次测验与错题可回看（`GET /kps/{id}/quizzes`，含作答与逐题判分），挂在节点而非会话消息上，消息流中的测验卡只是展示层。

### 7.4 节点笔记（B3-05）

- 每节点一篇 Markdown 笔记，`GET/PUT /kps/{id}/note` upsert、自动保存；64KB 上限；保存失败由前端三态提示（保存中 / 已保存 / 失败）并保留本地草稿，服务端不做草稿托管（P1-10）；
- 笔记顶部自动带节点位置（部分 → 章 → 节点）由前端从树数据渲染，不存进笔记正文；
- 原文选段「记到笔记」由前端在光标处插入引用块：**来源文本快照 + chunk 锚点**（`> 节点 · 定位：被引文本` 呈现，锚点数据附带），点击复用统一引用回跳（`GET /chunks/{id}`），不另建一套定位；
- 笔记不参与点亮与任何统计口径（决策 #26）。

## 8. 检索与上下文

chat 与讲解的上下文按三层组装：

1. **节点静态引用保底**：先取当前节点 `knowledge_refs` 切片全量（节点 = 20–45 分钟单元，通常 5k–15k tokens 可全量）；refs 超过 `_TOP_K=6` 条时按当前问题相关性选择，不固定截掉后半章；
2. **章节摘要作书级地图**：全书各章 `chapter_summary`（拟大纲时已生成）常驻上下文，支撑跨节点与结构性提问（「这部分讲什么」「和第 2 章什么关系」）；
3. **向量补足细节**：用户问题指向其他节点细节时，在**本书**向量库检索补足相关切片，引用仍限本书。

- 打开节点只加载该节点 refs（B3-02 反例：不得加载整本书）；引用回跳用 `chunk_id` 精确定位；
- **embedding 不是核心链路单点（P1-09）**：向量状态机 `pending → running → ready`，部分成功 `degraded`，失败 `failed`（附 `embed_error`，可重试）；未配置或失败只失去第 3 层跨节点补足——当前节点讲解、测验与原文（第 1、2 层）完全可用，页面按此口径提示，不写"讲解与测验受限"；
- **上下文预算显式**：节点 refs 全量与章节摘要地图各有 token 硬上限；refs 超限按标题分段**整块取舍**（优先与当前问题相关及靠前的完整段），不做静默中部截断；
- 真实抽评前不加重排器。

## 9. 异步、事务与恢复

- FastAPI BackgroundTasks，不引入 Celery 或消息队列；
- **文件落盘不与数据库事务混写（P2-05）**：上传先写临时文件 → 事务内建 study + source + 绑定主资料并提交 → 临时文件原子 rename 为 `stored_path`；任一步失败按明确顺序清理（事务回滚则删临时文件），应用启动时清理无 source 记录对应的孤儿文件；
- 结构建树、引用挂载、拟大纲应用各自独立事务；引用挂载提交是拟大纲的前置，embedding 不是；
- **任务认领与启动恢复（P1-02）**：后台任务以条件更新原子认领（`parse_status: pending→parsing`、`outline_status: structure_ready→planning`、`embed_status: pending→running`），重复触发不双跑（replan 的 409 由此实现）；应用启动时扫描中断态——处于 `parsing / planning / running` 的任务一律转为可重试的 `failed`（原因"进程中断"）或重新入队，不无限转圈（B1-03）；
- **创建幂等（P1-05）**：`POST /studies` 支持 `Idempotency-Key` 请求头，服务端按键唯一约束去重、重复提交返回同一 study；配合前端按钮禁用防双击；
- **重新解析（决策 #29）**：仅两种入口——解析失败重试、无目录重识别。失败重试先把新结果写**暂存数据**，完整成功后一个事务原子替换旧 chunks / vec_chunks / refs，失败则旧数据原样保留；已有自动结构且解析已成功的重识别返回 409；**全书存在任何学习证据（§5.4 定义）时重解析 409**——历史消息、测验与笔记引用的 chunk 不得被删除（本版不做 chunk 版本化）。

## 10. 前端实现约定

- 服务端状态全部 TanStack Query；OpenAPI 生成类型，禁止手抄响应模型；
- 树编辑统一走 knowledge mutation，成功后失效树、进度、书架查询；
- 三框布局折叠状态、树视图选择（星盘/工作树）按书 localStorage 记忆，不落库；
- 原文深链使用真实 `studyId` 与 chunk 定位，不允许写死地址（前身反例：`/studies/0/`）；
- 点亮仪式（粒子 → 流光 → 金实心，章满戴冠）为纯前端动效，尊重系统「减少动态效果」设置；组件只实现页面清单需要的状态，不提前做拖拽布局或虚拟化。

## 11. 安全与数据边界

- LLM 与 embedding key Fernet 加密落库，密钥文件本机保存；界面只显示掩码（B5-02）；
- **密钥 PUT 语义（P1-06）**：字段缺省保持不变、置 null 清除、填新值替换；GET 只返回掩码；掩码值不是合法输入，提交掩码原文按"未修改"处理，不回写；
- 日志、异常、outline 事件与 LLM 请求上下文均不包含明文 key；
- 单部署单用户，无账号；默认仅本机监听 127.0.0.1；CORS 不用通配符，校验 Host / Origin，拒绝跨源写请求（防本机其他页面借浏览器向服务写数据）；
- **上传边界（P1-06）**：扩展名 + 文件签名（magic bytes）双重校验；大小上限；文件名只作显示，存储路径服务端生成；EPUB 作为 zip 读取时防路径穿越，并限制 entry 数量、总解压大小与压缩比（防 zip 炸弹）；XML 解析禁外部实体与网络访问（XXE）；PDF 限制页数并设解析超时；
- **Markdown 渲染安全（P1-06）**：assistant 消息与笔记在前端渲染时禁原始 HTML 或严格消毒（标签白名单），链接协议白名单（http/https），禁 `javascript:` 等协议。

## 14. 打包与分发（Windows 免安装文件夹，决策 #33）

### 14.1 选型与产物

- 工具：PyInstaller **onedir**（构建期依赖，进 dev 组；用户机零依赖）。依赖已极轻（#32 用 pypdf，无 ML 模型），无需处理模型下载；单文件 exe 否决（解包慢、杀软误报高）。
- 构建命令：`cd backend && uv sync && uv run python scripts/build_exe.py`（先 `pnpm build` 前端，再 PyInstaller；前端 dist 必须存在）。
- 产物：`backend/dist/BetterOneself/`，整文件夹拷贝即分发：

```text
BetterOneself/
├─ BetterOneself.exe        ← 双击运行（控制台窗口可见，关窗=停止服务）
├─ data/                    ← 自动生成：betteroneself.db、uploads/、secret.key
└─ _internal/               ← 运行时与资源（frontend_dist/、alembic/、vec0.dll 等）
```

### 14.2 冻结环境路径基准

- `config.py`：`FROZEN` 判定后，`BACKEND_DIR`（只读资源基准，alembic.ini/alembic/ 迁移用）指向解包资源目录（`sys._MEIPASS`）；`APP_DIR`（可写基准）指向 exe 所在目录；`data_dir` 默认 = `APP_DIR/data`。开发模式行为不变。
- 打包数据文件：`frontend/dist → frontend_dist`、`alembic.ini`、`alembic/`、三个 skills `prompt.md`（按原相对路径放置，`PROMPT_PATH` 零改动）、`sqlite_vec` 的 `vec0.dll`（`collect_data_files`）。
- 前端托管：冻结时 `_mount_frontend` 读 `_internal/frontend_dist`，其余（同源相对路径请求、SPA fallback、Origin 对本机任意端口放行）零改动。

### 14.3 启动器（app/launcher.py）语义

- 双击 exe：起服务（默认 `127.0.0.1:8000`）→ 自动打开浏览器进应用；`BO_NO_BROWSER=1` 跳过开浏览器（QA 用）。
- 端口占用：探测 `/api/studies` 返回 200 → 视为已有实例在跑，直接开浏览器并退出；否则自动改用空闲端口并告警（判定仅凭 200 状态，多服务共端口场景暂不考虑）。
- `BO_` 环境变量在打包后全部照常生效（`BO_DATA_DIR / BO_HOST / BO_PORT / BO_LLM_STUB` 等）；未配置 LLM 时仍可用原文阅读路径，AI 功能按 B5-03 降级提示。
