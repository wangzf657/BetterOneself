> 日期：2026-11-20｜状态：目标架构与验证计划，未实施（代码已按决策 #24 清零，待按本文重建）

> 配套：[数据模型](数据模型.md)、[流程图](流程图.md)、[接口设计](接口设计.md)

## 1. 技术目标与约束

1. 只做最薄闭环「导入 → 骨架 → 学 → 测 → 点亮」；计划、复习、卡片、掌握档案、督促、导出在 [后续候选](../后续候选/)，不在本文。
2. 原书结构识别与 AI 拟大纲解耦：前者零 LLM，后者失败可跳过、原树保留（B2-01、B2-03、B5-03）。
3. 骨架只有结构信息，讲解与测验进入学习时按节点生成，导入阶段不预生成任何学习内容（B2-04）。
4. 点亮只认测验通过证据：一次通过即点亮、永久保留；阅读、提问、打开会话不产生点亮（B4-03）。
5. 入口必须快：吸取前身「全文 LLM 拆解做学习入场券」的教训（[注意事项](../注意事项.md) #2），有可靠目录的书导入即可看树。
6. 核心 AI 能力拆成三个可独立测试的小 skill，不建设通用编排平台（决策 #14）。
7. 所有 LLM 自动化测试 mock；真实样书只用于人工冒烟与质量评审；真机冒烟是发版前必过的一关（注意事项 #9）。

## 2. 技术栈

| 层 | 选型 | 本版使用方式 |
|---|---|---|
| 后端 | Python 3.12、FastAPI、SQLAlchemy 2、SQLite、Alembic | 单机单用户；从零建库，单个 init 迁移 |
| 向量 | sqlite-vec、硅基流动 BAAI/bge-m3 | 1024 维 float32；与正文解析异步并行 |
| PDF | Docling + PDF 书签读取 | 书签优先建结构，正文按页定位；完整链路待 spike（§4.3） |
| EPUB | 标准库 `zipfile` + BeautifulSoup/lxml | 读 OPF、nav/NCX 与正文，不新增 ebooklib |
| AI | OpenAI 兼容 SDK | 拟大纲（含章节摘要）、讲解、出题与判分；无 LangGraph——V0.1 会话是无分支顺序流，SDK 直调即可 |
| 前端 | React 19、Vite、TS strict、TanStack Query、shadcn/ui、Tailwind 4 | 类型由 OpenAPI 生成 |
| 测试 | pytest、Playwright、ruff、mypy、tsc、ESLint | 核心逻辑单测 + 主链路真实结果 E2E |

GLM Coding Plan 已知约束：不含 embedding（embedding 独立走硅基流动）、高负载可能排队、思考型模型需给 reasoning tokens 留空间。属于服务约束，不进入产品文案。

## 3. 模块边界

```text
frontend/src/features/
  studies/     书架（P02）+ 添加一本书（P01）
  tree/        技能树（P03）：星盘、章内路径、工作树、详情面板与编辑弹窗
  learn/       学习会话（P04）：三框布局、对话、内嵌测验、节点笔记
  settings/    设置（P05）：服务配置、用量、点亮反馈

backend/app/
  api/         参数校验与响应，不写业务
  services/    studies / sources / knowledge / outline / learning / quiz / notes / app_settings
  ingest/      格式识别、目录提取、正文解析、切片、embedding、向量库
  skills/      outline_planner / tutor / quiz
  models/      按数据模型迁移
  schemas/     Pydantic 契约
```

定位原则：目录提取是确定性 ingest 能力，不是 LLM skill；讲解、出题、判分是 skill；点亮判定是 quiz service 的事务逻辑，不是 LLM 输出。

## 4. 导入与目录识别

### 4.1 三阶段解耦（B1-01～03、B2-01～04）

**阶段 A：结构草稿**

- 读取目录、标题与顺序，生成初始知识树，标记识别依据与置信度；
- 不调用 LLM，不等待正文或 embedding，结构树立即可浏览。

**阶段 B：正文与引用**

- 解析正文、规范化、切片（切片是检索单位，不直接创建知识点）；
- 将切片挂到目录节点（`knowledge_refs`），计算跨格式通用篇幅 `char_count`；
- 引用挂载事务提交后自动触发一次 AI 拟大纲（阶段 C 的前置条件）；
- embedding 后台并行，不阻塞任何阶段。

**阶段 C：拟大纲应用**

- 见 §5；必须等引用挂载完成后才应用结构调整，避免把引用尚未生成的节点改成无来源学习单元。

### 4.2 格式策略

| 格式 | 结构信号优先级 | 正文与定位 | 置信度处理 |
|---|---|---|---|
| PDF | 书签 → 编号标题 → 字号/字重 | Docling 正文；优先按书签页码区间挂切片 | 书签高；编号中；样式低 |
| EPUB | nav → NCX → 正文标题 | OPF spine 顺序读取 XHTML，保留 `href + 锚点` | nav/NCX 高；正文标题中 |
| Markdown | `#`–`######` 标题 | 按完整标题路径切分，记录行号 | 明确标题高；跳级需提示 |
| TXT | Markdown 式标题 → `第 N 章` / 数字编号 → 无结构 | 按识别标题切分并记录行号 | 编号中；无结构不假装有目录 |

无结构 TXT 或识别失败文档：保留正文、显示无目录空态（P03-F），本期不支持学习；**不自动全文 LLM 拆解**。

### 4.3 PDF 待验证

【目标】先读书签与页码形成结构草稿；Docling 按页导出正文，书签页码区间确定目录叶子；页内按标题与段落切片并保留完整层级；书签与正文无法对齐的区间标低置信度，不模糊匹配后假装成功。

【待验证，不得提前写成已完成】

- 313 页样书从书签 → 按页导出 → 页码区间挂引用的完整链路；
- 第一章 p15–38 的引用覆盖率、错挂率与耗时；
- 无书签 PDF、扫描 PDF、中文编号 PDF 的降级表现；
- EPUB nav/NCX 与 TXT 编码、标题规则的真实样本覆盖。

### 4.4 切片规则

- 切片按标题层级组织（h1–h6 完整路径，前身切片器丢 h3–h6 是已确认的反例），**不按整章切**：整章切片语义混杂会稀释向量检索精度，引用回跳也只能定位到章、不满足「定位到对应位置并高亮」；「章-节」是学习单元（知识点）的粒度，不是切片粒度；
- `MAX_CHARS` 沿用前身实测值，只有真实检索抽评证明不足才调；
- `location` 保存页码或行号区间，引用回跳不依赖标题模糊搜索。

## 5. AI 拟大纲（B2-03，决策 #25）

### 5.1 输入与输出

输入：`book_title`、`nodes`（含 `char_count` 必填、`page_span` 仅 PDF 可靠页码时填，其他格式 `null` 不伪造）、`chapter_summaries`（可选）。正文逐字内容不进入输入。

输出限定五类结构操作 + 全书总述：

1. `exclude`：排除非学习单元并给理由；
2. `split`：把篇幅过大或语义过多的节点拆成 2–5 个学习区域；
3. `merge`：合并在语义与篇幅上都过碎的相邻节点；
4. `organize`：章内建立学习区域父节点，不改章锚点，产物 `origin='ai_organize'`；
5. `group`：章层之上建部分节点，仅覆盖**连续章节区间**，产物 `origin='ai_group'`；不吞并章、不改章顺序；原目录贴合书逻辑时可不出。

另附 `thesis`（一句话总述：这本书整体讲什么 + 各部分如何推进），存 `studies.outline_thesis`，不产生节点。每条操作必须引用输入节点 ID 并带一句理由。结构化输出校验失败即本次规划失败，保留原树。

### 5.2 触发与降级

- 引用挂载事务提交后自动排一次，两步执行：先逐章压缩内容摘要（每章独立一次轻调用、可并行，输入该章 refs 全文，固定四问模板：这章解决什么问题 / 核心论点 / 与前后章的关系 / 内容性质〔理论·案例·小结·附录〕），再拟大纲；摘要写入 `kp.chapter_summary`（§8 chat 复用），失败退回仅结构信息输入（决策 #8 原行为），不重试循环、不阻塞；
- 同一结构版本只自动跑一次，浏览与学习不重复触发；
- 未配置 LLM：引用就绪后直接标 `skipped`；超时、限流、校验失败标 `failed`；两者原树均保留（B5-03）；
- 用户可手动重试（`POST /outline/replan`）；
- 应用结果时按 `updated_at` 比对，跳过用户已编辑的节点，保留用户最后操作。

### 5.3 粒度约束

prompt 只给软约束：常见学习目标 20–45 分钟；过粗过细结合标题语义判断；小结/思考题是否排除取决于内容角色，不只靠关键词正则；章不可删、不跨章合并；部分层按书的逻辑划，不设统一格数；不生成依赖边，默认学习顺序仍是目录顺序。

### 5.4 准确性保障（「准确」= 不破坏、有据、克制、可回滚）

LLM 只提结构操作建议，不生成树——准确性的地基是硬约束兜住结构、把 LLM 的自由度限制在五类操作内：

**生成**：thesis 与全部操作**单次全局调用**产出（部分分组必须看到全书，逐章调用无全局视野）；prompt 按分析阅读顺序分步——①通读标题树与摘要写 thesis → ②划部分（仅连续区间，已贴合则不分组）→ ③逐部分查章（非学习单元 → exclude，必须给理由）→ ④逐章查粒度（char_count 偏离同书分布 → split/merge）→ ⑤输出操作列表（每条带 node_id 与理由，不确定的不动）。低温度（0–0.3）；思考型模型换准确率（导入是后台任务，慢可接受）——【待验证】与标准模型的真实样书对比。

**校验（代码层，不靠 LLM 自觉；任一失败 → 整体失败保树，宁缺毋滥）**：

- 操作引用的 node_id 必须存在于输入；
- exclude 不得作用于 `is_chapter=true`；
- merge 双方相邻且同章；split 仅章内、产物 2–5 个；
- group 为连续章节区间，不吞并章、不改顺序；
- 同一节点不得出现在冲突操作中（先 exclude 又 split）；
- thesis 非空、长度合理。

**应用**：`updated_at` 比对跳过用户已编辑节点；每条操作落 `outline_events`（理由即 planning_note，B2-03「调整结果可辨认」）；恢复原目录整机回滚；引用就绪前不应用。

**评测**：golden 小书（结构松散的已知答案样例）做 skill 契约回归；真实样书人工抽评是发版验收（需求列表既定规则）。

### 5.5 状态机与页面状态条映射

`studies.outline_status`：`idle → structure_ready → planning → ready | skipped | failed`。

| P03 状态条 | 判定 |
|---|---|
| 结构识别中 | `parse_status ∈ {pending, parsing}` 且 `outline_status=idle` |
| 原文与引用准备中 | `outline_status=structure_ready` 且正文解析未完成；结构可编辑，不能开学习 |
| AI 规划中 | `outline_status=planning`（原目录仍可编辑） |
| 未配置 AI | `outline_status=skipped` 且原因为未配置 |
| 规划失败 | `outline_status=failed`（附原因与重试） |
| 规划完成 | `outline_status=ready`（附调整摘要：N 个部分、排除/拆分/合并计数） |
| 低置信度 | 树上存在 `confidence` 低于阈值的结构（派生展示，请用户检查标记节点） |

## 6. 三个核心 skills

```text
backend/app/skills/
  outline_planner/   skill.py + prompt.md + test_skill.py + golden/
  tutor/             同上
  quiz/              同上
```

每个 skill 只有：一个输入/输出 Pydantic 契约、一个主提示词、一组 golden cases、对统一 `llm()` 薄函数的调用。不引入注册表、热加载、YAML DSL、插件包或可视化编排。

| Skill | 职责 | 不做什么 |
|---|---|---|
| `outline_planner` | 章节摘要消费、全书总述、部分分组、排除、拆分、合并、章内组织 | 不输入正文逐字内容、不建依赖图 |
| `tutor` | 开场讲解（定位 + 首段 + 理解问题）、自由问答、按学习方法调整风格 | 不改节点状态、不出题 |
| `quiz` | 按节点出题（客观题为主 3–5 题）、客观题判定、简答题评语 | 不决定点亮（service 判定）、不做卡片 |

**四问法沉入 prompt（决策 #25）**：tutor 开场先答「本细节在整体中的位置」；quiz 题型覆盖「细节理解与辨析」（作者论断是否成立、论据是否支持）和「应用」（给定情境怎么用）。不新增 UI。

**学习方法（B3-03）**：`scheme` 三值 `guided（带我学）/ lecture（讲给我听）/ drill（帮我过关）`，只改变 tutor 的讲解风格与 quiz 的考练密度，**不降低也不抬高通过线**。书级默认存 `studies.scheme`，会话内切换只影响当前会话。

## 7. 学习会话与测验点亮（B3、B4）

### 7.1 会话模型：节点 1:1 持久会话

- 一个骨架节点至多一条会话：进入学习时「取或建」（`POST /sessions {kp_id}` 幂等），消息持续追加；「继续学习」回到上次节点即回到同一条会话；
- 节点状态「学习中」为派生态：该节点会话存在消息且未点亮；不落字段；
- 自由提问、阅读、离开都不改节点状态（B3-04）。

### 7.2 开场与对话（B3-01、B3-02）

- 进会话若无 assistant 消息，前端自动调 `POST /sessions/{id}/opening`：tutor 生成首条消息——① 一句话定位（本节点属于哪部分、推进全书什么、要解决什么；大纲不可用时只说后者）② 首段讲解带 `[1][2]` 引用 ③ 一个简短理解问题；失败不伪造用户消息，保留原文与重试按钮；
- 对话 `POST /chat` SSE 流式；生成中可停止；
- 每条 assistant 消息带 `chunk` 引用列表；前端点击角标 → `GET /chunks/{id}` → 原文框（收起则自动展开）滚动定位高亮。

### 7.3 测验与点亮（B4-01～04）

- `POST /sessions/{id}/quizzes` 生成一组：客观题为主 3–5 题，题数与通过线在生成说明中明示（如「4 题，对 3 题点亮」）；题干、选项、解析必须锚定本节点 refs；
- **提交前不泄露答案**：题目面（questions_json）下发，答案与解析（answers_json）只存服务端，提交判分后才返回；
- `POST /quizzes/{id}/answer`：客观题即时判定；简答题由 quiz skill 评语；判分后返回对错、正确答案、解释、来源与错题「回到原文」「再问一个变式」所需引用；
- **达线即点亮**：判分事务内写 `knowledge_points.lighted_at`，响应带点亮反馈卡数据（节点名、得分、通过线、口径说明）；点亮只认测验证据，永久保留（B4-03）；
- **未通过**：不点亮、不锁任何功能；「再考一组」生成新题——生成时将该节点全部历史题干传入 quiz skill 排除，生成后做题干完全重复检查，重复则重试一次（B4-02 反例：不得出现同题）；
- 历次测验与错题可回看（`GET /kps/{id}/quizzes`），挂在节点而非会话消息上，消息流中的测验卡只是展示层。

### 7.4 节点笔记（B3-05）

- 每节点一篇 Markdown 笔记，`GET/PUT /kps/{id}/note` upsert、自动保存；64KB 上限；
- 笔记顶部自动带节点位置（部分 → 章 → 节点）由前端从树数据渲染，不存进笔记正文；
- 原文选段「记到笔记」由前端在光标处插入引用块（节点名 + 定位 + 被引文本）；
- 笔记不参与点亮与任何统计口径（决策 #26）。

## 8. 检索与上下文

chat 与讲解的上下文按三层组装：

1. **节点静态引用保底**：先取当前节点 `knowledge_refs` 切片全量（节点 = 20–45 分钟单元，通常 5k–15k tokens 可全量）；refs 超过 `_TOP_K=6` 条时按当前问题相关性选择，不固定截掉后半章；
2. **章节摘要作书级地图**：全书各章 `chapter_summary`（拟大纲时已生成）常驻上下文，支撑跨节点与结构性提问（「这部分讲什么」「和第 2 章什么关系」）；
3. **向量补足细节**：用户问题指向其他节点细节时，在**本书**向量库检索补足相关切片，引用仍限本书。

- 打开节点只加载该节点 refs（B3-02 反例：不得加载整本书）；引用回跳用 `chunk_id` 精确定位；
- 真实抽评前不加重排器。

## 9. 异步、事务与恢复

- FastAPI BackgroundTasks，不引入 Celery 或消息队列；
- 文件保存、项目创建、主资料绑定一个事务；正文解析、embedding、拟大纲在提交后运行；
- 结构建树、引用挂载、拟大纲应用各自独立事务；引用挂载提交是拟大纲的前置，embedding 不是；
- 重新解析只用于失败重试或结构重识别：保留手动节点与学习数据；已有自动结构时重识别返回冲突；
- 重启后未完成任务以数据库状态识别：正文可重试、规划可重试、原树不清空（B1-03：离开再回来状态不丢失，不无限转圈）。

## 10. 前端实现约定

- 服务端状态全部 TanStack Query；OpenAPI 生成类型，禁止手抄响应模型；
- 树编辑统一走 knowledge mutation，成功后失效树、进度、书架查询；
- 三框布局折叠状态、树视图选择（星盘/工作树）按书 localStorage 记忆，不落库；
- 原文深链使用真实 `studyId` 与 chunk 定位，不允许写死地址（前身反例：`/studies/0/`）；
- 点亮仪式（粒子 → 流光 → 金实心，章满戴冠）为纯前端动效，尊重系统「减少动态效果」设置；组件只实现页面清单需要的状态，不提前做拖拽布局或虚拟化。

## 11. 安全与数据边界

- LLM 与 embedding key Fernet 加密落库，密钥文件本机保存；界面只显示掩码（B5-02）；
- 日志、异常、outline 事件与 LLM 请求上下文均不包含明文 key；
- 单部署单用户，无账号；默认仅本机监听；
- 上传只接受四种扩展名并限制大小；文件名只作显示，存储路径服务端生成；EPUB 作为 zip 读取时防路径穿越。
