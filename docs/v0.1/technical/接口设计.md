# V0.1 接口设计

> 日期：2026-11-20｜状态：目标 API 契约，未实施（代码已清零，随重建落地）
> 产品行为以 [需求列表](../product/需求列表.md)（B1-01…B5-04）为准；字段与口径见 [数据模型](数据模型.md)。
> 原则：路由薄、Pydantic 契约明确、前端类型从 OpenAPI 生成。本文不表示端点已经存在。

## 1. 通用约定

- 前缀 `/api`，JSON UTF-8；文件上传 `multipart/form-data`；讲解与对话使用 SSE。
- 路径中的资源必须属于同一 study，否则 404/422，禁止跨书挂接（B3-02 反例：引用不得落到另一本书）。
- 写操作由 service 开事务；路由不直接拼 SQL。
- 状态码：400 格式错误；404 不存在；409 状态冲突（如规划已在运行）；415 文件类型不支持；422 领域约束不满足；503 LLM 未配置或调用失败（带 `retryable`）。
- 错误响应保留可读 `detail`；内部异常不泄露密钥、文件绝对路径或模型请求头。
- 列表空返回 `[]`；进度不可用（分母为 0）返回 `null`，前端显示「—（无有效学习单元）」，不用 0 冒充。
- 页面路由：P01 `/studies/new`、P02 `/studies`、P03 `/studies/:studyId`、P04 `/studies/:studyId/learn/:nodeId`、P05 `/settings`（见 [页面清单](../product/页面清单.md)）。

## 2. 学习项目与导入（B1）

### `POST /api/studies`

`multipart/form-data`：`name`（1–200，必填）、`file`（`.pdf/.md/.markdown/.txt/.epub` 单文件，必填）；请求头 `Idempotency-Key`（前端生成 UUID，P1-05）。

- 扩展名外 415；大小超限 422；文件签名校验失败 415；**幂等**：同 key 重复提交返回同一 study（201 / 200），不产生两本书。
- 文件先落临时盘；一事务创建 study + source + 绑定主资料并提交，随后临时文件 rename 为 `stored_path`；提交后启动后台解析（结构识别 → 正文切片 → 拟大纲排队）。
- 201：`{study}`（含初始 `parse_status='pending'`、`outline_status='idle'`）。
- **不产生没有主文件的项目**（B1-01 反例）；无补充资料、粘贴文本等入口（B1-02 反例）。

### `GET /api/studies`

书架列表（P02）。每项：

```json
{
  "id": 1, "name": "……", "source_type": "pdf",
  "parse_status": "parsed", "parse_error": null,
  "progress": {"lighted": 12, "total": 178, "percent": 6.7},   // total=0 时 progress=null
  "last_learned_at": "……", "last_kp": {"id": 42, "name": "4.2 上下文工程", "status": "learning"}
}
```

- 书架项带解析状态与错误（P1-05）：失败的书可直接在卡片定位 `reparse` / `replace`；
- `last_kp` 为 null 时「继续学习」进树的第一个未点亮学习单元（前端从树数据取）。

### `GET /api/studies/{id}` / `PATCH /api/studies/{id}` / `DELETE /api/studies/{id}`

- GET：名称、`outline_thesis`、`scheme`。
- PATCH：`{name? / scheme?}`；**不接受换主文件**（换主文件走 `source/replace`，仅限失败态）。
- DELETE：级联删除全部数据；前端删除前展示影响清单（会话数、测验数、点亮数），删整本书需输入书名确认。

### `POST /api/studies/{id}/source/replace`

更换主文件（P1-05）：**仅** `parse_status='failed'` 且全书无任何学习证据时可用，否则 409；`multipart/form-data` 同创建；原 study 复用，source 原子替换后重走解析。

### `GET /api/studies/{id}/progress`

P01 分步进度与 P03 状态条数据源：

```json
{
  "parse":   {"status": "parsed", "error": null},
  "outline": {"status": "planning", "error": null, "thesis": null,
               "adjust_summary": null,   // ready 时：{parts: 4, excluded: 18, split: 6, merged: 12,
                                         //           applied: N, skipped: M}（实际应用数与跳过数，P2-07）
               "reason": null},           // skipped/failed 时可读原因
  "embedding": {"status": "ready", "done": 812, "total": 855, "error": null}
}
```

### `POST /api/sources/{id}/reparse`

重试解析（B1-03、B5-03、决策 #29）：仅解析失败重试与无目录重识别两个入口；**全书存在任何学习证据（session/message/quiz/note/lighted）时 409**；已有自动结构且解析已成功时 409；执行采用暂存 + 完整成功后原子替换。

### `POST /api/sources/{id}/reembed`

embedding 重试（P05 §2 状态附重试）：仅 `embed_status ∈ {failed, degraded}` 时可触发，重新入队向量任务；核心链路不受影响（B5-03）。

## 3. 技能树与结构编辑（B2、B5-01）

### `GET /api/studies/{id}/knowledge`

嵌套树（P03 三视图与 P01 结果共用）。节点：

```json
{
  "id": 42, "name": "……", "sort_order": 3, "parent_id": 9,
  "is_chapter": false,
  "is_learning_unit": true,                      // 结构叶 ∧ 未排除 ∧ refs≥1（决策 #27，派生）
  "origin": "toc", "confidence": 0.95, "confidence_basis": "原书目录",
  "planning_note": null,
  "excluded": false, "exclusion_reason": null,
  "status": "unlearned | learning | lighted",    // 仅 is_learning_unit=true 有三态；容器节点恒为 null
  "lighted_at": null,
  "lighted_count": 3, "valid_total": 8,          // 容器节点：子树聚合点亮计数
  "children": [ ... ]
}
```

- 容器节点（父节点、部分层、有子节点的章）`status=null`、无学习入口，前端显示聚合进度（决策 #27）；
- 含 `progress` 汇总（口径见数据模型 §4）；`low_confidence` 节点带标记（P03 状态条 ⑦）。

### `GET /api/studies/{id}/outline-status`

P03 页头与状态条：`{status, error?, thesis?, adjust_summary?, low_confidence_count}`。`thesis` 未生成时为 null，不留占位。

### `POST /api/studies/{id}/outline/replan`

手动重试规划（B2-03、B5-03、决策 #29）：结构不存在 422；已在运行 409；成功 202。与自动规划共用同一应用链路：逐条写事务复查（有证据的 split/merge 跳过、用户编辑冲突跳过，记 `planning_conflict_skipped`），**不因已有学习证据整体拒绝**。

### `GET /api/studies/{id}/outline/events?limit=50`

倒序结构事件（P03-E 抽屉）：`{event_type, actor, kp_name, detail, created_at}`；`kp_name` 取自 detail_json 名称快照（kp_id 可能已 SET NULL）。

### `POST /api/studies/{id}/outline/restore-original`

恢复原目录（P03-E/F、决策 #29）。前置：全书**无任何学习证据**（session/message/quiz/note/lighted，不能只看消息）且 `outline_status ≠ planning`（防 stale 写入）；违反则 409/422，422 响应列出证据所在节点，提示改用逐个排除。执行前由前端弹窗展示**撤销清单**（`GET /api/studies/{id}/outline/restore-preview` 返回：AI 调整数、手动重命名数、手动排除数）。成功 200：`{removed, restored, revoked_renames, revoked_exclusions, progress_before, progress_after}`。

### `GET /api/kps/{id}/exclude-impact`

排除影响预览（P1-01）：不落库，实时计算该节点排除后的 `{progress_before, progress_after, lighted_affected}`（分母、分子、受影响已点亮数）。排除弹窗在确认前调用本端点展示，确认后执行 exclude，**执行结果必须与预览一致**。

### `PATCH /api/kps/{id}`

`{name}` 重命名（B2-05）。200 返回节点；原名进 outline_events；**不改变分母**（不写分母事件）。

### `POST /api/kps/{id}/exclude` / `POST /api/kps/{id}/restore`

`{reason?}`。200：

```json
{"kp": { ... }, "progress_before": {"lighted": 12, "total": 178, "percent": 6.7},
 "progress_after":  {"lighted": 12, "total": 164, "percent": 7.3}}
```

进度前后值即弹窗展示数据（与 exclude-impact 预览一致，B5-01：分母变化明示）；排除已点亮节点前端先弹确认。已排除再排除 409；已排除节点创建会话 / 生成测验 422（历史会话、测验、笔记只读可回看）。

### `POST /api/kps/{id}/dissolve-group`

解散部分分组（P03-D）。仅 `origin='ai_group'` 节点，否则 422。子章上移一级，学习数据零变动；200 同上带进度前后值。

## 4. 学习会话（B3）

### `POST /api/studies/{id}/sessions`

`{kp_id, scheme?}`。**幂等取或建**：该节点已有会话则直接返回。200：`{session}`。422 情形：节点非有效学习单元（容器节点 / refs=0，前端显示「原文准备中」）、节点已排除（历史会话只读回看，不开新学习）。

### `GET /api/sessions/{id}`

`{session, messages[], quizzes[]}`——前端按 `created_at` 合并渲染对话流（测验卡来自 quizzes）。消息含 `refs`（角标回跳数据）。

**测验序列化面分两级（P1-03）**：`answered_at` 为空的测验按 `QuizPublic` 序列化（quiz_id、题号、题型、计分/练习标记、题干、选项、pass_line、question_count）——**不含答案、解析与答案 refs**；已提交的按 `QuizAnswered` 序列化（另含本人作答、逐题判分、评语）。历史回看端点（`GET /kps/{id}/quizzes`）一律 `QuizAnswered`。

### `POST /api/sessions/{id}/opening`

生成首条讲解（B3-01）。**SSE 流式**：`event: delta`（增量文本）/ `done`（完整消息含 refs）/ `error`（可读原因，可重试）。

- **流建立前失败 → HTTP 503 JSON（带 retryable）；流建立后失败 → SSE `error` 事件**（P1-04）；
- 原子认领：会话已有 assistant 消息 409；开场生成进行中再请求返回既有结果（幂等），双击不产生两条开场；
- 失败不伪造用户消息；大纲不可用时降级为仅基于当前节点（响应不报错）；
- 内容契约：① 一句话定位（部分 → 章 → 节点、推进作用）② 首段讲解带 `[1][2]` 引用 ③ 一个简短理解问题。

### `POST /api/sessions/{id}/chat`

`{content}`。SSE 流式同上（错误分界同 opening）；生成中客户端断开即停止（B3-04）。**持久化语义（P1-04）**：同一会话串行生成（并发请求排队）；用户消息在调用 LLM 前提交入库；assistant 消息完成或停止时保存（停止保存已生成部分并标记 stopped）；LLM 失败不保存 assistant 消息、用户消息保留可重试；提问不改节点状态。

### `PATCH /api/sessions/{id}/scheme`

`{scheme: guided | lecture | drill}` 会话内切换（B3-03），只影响本会话后续生成，不降通过线。

### `GET /api/kps/{id}/content`

节点原文（B3-02）：`{chunks: [{id, title, content, location}]}`——只返回该节点 refs 切片，**不拉整本书**。P04 左侧原文框数据源。

### `GET /api/chunks/{id}`

引用回跳（B3-02）：`{chunk, source_id, location}`。点击角标 → 原文框（收起则自动展开）滚动定位高亮；位置不可用时前端展示所在章与来源文本，不跳空白页。

### `GET /api/kps/{id}/note` / `PUT /api/kps/{id}/note`

节点笔记（B3-05）。GET 未写过返回 200 空串；PUT upsert `{content_md}`，64KB 上限 422。自动保存由前端防抖调用；笔记不参与点亮与统计。

## 5. 测验与点亮（B4）

### `POST /api/sessions/{id}/quizzes`

生成一组测验（B4-01、B4-02）。200（`QuizPublic` 面，不含答案）：

```json
{
  "quiz_id": 7, "question_count": 4, "graded_count": 4, "practice_count": 1, "pass_line": 3,
  "questions": [{"no": 1, "type": "choice", "graded": true, "stem": "……", "options": ["A", "B", "C", "D"]},
                 {"no": 5, "type": "short", "graded": false, "stem": "……"}],
  "coverage": [{"no": 1, "dimension": "细节理解与辨析"}, {"no": 2, "dimension": "应用"}]
}
```

- **3–5 道客观计分题（单选/判断，`graded=true`）+ 至多 1 道简答练习（`graded=false`，不计入成绩）**；
- `pass_line` 由 service 按计分题数查固定映射 {3题:2, 4题:3, 5题:4} 落库，响应即对话流中的测验说明（B4-02）；
- **幂等**（P1-03）：该节点已有进行中的测验直接返回它（200，同 id），双击与断连重试不重复生成；一节点同时最多一组进行中；
- **响应不含答案、解析与答案 refs**（B4-01 反例、未提交测验公开面）；覆盖本节点 refs 之外的内容为契约违规（skill 校验）；
- 生成时排除该节点全部历史题干；生成后重复检查重试一次，**第二次仍重复 → 503 `{detail: "本次出题失败……", retryable: true}`，不下发旧题**（B4-02）；LLM 失败 503。

### `POST /api/quizzes/{id}/answer`

`{answers: [{"no": 1, "choice": "A"} | {"no": 4, "choice": true} | {"no": 5, "text": "……"}]}`。200（`QuizAnswered` 面）：

```json
{
  "per_question": [{"no": 1, "graded": true, "correct": true, "answer": "B", "explanation": "……", "refs": [ ... ]},
                    {"no": 5, "graded": false, "comment": "具体评语", "refs": [ ... ]}],
  "correct_count": 3, "pass_line": 3, "passed": true,
  "lighted": {"kp_name": "4.2 上下文工程", "lighted_at": "……", "already_lighted": false}
}
```

- 判分只对 `graded=true` 的题：单选/判断二元等权比对；简答练习只出 `comment`，不进 `correct_count`、不影响 `passed`（B4-01）；
- 通过线生成时已定（固定映射落库），判分只比对不重算（B4-02）；
- 作答与逐题判分（正误、答案、解析、评语、返回用 refs）在判分事务内一次写入 `submitted_answers_json` / `grading_results_json`，刷新后回看完全一致（决策 #30）；
- `passed=true` 且节点未点亮 → 判分事务内写 `lighted_at` 与 `lighted_by_quiz_id`，响应带点亮反馈卡数据（B4-03）；**节点已点亮时重考照常判分，`lighted.already_lighted=true`，不触碰点亮字段**；
- 未通过：不点亮、无任何惩罚字段；「再考一组」走生成端点（自动去重）；
- **提交原子认领（P1-03）**：条件更新 `WHERE answered_at IS NULL`，首个请求判分；已提交再提交幂等读回已判分结果（200 同响应），不重复判分、不报 409。

### `GET /api/kps/{id}/quizzes`

历次测验回看（B4-04，`QuizAnswered` 面）：`[{quiz_id, created_at, question_count, graded_count, correct_count, pass_line, passed, questions, submitted_answers, per_question}]`——含本人作答、错题评语与 refs，可一键回到原文；刷新与重进内容一致。

## 6. 设置与用量（B5）

### `GET /api/settings` / `PUT /api/settings`

分组：讲解与测验服务（`llm.base_url / llm.model / llm.api_key`）、资料处理服务（`embed.*`，GET 另返回 `embed_status / embed_error`）。

- GET 只返回掩码（`sk-****abcd`），永不返回明文（B5-02 反例）；
- **PUT 语义（P1-06）**：字段缺省保持不变、置 null 清除、填新值替换；掩码值不是合法输入，提交掩码按"未修改"处理，不回写；分节独立保存，某项校验失败不清空其他项；
- 未配置或失败的资料处理服务不阻塞树与原文（B5-03）：**仅失去跨节点向量补足，当前节点讲解、测验与原文可用**，响应按此口径返回状态说明。

### `GET /api/usage?from=&to=`

按日期与场景：`[{date, scene: outline|tutor|quiz|embed, requests, prompt_tokens, completion_tokens}]`（B5-04）。空区间返回 `[]` 并由前端给出明确空态文案。

## 7. 需求到接口映射（22 条全覆盖）

| 需求 | 端点与落点 |
|---|---|
| B1-01 创建即绑主文件 | POST /studies（事务 + Idempotency-Key + 临时文件 rename） |
| B1-02 四格式单文件 | POST /studies 415/422（含文件签名）；无其他导入入口 |
| B1-03 导入状态与失败可见 | GET progress、parse_error、POST reparse、POST source/replace、启动恢复 |
| B2-01 零 LLM 结构树 | 导入管线阶段 A；GET knowledge 即见树 |
| B2-02 置信度可见 | knowledge 树 confidence/confidence_basis |
| B2-03 自动拟大纲可降级 | 导入管线阶段 C；outline-status、replan（逐条复查与 conflict_skipped） |
| B2-04 不预生成学习内容 | 负向约束：导入阶段无讲解/测验生成端点 |
| B2-05 重命名/排除/恢复 | PATCH kps、GET exclude-impact、exclude/restore、dissolve-group、restore-original、events |
| B2-06 三态可见全开放 | knowledge 树 is_learning_unit + status；无解锁校验端点 |
| B3-01 首条讲解 | POST sessions（取或建 + 有效学习单元 gate）+ POST opening（原子认领） |
| B3-02 三框与引用回跳 | GET kps/content、GET chunks、消息 refs |
| B3-03 学习方法三选一 | studies.scheme、PATCH sessions/scheme |
| B3-04 自由提问不改状态 | POST chat（无状态副作用；用户消息先落库） |
| B3-05 节点笔记 | GET/PUT kps/note（三态由前端呈现） |
| B4-01 有来源的测验 | POST quizzes（graded/practice 标记、coverage 列表、refs 校验） |
| B4-02 通过线明示可重考 | 生成响应 pass_line（固定映射）；历史题干去重与二次重复终态 |
| B4-03 通过即点亮 | POST answer（lighted + already_lighted）；knowledge 树 lighted_at/lighted_by_quiz_id |
| B4-04 结果与错题回看 | GET kps/quizzes（QuizAnswered：作答 + 逐题判分持久化） |
| B5-01 进度可下钻 | GET studies（progress）、GET exclude-impact、lighted_by_quiz_id 下钻 |
| B5-02 密钥安全 | settings 掩码 + Fernet 落库 + PUT 三语义 |
| B5-03 AI 失败不阻塞 | reparse、replan、opening/chat 503 + retryable；树与原文端点不依赖 LLM |
| B5-04 配置与用量可见 | settings（含 embed_status）、usage |
