# 第一部分：产品定义

## 1. 一句话定位

**一个不限定领域的伴学 Agent：你导入自己的学习资料，它拆解成体系、排出计划，每天陪你学、考你练、盯着你复习——直到你真的学会，而不是"看过"。**

工作名 BetterOneself，直取"成为更好的自己"之意。

## 2. 要解决的问题

自学者手握资料（PDF/文档/网页/开源项目）却始终学不进去，症结不在"缺内容"而在**缺过程管理**：

| 断裂点 | 现状 | 后果 |
|---|---|---|
| **导入后断崖** | NotebookLM 等给生成物不给路径，用户导入 30 份 PDF 后第一问是"然后呢"〔调研〕 | 收藏≠学习，资料烂在收藏夹 |
| **学与习脱节** | 讲解类产品学完即止（OpenMAIC 止于"下课铃"），复习类产品（Anki）不吃任意资料 | 学了就忘，无间隔重复兜底 |
| **督促缺失** | 全行业"打开才存在"，无主动触达〔调研：竞品督促机制集体为零〕 | 靠意志力硬扛，3 天后弃用 |
| **不认识学习者** | 每次对话从零开始，无跨会话掌握度档案（OpenMAIC 用户最低分项恰是"认识我的强弱项"） | AI 讲得再多，不知道我卡在哪 |

**核心判断**：「任意资料 → 规划 → 督促 → 排程复习」四环，每一环的单独价值都已被市场验证（NotebookLM 的资料侧、StudyFetch 的计划侧、Khanmigo 的教法侧、Anki/RemNote 的复习侧），但**没有一家产品把四环打通**〔调研〕。我们要做的就是这个闭环，且这个位置目前是空的。

## 3. 目标用户

**首批（V1.0 ~ V1.1）——程序员/技术学习者**：
- 画像：以 repo、技术文档、论文、教程为教材的自学开发者；要学一个新框架/读一个开源项目/啃一个技术领域
- 为什么先做他们：① "以 repo 为教材"是零供给市场（NotebookLM 都不支持）〔调研〕；② 天使用户与建设者画像重合，反馈快；③ GitHub/MD 导入直接命中痛点，产品示例现成

**泛化（V2.0+）——所有"有资料、有目标、缺过程"的成人自学者**：
- 考证/备考人群（资料密集+deadline 驱动，规划督促需求最刚性）
- 职场技能提升者

**明确不服务（现阶段）**：K-12 应试学生（监管与内容合规复杂度高，DeepTutor 的 Guardian 模式留作远期参考）。

## 4. 差异化定位

```
                    教学法强
                       │
              Khanmigo │ ？
        （不吃用户资料）│（我们：用户资料×教法×过程管理）
                       │
  复习/记忆强 ─────────┼────────── 资料管理强
      Anki/RemNote     │      NotebookLM
   （无AI讲解无资料）   │    （无规划无督促无排程）
                       │
              OpenMAIC │  StudyFetch
         （止于下课铃）│（链路全但每环都浅）
                       │
                    生成物强
```

**四条差异化主张**（均有竞品空白支撑〔调研〕）：

1. **计划是导入后的第一屏，不是功能之一**——基于资料结构（章节/概念依赖）排课，计划项锚定源文引用，且随测验结果动态重排。StudyFetch 的计划只是"里程碑+进度条"，不与资料联动。
2. **讲解→卡片→排程→薄弱点→再讲解的自动闭环**——学习过程中的错题与卡壳点自动沉淀为复习卡片进入间隔重复队列，复习中的薄弱点反向触发针对性讲解。这个环闭源开源都没有人做到。
3. **督促是计划的执行器**——今日任务、逾期自动重排（重排而非堆叠，避免"破罐破摔"）、周复盘。全行业竞品在此为零。
4. **跨会话掌握度档案**——以知识点为粒度记录掌握状态，学习、规划、复习、报告全部从档案出发。这也是未来垂类路径沉淀的数据前提。

## 5. 产品原则（决策时的取舍标准）

按优先级排列，冲突时上位优先：

1. **闭环 > 单点**：宁可每环做薄，不可缺环断链。产品的价值在"伴学全过程"，不在某个功能多强。
2. **结构化学习流为主，对话附着其上**：纯对话式 tutor 是已被证伪的死亡赛道（Quizlet Q-Chat 下线、Mr.-Ranedeer 停维护〔调研〕）。对话永远发生在"任务/卡片/薄弱点"的上下文里。
3. **掌握证据 > 阅读时长**：进度由评估证据驱动（借鉴 DeepTutor 掌握度门控），"看过"不算"学会"；自评与评估分开记录。
4. **信任锚定**：AI 输出一律带源引用（NotebookLM 式 citation pin）；学习者档案可查看、可编辑、可导出、可删除。
5. **开放而非锁定**：数据与卡片可导出（Markdown/Anki），用户随时能带着资产离开。
6. **教学法护栏可调**：默认苏格拉底模式（先作答→分层提示→要求复述），提供"直接告诉我"开关。护栏依据哈佛 Kestin 2025 研究，但不强加于人。

# 第二部分：产品逻辑

## 6. 核心概念模型

七个概念构成产品骨架，箭头表示数据流向：

```
 学习项目 Study ──包含──→ 知识点 Knowledge Point ──挂载──→ 掌握档案 Mastery Profile
      │                                                        ↑
   汇聚资料                                                  被这些行为更新
      ↓                                                        │
 知识库 Source ──检索引用──→ 学习计划 Plan ──分解为──→ 学习任务 Task
                                │                        │
                                │                   触发两种学习行为
                                ↓                        ↓
                            动态重排 ←──── 督促 Nudge ← 学习会话 Session（讲解/测验）
                                                        │
                                                        ↓
                                                 复习卡片 Card ──排程──→ 复习队列（FSRS）
```

| 概念 | 定义 | 对标 |
|---|---|---|
| **学习项目 Study** | 一次有目标的学习活动的容器："学完 RustBook""读懂 React 源码"。资料、计划、任务、会话、卡片都归属于它 | DeepTutor 的 Workspace（一个科目一个容器） |
| **知识库 Source** | 导入资料的解析结果（PDF/MD/网页/GitHub repo），可被检索、被引用、被反复使用 | NotebookLM 的 Sources；OpenMAIC 的 KB |
| **知识点 Knowledge Point** | 从资料中拆解出的最小学习单元，有依赖关系（依赖图）、有类型（事实/概念/程序）、有掌握状态 | DeepTutor 的 memory/procedure/concept 分类 |
| **学习计划 Plan** | 由目标+资料+时间约束生成的日程：哪天学哪些知识点、做什么。**不是静态里程碑，而是随执行结果动态重排的活计划** | （竞品空白——StudyFetch 只有静态里程碑） |
| **学习任务 Task** | 计划落到"今天"的粒度：学某个知识点/复习某批卡片/做某组测验。用户每天面对的主体 | 通用 todo，但锚定知识点与源引用 |
| **学习会话 Session** | 任务触发的具体交互：讲解对话（苏格拉底模式可调）、内嵌测验、费曼式"你来讲我来挑错" | Khanmigo 的护栏对话；OpenMAIC 的课中测验 |
| **复习卡片 Card** | 学习/测验中产生的可回忆单元，自动或手动创建，进入 FSRS 排程的复习队列 | Anki/RemNote 卡片，但来源是 AI 交互自动沉淀 |
| **掌握档案 Mastery Profile** | 每个知识点的掌握状态（未学/学习中/已通过/已遗忘预警）+ 证据链（何时何题何对话） | DeepTutor 三层记忆的可审计理念 |
| **督促 Nudge** | 计划的执行器：今日任务提醒、逾期重排、每日摘要、周复盘 | Khoj automations 是唯一同类原型 |

**关键设计意图**：
- **Source 与 Study 分离**：同一份资料可服务多个学习项目（"一次导入，多处复用"，OpenMAIC 已验证）
- **知识点是枢纽**：计划排它、会话教它、测验考它、卡片记它、档案存它——所有模块通过知识点关联，这是"闭环"在数据结构上的实现
- **掌握档案是唯一事实源**：进度的唯一判据是档案中的掌握状态，而非任务勾选或阅读时长

## 7. 核心闭环（产品的心脏）

```
        ┌──────────────────────────────────────────────────────┐
        │                                                      │
        │   ⑤ 督促与重排                                        │
        │   今日任务 / 逾期自动重排 / 每日摘要 / 周复盘            │
        │        ↑                          │                   │
        │        │                          ↓                   │
   ④ 复习检验 │                   ① 导入与拆解                   │
   到期卡片出队│                   资料解析 → 知识点拆解 → 依赖图    │
   四档评分    │                   → 生成计划草案                  │
   错题→薄弱点 │                          │                     │
        │    │                          ↓                      │
        │    │                   ② 计划确认                     │
        │    │                   目标访谈(学多深/何时完/每天多久)    │
        │    │                   → 用户确认计划                   │
        │    │                          │                      │
        │    │                          ↓                      │
        │    └──────────── ③ 学习会话 ←── 今日任务               │
        │            讲解(带引用·苏格拉底可调) → 内嵌测验           │
        │            错题/卡壳 → 自动生成卡片入队 → 更新掌握档案      │
        │            薄弱点 → 影响明日任务 ←──────────────────────┘
        └── 卡片与档案反哺计划重排
```

闭环的五环与对应的产品判断：

1. **导入即拆解**：导入的终点不是"存起来"而是"拆成知识点树+依赖图"——这是对"导入后断崖"的直接回答。拆解结果先给用户看，再谈计划。
2. **计划必须经用户确认**：Agent 问三个问题（目标深度/完成期限/每日可用时间）后排计划，用户可编辑后生效。生成式内容"大纲先行、用户确认再继续"是 DeepTutor 验证过的信任设计。
3. **学习任务驱动对话**：进入学习即进入当日任务上下文，讲解默认带源引用+苏格拉底护栏；对话中暴露的错题与卡壳自动沉淀为卡片。
4. **复习是闭环的引擎**：卡片按 FSRS 到期出队；答错的卡片标记薄弱点，薄弱点反哺次日任务（插入针对性复习/变式题）。
5. **督促执行计划**：每天生成"今日任务"页；逾期任务不堆叠而是重排（保护用户动机——堆积的任务清单是弃用的第一诱因）；每日摘要收束一天。

## 8. 用户旅程（V1.0 全流程）

以天使用户画像走一遍：程序员小王要学 Rust。

### 第一次使用（约 15-20 分钟建立一切）

| 步骤 | 用户动作 | 系统行为 | 设计意图 |
|---|---|---|---|
| 1. 建学习项目 | 输入"我要学 Rust，用 RustBook + 官方文档" | 创建 Study | 目标先行 |
| 2. 导入资料 | 拖入 PDF / 贴 GitHub repo URL（rust-lang/rust-by-example）/ 贴网页链接 | 解析入库，显示进度与解析质量提示 | Source 沉淀，可复用 |
| 3. 看拆解结果 | 浏览自动生成的知识点树+依赖图，可调整（删/并/加） | 从资料拆解知识点，标注依赖与来源章节 | 回答"然后呢"——导入后第一屏是结构，不是聊天框 |
| 4. 目标访谈 | 回答三问：学到什么程度（能写 CLI 工具）/ 期限（6 周）/ 每天 45 分钟 | 生成分日计划：知识点×日期×预估时长 | 计划三要素：内容×时间×强度 |
| 5. 确认计划 | 浏览计划，拖改个别天，点"开始" | 计划生效，生成今日任务 | 用户确认优先于 Agent 全权 |
| 6. 第一次学习 | 进入今日任务 → 讲解对话（可问、可被考）→ 做对 3 题中的 2 题 | 错题自动生成 2 张卡片入队；知识点状态更新为"学习中" | 第一次会话就触达复习卡片——让用户第一天就理解闭环 |

### 日常一天（3-10 分钟或 45 分钟，两种模式）

- **碎片模式（3-10 分钟）**：打开"今日任务" → 清空到期的复习卡片（快速四档评分）→ 完成一个轻任务
- **专注模式（45 分钟）**：进入当日知识点讲解 → 对话提问（苏格拉底护栏默认开）→ 内嵌测验 → 卡壳处一键存卡片
- **收束**：每日摘要页——今天学了什么/复习了多少/明天是什么

### 异步发生（用户不看时）

- 逾期任务自动重排进未来日程（不堆叠）
- 薄弱点（连续答错的知识点）在次日任务中插入针对性复习
- 每周生成一次周复盘：完成率、掌握进展、遗忘预警、计划调整建议

### 生命周期事件

- **提前完成**：档案中知识点全部"已通过"且复习队列无高风险项 → 建议结项，输出学习总结（可导出）
- **长期中断后回来**：检测中断天数 → 触发"回炉计划"：重排剩余任务 + 队列中高风险遗忘卡片优先
- **换资料/加资料**：新增 Source 后重新拆解增量知识点，计划做差量调整，已掌握的不重学

## 9. 教学法依据（机制 → 理论映射）

只采用有实证支撑的教学法，每个机制可追溯到理论〔调研：学习科学映射〕：

| 产品机制 | 教学法 | 依据 |
|---|---|---|
| 内嵌测验 + "先作答再给反馈" | 主动回忆（Retrieval Practice） | 提取式练习比重读高效，与 SRS 合称学习策略中 ROI 最高的两件事 |
| FSRS 排程的到期复习队列 | 间隔重复 | 遗忘曲线；FSRS 为当前最优开源算法（Anki/RemNote 采用） |
| 知识点"通过测验才算掌握"、concept 类须用自己的话解释 | 掌握学习（Mastery Learning） | Bloom 两西格玛（1984）；哈佛 Kestin 2025：有护栏的 AI 导师增益约为课堂主动学习 2 倍 |
| 默认苏格拉底模式：先让用户作答→分层提示→要求复述推理 | 苏格拉底提问 | Khanmigo 商业化样板；避免"直接喂答案"导致的学习错觉 |
| "你来讲，我来挑错"任务类型 | 费曼技巧（输出式学习） | 几乎无竞品产品化〔调研〕——差异化机制 |
| 讲解分段呈现、单任务单知识点 | 认知负荷管理 | Kestin 2025 强调的护栏之一 |
| 计划生成前的先验访谈（学到什么程度/已知多少） | 先验知识诊断/前测效应 | DeepTutor Mastery Path 同款设计 |
| 逾期重排而非堆叠 | 动机保护（自我决定理论的应用） | 堆积的任务清单是弃用第一诱因；保持"可完成"感知 |

**克制的部分**：V1.0 不做 AI 同学/多人课堂（OpenMAIC 实证有价值但实时成本高）、不做音频播客（转换器军备竞赛，非主线）〔调研〕。

## 10. 边界与反模式（我们刻意不做的）

1. **不做"万能聊天机器人"**：对话入口永远在任务/卡片/知识点上下文内——自由闲聊会稀释"伴学"定位，且是已证伪的独立产品形态
2. **不追求生成物丰富度**：不堆播客/视频/游戏（StudyFetch 的军备竞赛路线被调研否决）；主线只有闭环
3. **不用 AI 直接改计划而不告知**：所有重排可见、可回滚——用户的计划用户做主
4. **不悄悄记录学习者**：档案可查看/编辑/导出/删除，AI 基于档案的行为要能被追溯到证据
5. **不用阅读时长冒充掌握**：时长只作参考字段，进度唯一判据是掌握证据

# 第三部分：产品规划

## 11. 产品路线图

> 排期为相对节奏，非承诺日期；每版一个主题，禁止范围蔓延。

### V1.0 —— 跑通"伴学"最小闭环（本期）
**主题：自用 + 小圈子验证——"这个闭环到底能不能让人学下去"**

- 定位：单部署、无账号体系，服务自己与少量天使用户
- 四环全做、每环做薄：导入（PDF/MD/网页/GitHub repo）→ 规划（目标访谈→资料拆解→计划确认）→ 学习（任务驱动的讲解对话+苏格拉底开关）→ 复习（FSRS 排程卡片+测验）→ 督促（站内今日任务+逾期重排+每日摘要）
- 掌握度档案以最简形态内建（知识点掌握状态 + 薄弱点视图），为后续版本打地基
- 详见 [v1.0/需求](v1.0/需求.md)

### V1.1 —— 督促触达外化 + 冷启动
**主题：让"伴"离开浏览器**

- IM 督促：企业微信/飞书/Telegram bot 推送今日任务、复习提醒、错题一题（借鉴 DeepTutor Partner"深度在 Web、触达在 IM"结构，先接 1-2 个渠道）
- 零资料冷启动：输入主题 → 自动检索并导入资料（对标 NotebookLM Discover sources）
- 邮件周报（低优先级，视 V1.0 数据决定）

### V1.2 —— 闭环加深 + 档案成型
**主题：从"陪你学"到"懂你"**

- 错题回灌闭环完整化：薄弱点自动触发针对性讲解与变式题
- 掌握度档案强化：跨学习项目的统一档案、知识点掌握趋势、遗忘预警
- 学习报告：周/月复盘（学了什么、掌握了什么、哪里弱、建议怎么调）
- 导入格式扩展（EPUB/音视频转写等）

### V2.0 —— 垂类学习路径 + 产品化
**主题：降低门槛，从工具变产品**

- **垂类路径市场**：「XX 技术栈学习路径」等模板化计划 + 内容包（内置知识点图谱+卡片库+节奏参数），用户零导入直接开学，或导入自有资料让模板做骨架、资料做血肉——解决"自建知识库门槛高"问题（这是本产品立项之初的第二诉求）
- 路径运营：路径模板的创建、评分、迭代（社区或官方供给，视 V1.x 数据定）
- 产品化基建：账号体系、多用户隔离、托管部署（从"自用"走向"开放"）
- 商业模式验证：订阅（托管服务）与 BYO-Key（免费/开源版）分层——借鉴 OpenMAIC 开放策略与 DeepTutor 纯开源路线的利弊〔调研〕

### 长期方向（仅立此存照，不做设计）
- 学习者生态：学习记录可携带、学习搭子（AI 同学）多人化——OpenMAIC 实证"社会临场感"有价值但实时性成本高，等成本结构合适再做
- 从"人学资料"到"人机共创"：学习产出（笔记/项目）反哺知识库
- 桌面/移动原生端（取决于 IM 触达数据：若 IM 承载了碎片场景，原生 App 优先级可降）

## 12. V1.0 成功标准

自用阶段无 GMV/DAU 之类指标，用**行为证据**验证闭环是否成立：

| 验证问题 | 衡量方式 | 目标 |
|---|---|---|
| 闭环真的能让人持续学吗 | 自己 + ≥3 名天使用户的周留存（每周至少 3 天产生学习行为） | 4 周后仍 ≥50% 的人在用 |
| 计划被执行了吗 | 生成的学习计划中当日任务完成率 | 中位数 ≥60%（计划不现实就没人执行） |
| 复习有人做吗 | 到期卡片的当日复习完成率 | ≥70%（复习队列不积压） |
| 掌握度可信吗 | 抽查测验通过的知识点，7 天后复习再现错误的比例 | ≤30%（档案确实反映掌握状态） |
| 差异化成立吗 | 用户主诉："它知道我该学什么/它会盯着我"是否出现在自发的正反馈里 | 定性确认 |

**反向止损线**：若 4 周验证后"计划完成率"与"复习完成率"两项均 <30%，说明问题不在功能多少而在闭环设计，优先回炉产品逻辑，不加新功能。
