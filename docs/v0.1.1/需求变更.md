# V0.1.1 需求变更：导入与 AI 规划（B6 组）

> 日期：2026-11-23｜状态：已实现（2026-11-24 全链路测试通过，见[实现进度.md](实现进度.md)）
> 编号规则：续 V0.1 的 B 系列新增 B6 组；对 V0.1 既有条目的修订在文末单独列出。
> 验收规则沿用 [V0.1 需求列表 §1](../v0.1/product/需求列表.md)：逐条通过 + 测试绿 + 真实界面走查。

## B6-01 上传勾选「使用 AI 规划」

上传对话框新增勾选项「使用 AI 规划」（默认**不勾**）。勾选仅表达用户意图，不做预检、不做消耗预估（那时文件未解析，章数字数未知，估不出有意义的数）。

**验收标准**

1. 不勾选：上传后走纯本地路径——解析、切片落库、embedding（若 embedding 预检通过），不发起任何 LLM chat 请求，星图页原树可学。
2. 勾选：上传后解析完成时进入 B6-02 预检流程。
3. 勾选项带说明文案：AI 规划将调用所配置的 LLM 服务并产生 token 消耗，解析完成后会给出预估并再次确认。

**反例（不通过）**

- 勾选状态未随上传请求提交，导致后端行为与用户勾选不一致。
- 勾选后立即弹预检或预估——时序错误，文件还没解析。

## B6-02 解析后统一预检，分路提示

解析完成（结构 + 切片落库）后做连通预检：**embedding 必检**（不管是否勾选 AI 规划）；**LLM 仅勾选时检**。预检是一次最小真实请求，本身消耗可忽略。

**验收标准**

1. embedding 预检通过且返回维度与库中向量表维度一致（当前 1024），才启动 embedding 任务；维度不一致按不通处理并说明原因（期望维度与实际维度）。
2. LLM 预检通过，才允许进入 B6-03 确认页。
3. 不通时分路提示，四种组合各自明确：
   - 仅 embedding 不通：检索补足不可用，AI 伴学不受影响；
   - 仅 LLM 不通：无法 AI 伴学与测验，检索不受影响；
   - 两者皆不通：纯原文阅读模式（原文、笔记、原树学习仍可用）；
   - 提示中给出「查看配置」入口，跳转设置页。
4. 预检不通过不产生任何重试风暴：用户不操作，不再自动重试。

**反例（不通过）**

- 用「AI 接口未配置」一句话盖住四种组合。
- embedding 预检失败但 embedding 任务仍被启动，最终静默 failed。
- 预检通过但向量维度与库中不一致仍放行（会写脏 vec 表）。

## B6-03 消耗预估与规划启动确认页

预检通过后弹出确认页，内容：消耗预估 + 用户意图输入 + 确认按钮。

**验收标准**

1. embedding 消耗只**提示**不设确认（必跑、成本可忽略），文案如「本书 embedding 约消耗 X token」；embedding 在预检通过后即后台启动，不等本页确认。
2. AI 规划 token 消耗以**区间**提示（如「预计 30–45 万 token」），估算口径见[技术设计 §4](技术设计.md)；用户点击「开始规划」后才启动。
3. 确认页可输入：
   - **计划学完天数**：数字输入，默认 10，范围 1–365；
   - **学习目标**：文本输入，默认「学透这本书：合上书也能讲清楚」，上限 200 字。
4. 两个字段随「开始规划」提交，存入 Study 并作为 AI 规划输入的一部分。
5. 用户关闭确认页不启动规划，星图页保留「继续完成 AI 规划」入口（B6-06），状态可恢复。

**反例（不通过）**

- 两个字段被拿去生成学习计划或排期——超出 V0.1.1 范围。
- 关闭确认页后规划被静默启动。
- embedding 因用户没点「开始规划」而被阻塞。

## B6-04 规划结果逐条确认后应用

AI 规划完成后，五类操作（排除/拆分/合并/分组/总述）以清单呈现，用户**逐条勾选**接受与否，确认后一次性应用；切片引用随之重挂。确认前原树照常可学。

**验收标准**

1. 每条操作展示：类型、涉及节点、AI 理由；默认全部勾选，用户可逐条取消。
2. 应用时逐条复查学习证据与用户编辑。确认前用户可能已在原树上学习，预标注规则与 V0.1 应用时的编辑保护规则一致，**默认取消勾选并标注原因**，不静默应用：
   - 拆分/合并：涉及子树含会话/测验/笔记/点亮证据，或涉及节点在建议生成后被编辑；
   - 排除/分组/章内组织：涉及节点在建议生成后被编辑才预标注。分组只重挂父节点、不让证据悬空，**不因学习证据预标注**（否则学过一章后所有分组建议都被取消，全是噪音）。

   应用时仍在写事务内逐条复查，复查不通过的跳过并记事件。
3. 应用成功后：树更新、引用重挂、thesis 与章节摘要随节点迁移，事件流完整记录（建议→确认→应用→跳过原因），点亮与学习数据不丢失。
4. 「全部拒绝」：树保持原树，建议作废，事件记录一次 planning_declined，规划状态转「已跳过」，之后可重新规划（B6-06）。**直接关闭**确认页（点 × 或「稍后」）：树保持原树，建议保留在「待确认树」状态，不记事件、不消耗 token，可从星图页重新打开继续确认。
5. 确认页在应用前展示基于所选操作的进度影响预估（如「本次将排除 3 个节点，点亮进度统计口径不变」）。

**反例（不通过）**

- 只提供「全部接受 / 全部拒绝」两个选项。
- 关闭确认页被当成拒绝，建议丢失，重新打开要再花一次 token 生成。
- 确认前原树被锁定不可学习。
- 应用了含学习证据的条目导致会话/点亮悬空。

## B6-05 双进度独立展示

星图页两路进度与状态分开：embedding 进度、AI 规划状态。两者节奏差异大（embedding 批次快、规划分钟级），合并展示会让规划显得卡死。

**验收标准**

1. embedding 一路：状态（预检/进行中/完成/降级/失败/预检失败）+ done/total 计数式进度。
2. AI 规划一路：阶段化状态（未启用/预检中/预检失败/待确认消耗/摘要中第 x/y 章/规划中/待确认树/已应用/失败/已跳过），**章摘要阶段可见到章一级**。
3. 任一路失败只影响本路展示与重试入口，不影响另一路。
4. 未勾选 AI 规划时不显示该路（而非显示灰色的「未开始」）。

**反例（不通过）**

- 规划进行中一分钟无任何进度变化（无章级进度的笼统 spinner）。
- 一路失败导致整页进度区报错。

## B6-06 星图页双路手动重试

预检失败或任务失败后，星图页提供与失败路对应的重试入口，点击后**先重新预检、通过再启动**。

**验收标准**

1. 「重试 embedding」：重新 embedding 预检 → 通过即补跑（沿用 V0.1 reembed 语义）。
2. 「继续/重试 AI 规划」：重新 LLM 预检（含未勾选后改主意的场景，允许从星图页补启动规划）→ 通过则回到 B6-03 确认页。入口：预检/规划失败时在双进度区；其余情况（未启用、待确认消耗、待确认树）在书菜单「···」→「AI 规划…」。
3. 规划已应用后再次重试：先按 V0.1 编辑保护规则检查学习证据，有证据则拒绝并提示改用目录编辑器。
4. 重试中的状态变化实时反映到双进度区。

**反例（不通过）**

- 重试不经过预检直接启动任务，失败回到静默失败。
- 有学习证据的书被重新规划导致树结构被替换。

## B6-07 学习页原文双视图（解析文本 / 原文）

学习页原文面板默认展示**解析文本**（现状行为），顶部提供与**原文**的切换，切换后按当前阅读位置同步定位。动因：解析是有损工作表示（丢图片、丢排版、极端情况解析出错），原文是无损参照，用户需要兜底入口。

**验收标准**

1. 切换 toggle 常驻原文面板顶部，默认解析文本，记住用户上次选择（同一学习项目内）。
2. 切换时按当前 chunk 的 location 同步定位：EPUB 打开对应文件并滚动到对应段落（V0.1 的 EPUB location 只有文件与标题锚点，段落由切片首段文本匹配细化），PDF 跳到 location 起始页，TXT/MD 定位到对应文本位置；反向切换同样定位，匹配不到时回到上次定位的切片。
3. 原文视图按格式保真渲染：EPUB 渲染 sanitize 后的 XHTML 且**图片可见**（图片资源从原始 zip 按需读取，见[技术设计 §8](技术设计.md)）；PDF 用 pdf.js 整页渲染（图片天然在页上）；TXT 纯文本；MD 渲染（外链图片可见，本地相对路径图片显示占位并注明单文件导入不支持）。
4. 解析文本视图行为与 V0.1 完全一致：切片、检索、回跳、引用挂载、char_count 与 token 预估口径**不受图片与本需求任何影响**。
5. 原文文件缺失或读取失败时：原文视图明确报错并提示原因，解析文本视图照常可用（兜底方向是原文兜解析，不反向）。
6. EPUB 原文渲染必须 sanitize（白名单标签与属性，剥离 script/style/事件属性），图片资源端点防路径穿越（见技术设计 §8.3）——EPUB 内容属外部输入。

**反例（不通过）**

- 切换后从原文顶部开始，无法定位到当前节点内容。
- 原文视图直接内联渲染 EPUB 原始 XHTML（未 sanitize，XSS）。
- 图片资源端点可用 `../` 读到 zip 外文件或任意系统路径。
- 为显示图片改动了切片内容、字数统计或消耗预估口径。
