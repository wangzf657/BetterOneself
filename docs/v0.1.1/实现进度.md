## 二、后端（完成）

### 状态机（已实现，与技术设计 §2 一致）

- `Source.embed_status`: pending → precheck_failed →（手动重试先重预检）→ pending → running → ready/degraded/failed
- `Study.outline_status`: 未勾选驻留 `structure_ready`（原树可学）；勾选 → precheck_ok ⇄ precheck_failed → planning → awaiting_confirm → ready / skipped（仅全部拒绝）；planning 崩溃 → failed（保树）
- `recover_on_startup` 只重做「parsed 且 embed pending」的预检；**不再自动排规划**；`precheck_failed` 不自动重试

## 四、已知问题（接手先看）

1. **`planning-flow` 证据预标注用例失败**：用户在学习页产生会话后打开确认页，桩 merge（目标 1.1+1.2）未被预标注「子树含学习证据」——页面快照显示两条均未 flagged。注意：后端单测 `test_evidence_flags_split_merge_only` 用 **Note** 证据是通的；E2E 里是 **Session** 证据。排查方向：`tree_core.evidence_kp_ids` 的 Session_ 路径在该场景是否命中（会话挂在哪个 kp、`get_or_create_session` 时机）、`proposal_view` 打开时树索引是否过期。用 `pnpm exec playwright show-trace test-results/.../trace.zip` 看现场。
2. **`planning-fail` 用例超时**：断言 `getByRole("button", { name: "重试" })` 90 秒未找到，但失败快照里按钮存在（「AI 规划：失败」+ 重试按钮可见）。怀疑与前面重命名对话框关闭时序或名称匹配有关；先单独跑 `pnpm e2e planning-fail.spec.ts` 复现。
3. **既有缺口（V0.1 起，本轮只登记不改）**：`validate_plan` 不拦「两个顶层叶章合并」（提示词写了「同章」但代码没查同章祖先）；用户可在确认页拒绝此类建议。
4. **QA 交付物会变红**：`qa/_scripts/reg_api.py` R2.2 与 `qa/_scripts/reg-ui.spec.ts` 依赖「导入即自动规划」，留给 QA 轮改。
5. 文档四份（概述/需求变更/技术设计/决策记录）状态仍标「待评审」，收尾时应改「已实现」。
