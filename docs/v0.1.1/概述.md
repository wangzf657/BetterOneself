# V0.1.1 概述：导入管线与 AI 规划信任模型重构

> 日期：2026-11-23｜状态：已实现（2026-11-24 全链路测试通过，见[实现进度.md](实现进度.md)）
> 基线：V0.1（已实现，97 用例绿）｜前置阅读：[V0.1 需求分析](../v0.1/product/需求分析.md)、[V0.1 技术方案 §4/§9](../v0.1/technical/技术方案.md)

## 定位

V0.1 之上的第一个小版本。**不新增学习功能**，只重构一件事：从「导入一本书」到「树定稿可学」的管线时序与信任模型。

## 动机

V0.1 的管线是「切片挂引用 → AI 拟大纲自动应用 + embedding 并行」。真机使用暴露三个问题：

1. **成本不知情**：BYO-Key 场景下，AI 拟大纲的 token 消耗（分钟级、逐章摘要是大头）在用户无感知时发生；QA 首轮就发现过「用量静默炸」。
2. **信任模型别扭**：AI 改树先斩后奏——自动应用后再靠「事件留痕 + 事后恢复原树」兜底。树是本产品的信任锚，用户应该在树被改动前看到并确认。
3. **进度不透明**：拟大纲分钟级（每批 ~65s），前端只有一个笼统状态，用户分不清慢和卡。

## 术语改名

**「AI 拟大纲」统一改称「AI 规划」。**

- 对外（UI 文案、API 命名语义、文档）：一律「AI 规划」。
- 代码内部标识符（`outline_planner` skill、`outline_status`、`OutlineEvent`）**不改名**——避免无意义的重命名波及 V0.1 的 97 个用例，见[决策记录 #38](决策记录.md)。

## 范围内 / 范围外

范围内：

- 上传时「使用 AI 规划」勾选（opt-in）
- 解析后统一预检（embedding 必检、LLM 勾选才检）
- 消耗预估提示；AI 规划启动前 token 确认
- AI 规划确认页新增：计划学完天数（默认 10）、学习目标（默认「学透这本书：合上书也能讲清楚」）
- 规划结果（五类操作）逐条确认后应用，切片引用随之重挂
- 前端 embedding / AI 规划双进度独立展示；星图页双路手动重试
- 学习页原文双视图（解析文本 / 原文切换、双向定位；图片走原文视图，见决策 #41）

范围外（明确不做，防蠕变）：

- **不做学习计划排期**：计划天数与学习目标只作为 AI 规划的上下文输入与学习档案记录，不生成每日计划、不做督促提醒——那是[后续候选·计划与督促](../v0.1/后续候选/)的范围。
- **解析文本视图不内嵌图片**：图片只在原文视图呈现（EPUB/PDF/MD 口径见技术设计 §8.2）；「此处有图」占位待真机验证后再议（后续候选·学习增强）。
- 不改检索、会话、测验、点亮的既有行为。
- 不动 V0.1 数据模型中既有字段的语义，只增不改。

## 依赖增量

均为成熟库，不自写：前端 `pdfjs-dist`（PDF 原文渲染）、`react-markdown` + `remark-gfm`（Markdown 原文渲染）；后端 `nh3`（EPUB XHTML 白名单消毒）。

## 实施顺序建议

1. 后端：状态机与预检、预估接口（B6-02、B6-03 的 API 部分）
2. 后端：规划建议暂存 + 确认应用 + 引用重挂（B6-04）
3. 前端：上传勾选、确认页、双进度、树确认、重试入口（B6-01…B6-06 的 UI 部分）
4. 原文双视图（B6-07）与管线重构**无依赖**，可独立排期：资产端点与 sanitize（后端）→ toggle 与双向定位（前端）
5. 回归：V0.1 全量用例适配新时序后保持绿

每步的验证标准见[需求变更](需求变更.md)各条目。
